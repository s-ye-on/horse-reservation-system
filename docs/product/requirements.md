# 제품 요구사항

## 목표

회원이 자신의 탑승 이력과 승인 상태에 맞는 수업을 달력에서 예약하고, 관리자가 정원·입금·쿠폰·출석을 일관되게 처리할 수 있는 마장 예약 서비스를 만든다.

## 사용자

- 회원: 예약 신청, 변경·취소, 예약 및 쿠폰 내역 확인
- 관리자: 회원 권한, 쿠폰, 시간대, 정원, 예약 승인, 출석과 예외 처리

## 제공 채널

- 회원·관리자 웹: React와 TypeScript 기반 반응형 웹
- 회원 모바일 앱: React Native와 Expo 기반 Android·iOS 앱
- 관리 기능은 웹을 우선하며 모바일 앱은 회원 기능에 집중한다.

## 클래스

| 클래스 | 일반 기승 완료 횟수 | 비고 |
|---|---:|---|
| 왕초보 | 0회 | 일반 기승 |
| 원형초보 | 1~5회 | 일반 기승 |
| 원형 속보 | 6~20회 | 일반 기승 |
| 대마장초보 | 21~25회 | 일반 기승 |
| 대마장 속보 | 26~69회 | 일반 기승 |
| 구보초보 | 70~99회 | MVP 3.2 일반 기승 |
| 구보 | 100회 이상 | MVP 3.2 일반 기승 |
| 마장마술 | 횟수 무관 | 관리자 승인 필요 |
| 장애물 | 횟수 무관 | 관리자 승인 필요 |

회원은 `effectiveClass` 이하의 일반 클래스도 예약할 수 있다. 마장마술 또는 장애물 승인 회원은
일반 progression을 바꾸지 않는 별도 자격으로 대마장 속보까지 예약할 수 있다. 특수 승인만으로
구보초보·구보가 열리지는 않으며, 일반 progression으로 이미 얻은 구보초보·구보 자격을 낮추지도 않는다.

## 회원 기능

- 현재 등급과 예약 가능 클래스 확인
- 달력에서 날짜·시간·클래스별 예약 가능 여부 확인
- 시간표 동기화 중 예약 가능 조회·신청·변경의 일시 중단 안내 확인
- 쿠폰 또는 1회 결제로 예약 신청
- 수업 시작 3시간 전까지 당일 수업 신규 예약 신청
- 승인대기, 입금대기, 반려, 확정, 완료, 취소 상태 확인
- 예약 변경 및 취소
- 쿠폰 잔여 횟수, 만료일, 무료 변경권, 사용 내역 확인

## 관리자 기능

- 회원 정보와 특수 클래스 승인 관리
- 10회권 쿠폰 등록 및 보정
- 요일별 정규 시간표와 정기 휴일 관리
- 시간표 동기화 상태·진행률·실패 원인 조회와 동일 version 수동 재시도
- 날짜별 `OPEN`, `CLOSING`, `CLOSED` 운영 상태와 휴무 정리
- 날짜·시간·클래스별 정원과 개별 TimeSlot 휴강 관리
- 예약 승인, 반려, 변경, 취소
- 수업 시작 전 관리자 수동 예약 추가
- 입금대기 확인과 만료 예약 복구
- 수업 완료 및 노쇼 처리
- 쿠폰 차감·반환 선택과 사유 기록
- 예약, 변경, 쿠폰 사용 감사 이력 조회
- 가족 그룹과 공유 쿠폰 사용 권한 관리
- 일반 클래스 progression baseline·promotion hold와 기승 횟수 보정

## 정원

- 한 타임 전체 예약은 최대 8명이다.
- 원형 클래스 합계는 최대 4명이다.
- 클래스별 예약 수는 관리자가 설정한 정원을 넘을 수 없다.
- 승인대기, 입금대기, 확정 예약은 정원을 점유한다.

강사, 말, 실내·야외·원형마장 자동 배정은 초기 범위에 포함하지 않는다.

## 범위 제외

- 대기 예약
- 초보 우선권
- 온라인 결제 연동
- 강사·말·마장 자동 배정
- 문자 또는 카카오톡 자동 알림
- 매출 및 고급 통계

## MVP-3 이후 확정 요구사항

다음 변경은 MVP-3.2에서 구현한다.

- 일반 클래스에 구보초보(일반 기승 완료 70회 이상)와 구보(100회 이상)를 추가한다.
- 실제 일반 기승 횟수와 관리자 progression baseline을 함께 반영해 `progressionClass`를 계산한다.
- progression baseline은 기존 경력의 최소 시작점을 인정하며 이후 자동 승급을 막지 않는다.
- 특수 승인이 없는 회원에게만 `progressionClass` 이하의 promotion hold 상한을 지정할 수 있다.
- `effectiveClass`는 promotion hold가 없으면 `progressionClass`, 있으면 두 클래스 중 낮은 값이다.
- 특수 승인과 promotion hold는 동시에 활성화할 수 없고 어느 한쪽도 자동 해제하지 않는다.
- 기승 횟수 보정은 baseline 이후 Horse가 집계한 실제 완료 횟수 오류만 정정하고 조정 이력을 보존한다.
- 가족 그룹 구성원은 Coupon 소유권을 바꾸지 않고 서로의 유효 쿠폰을 사용할 수 있다.
- 가족 그룹에는 대표 회원을 두지 않으며 관리자가 생성·구성원 변경·해제를 수행한다.
- 전용 가족 이관 기능은 제공하지 않고 기존 membership 제거와 새 membership 추가를 독립적으로 수행한다.

저장 모델과 이관, 관리자 변경 이력과 예약 검증은 MVP-3.2 Task와 ADR에서 구현한다.
