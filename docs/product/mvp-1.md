# MVP 1: 예약 운영 최소 완성본

## 목표

반응형 웹에서 회원의 예약 신청부터 관리자 승인, 수업 완료, 쿠폰과 탑승 이력 반영까지 한 흐름으로 실제 운영할 수 있게 한다.

## 포함 범위

- JWT 검증 기반 회원·관리자 권한 구분
- 회원 등급 및 특수 클래스 승인 관리
- 관리자 10회권 쿠폰 등록
- 날짜·시간·클래스별 정원 설정
- 회원 예약 가능 클래스와 시간대 조회
- 쿠폰 예약의 관리자 승인대기 및 쿠폰 임시 점유
- 쿠폰 없는 예약의 2시간 입금대기
- 관리자 예약 확정과 반려
- 반려와 취소 상태의 분리 표시
- 입금대기 자동 만료와 정원 반환
- 만료 입금대기 예약의 조건부 복구
- 수업 완료와 노쇼 처리
- 쿠폰 차감, 첫 기승일, 만료일 계산
- 쿠폰 만료 상태 전이와 사용 가능 잔여분 자동 소멸
- 일반 및 특수 클래스 탑승 이력 기록
- 회원 예약 목록, 쿠폰, 사용 내역 조회
- 관리자 승인대기 경고

## 제외 범위

- 회원 셀프 변경·취소 정책 자동화
- 일괄 완료와 고급 운영 대시보드
- 외부 결제 및 알림 연동
- 강사·말·마장 자동 배정
- 모바일 네이티브 앱
- 로그인 화면, 토큰 발급·갱신·폐기와 클라이언트 저장

## 인증과 배포 경계

MVP-1은 서명된 JWT를 검증하고 `MEMBER`, `ADMIN` 권한으로 API 접근을 제한하는 Resource Server 경계까지만 포함한다. 실제 로그인과 토큰 수명주기 및 저장 흐름은 후속 MVP에서 구현한다.

개발용 JWT 기본 Secret과 localhost API URL fallback은 로컬 실행 편의를 위한 설정이다. 운영 Secret과 API URL의 환경변수 강제 및 미설정 시 배포 차단은 아직 구현되지 않았으며, 배포 전 별도 task에서 완료해야 한다. 이는 MVP-1 도메인 기능 완료와 분리해 관리한다.

## 완료 조건

- 동시에 예약을 신청해도 전체·원형·클래스 정원을 초과하지 않는다.
- 쿠폰 잔여 횟수를 초과한 임시 점유를 만들 수 없다.
- 모든 예약은 관리자 승인 전까지 확정 상태가 아니다.
- 입금대기는 2시간 후 자동 만료하고 정원을 반환한다.
- 수업 완료가 쿠폰 차감과 탑승 이력에 한 번만 반영된다.
- 회원과 관리자가 동일한 예약·쿠폰 상태를 확인할 수 있다.
- 반려는 `rejected`, 접수 후 취소는 `cancelled`로 구분된다.
