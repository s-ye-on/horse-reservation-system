# ADR-009: 기승 횟수와 예약 가능 클래스 승인 모델 변경 연기

## 상태

`SUPERSEDED BY ADR-019`

## 배경

향후 일반 클래스에 구보초보(70회 이상)와 구보(100회 이상)를 추가하고, 기승 횟수를
최소 조건으로만 사용하면서 최종 예약 가능 클래스는 관리자가 회원별로 승인하는
요구사항이 제안되었다. 현재 모델은 일반 기승 완료 횟수에서 등급과 예약 가능 클래스를
파생하므로 이 변경은 회원, 예약 검증, 관리자 권한, API와 데이터 이관에 걸친 도메인
변경이다.

## 결정

- MVP-3에서는 현재 클래스와 횟수 기반 예약 가능 정책을 유지한다.
- 구보초보와 구보 클래스는 MVP-3 구현에 추가하지 않는다.
- 기승 횟수와 예약 가능한 클래스의 분리는 MVP-3 완료 후 독립 Task와 ADR로 상세
  설계한다.
- 후속 설계에서는 회원별 승인 저장 모델, 기존 회원 초기 승인값, 관리자 변경 이력,
  예약 생성·변경 시 재검증 및 API 호환성을 함께 결정한다.

## 결과

- MVP-3 운영 효율화 범위에 대규모 도메인 마이그레이션이 섞이지 않는다.
- 현재 예약 정책과 테스트는 MVP-3 동안 유지된다.
- 후속 구현 전에는 데이터 이관과 관리자 승인 기본값을 추측해서 추가하지 않는다.

M32-00에서 후속 정책을 확정했다. 단일 관리자 승인·manual override 대신 progression
baseline으로 기존 경력을 인정하고 promotion hold로 안전 상한을 적용한다. 상세 결정은
[ADR-019](adr-019-class-progression-baseline-and-promotion-hold.md)를 따른다.
