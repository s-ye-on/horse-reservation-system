# ADR 007: 예약 변경 실행 모델

## 상태

`ACCEPTED`

## 배경

예약 변경은 대상 시간대의 정원을 먼저 확보하고 기존 시간대의 점유를 해제해야 한다. Reservation을 정원 점유의 SSOT로 사용하는 현재 모델에서 예약 ID와 쿠폰 점유를 유지하면서 두 시간대 사이 이동을 원자적으로 처리할 방법이 필요하다.

## 결정

예약 변경은 기존 Reservation의 날짜와 시작 시각을 제자리 변경하고 `ReservationChangeLog`에 전후 값을 추가한다. 새 Reservation을 만들거나 기존 예약을 `cancelled`로 전이하지 않는다.

변경 트랜잭션은 다음 규칙을 따른다.

1. 원본과 대상 `ScheduleDate`를 날짜 오름차순으로 잠그고 대상 날짜의 운영 상태를 재검증한다.
2. 회원·날짜 직렬화 행을 날짜 오름차순으로 잠근다.
3. 원본과 대상 `TimeSlotCapacity`를 ID 오름차순으로 `PESSIMISTIC_WRITE` 잠금한다.
4. Reservation을 잠그고 최초 조회한 원본 일정·쿠폰·상태가 유지되는지 재검증한다.
5. 대상 날짜의 겹치는 활성 Reservation과 대상 TimeSlot의 점유를 잠금 조회한다.
6. 최초 일정 projection에 연결된 쿠폰이 있으면 Coupon 행을 잠근다.
7. 쿠폰 만료일, 무료 변경권, 대상 정원과 변경 정책을 검증한다.
8. 같은 Reservation의 날짜·시작·종료 시각을 변경하고 감사 이력을 추가한다.

변경은 예약 상태, 결제 방식, 쿠폰 ID, 승인 신청 시각, 입금 마감 시각을 유지한다. `pending_payment`의 2시간과 승인대기 경고는 최초 예약 신청 시각을 기준으로 계속 계산한다.

같은 대상 일정으로 재시도하면 이미 완료된 결과를 반환하고 정원, 무료 변경권, 쿠폰 로그, 예약 변경 이력을 다시 처리하지 않는다.

이 확장 순서는 ADR-015와 ADR-016을 따른다. 기존 구현의 TimeSlot 이후 Coupon 선잠금은
Checkpoint 1 보정과 M31-06에서 실제 교차 Command 잠금 순서를 검증한 뒤 교체한다.

## 결과

- 예약 ID와 기존 쿠폰 임시 점유가 변경 전후에 유지된다.
- 대상 점유 성공과 원본 점유 해제가 Reservation 한 행의 변경으로 함께 커밋된다.
- A에서 B, B에서 A로 교차 변경하는 요청도 동일한 시간대 잠금 순서를 사용한다.
- 같은 쿠폰의 여러 예약이 동시에 변경되어도 쿠폰 행 잠금이 대상 점유 조회보다 먼저 실행되어 무료 변경권 사용을 직렬화한다.
- 변경 이력은 상태 SSOT가 아니라 추가 전용 감사 기록으로만 사용한다.

## 검증

- 대상 정원이 찬 경우 원본 예약은 변경되지 않는다.
- 교차·경쟁 변경이 정원을 초과하거나 무한 대기하지 않는다.
- 동일 대상 재시도에서 변경 이력과 무료 변경권 로그가 한 번만 생성된다.
- 변경 전후 상태·쿠폰·신청 시각·입금 마감이 동일하다.
