# ADR-012: 운영 job 관측성 경계

## 상태

채택

## 배경

MVP-3의 쿠폰 만료와 입금대기 만료는 동일 Spring Boot 애플리케이션의 scheduler와 관리자 수동 API에서 실행된다. 외부 APM이나 별도 배치 서버 없이도 운영자는 실패한 작업과 수동 실행 관리자를 서버 로그에서 식별할 수 있어야 한다.

## 결정

- 공통 운영 job logger가 실행 경계에서 성공과 실패를 기록한다.
- 로그 필드는 작업 이름, 실행 방식(`SCHEDULED`, `MANUAL`), 행위자 유형(`SYSTEM`, `ADMIN`), 행위자 식별자, 결과 요약 또는 예외 종류로 고정한다.
- 자동 실행의 행위자는 `SYSTEM`, 수동 실행의 행위자 식별자는 인증된 관리자 JWT `sub`를 사용한다.
- scheduler와 수동 API는 기존 Application Service를 그대로 호출하며 관측성 계층은 트랜잭션이나 비즈니스 상태를 소유하지 않는다.
- 실패는 stack trace와 함께 기록한 뒤 원래 예외를 다시 전파한다.
- 회원 이름·전화번호와 요청 본문 전체는 로그에 기록하지 않는다.
- 일괄 출석의 항목별 예상 밖 실패는 기존 격리 동작을 유지하면서 예약 ID, 행위, 관리자 JWT `sub`를 기록한다.

## 결과

- 외부 인프라 없이 애플리케이션 로그만으로 어떤 운영 작업과 관리자 요청이 실패했는지 식별할 수 있다.
- 자동·수동 실행이 동일 Service를 공유한다는 기존 아키텍처와 실패 의미를 유지한다.
- 외부 APM, 알림, 영속 실행 이력과 자동 재시도는 실제 운영 요구가 생길 때 별도 결정한다.
