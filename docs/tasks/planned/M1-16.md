# M1-16: 입금대기 만료 복구 API

## 상태

`READY`

## 재개 조건

- 완료 조건은 만료 복구의 관리자 감사 이력을 요구한다.
- 도메인 모델에는 `ReservationChangeLog`가 정의되어 있지만 현재 Flyway migration, Entity, Repository가 구현되어 있지 않다.
- 기존 `reservations.admin_confirmed_at`만으로는 최초 확정과 만료 복구를 구분하거나 관리자 식별자와 복구 사유를 기록할 수 없다.
- M1-15A에서 추가 전용 변경 로그 영속성을 먼저 구현한다.
- 복구 요청은 최대 500자의 필수 관리자 메모를 받고 JWT `sub`를 `actorAuthSubject`로 기록한다.

## 목표

관리자가 만료된 1회 결제 예약의 현재 정원을 재확보한 경우에만 예약을 `confirmed`로 복구한다.

## 제외 범위

- 입금대기 자동 만료와 최초 입금 확인
- 쿠폰 예약 복구와 외부 결제 연동
- 관리자가 정원을 초과하는 강제 복구 기능
- 기존 아키텍처·컨벤션 변경과 관련 없는 리팩터링

## 완료 조건

- [ ] ADMIN만 `payment_expired`인 1회 결제 예약을 복구할 수 있다.
- [ ] 현재 전체·원형·클래스 정원을 원자적으로 재확보한 경우에만 `confirmed`로 전이하고 감사 이력을 남긴다.
- [ ] 정원 경쟁에서 한 요청만 성공하고 실패·중복 요청은 상태나 정원 점유를 부분 변경하지 않는다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- 복구 시 정원 초과를 허용하거나 관리자 강제 덮어쓰기가 필요하다.
- 정원 재확보와 상태 전이를 같은 command 트랜잭션에서 처리할 수 없다.
- 동일 정원을 향한 복구·신규 예약 경쟁을 MySQL 통합 테스트로 재현할 수 없다.
- `payment_expired` 외 상태나 쿠폰 예약도 복구해야 한다는 요구가 추가된다.
- 허용 범위 밖의 스키마·프론트엔드 변경이 필요하다.
