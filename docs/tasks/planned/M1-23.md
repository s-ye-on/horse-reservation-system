## 완료 조건

- [ ] `pending_admin_approval`, `pending_payment`, `payment_expired` 예약과 `normal`, `warning`, `critical` 경고가 서버 조회 결과대로 구분·정렬된다.
- [ ] 쿠폰 예약 확정·반려, 1회 결제 입금 확인, 만료 예약 복구만 현재 상태에 맞는 확인 절차로 실행된다.
- [ ] 처리 중 중복 제출을 막고 상태 충돌·복구 정원 부족·권한 거부 시 목록을 최신화한 뒤 재시도 가능한 오류를 표시한다.
- [ ] 320px 이상 반응형 상태별 작업·경고 컴포넌트 테스트와 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- M1-16A 조회 응답이 예약 상태, 결제 방식, 신청·수업 시각과 `normal`, `warning`, `critical` 경고를 제공하지 않는다.
- M1-16B 조회 응답이 `pending_payment`, `payment_expired`, `payment_due_at`, 현재 마감 여부를 제공하지 않는다.
- M1-13~M1-16 API의 허용 이전 상태나 상태 충돌·정원 부족 오류를 UI에서 구분할 수 없다.
- 요구사항 충족에 클라이언트 경고 시각 계산, 만료 job 호출, 생성형 API 클라이언트 직접 수정이 필요하다.
