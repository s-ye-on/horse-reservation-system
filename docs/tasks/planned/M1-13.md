# M1-13: 관리자 예약 확정 API

## 상태

`READY`

## 목표

## 제외 범위

- 예약 반려·취소와 만료 복구
- 수업 완료·노쇼와 쿠폰 실제 차감
- 입금 확인 외부 연동과 관리자 화면
- 기존 아키텍처·컨벤션 변경과 관련 없는 리팩터링

## 완료 조건

- [ ] ADMIN만 `pending_admin_approval` 또는 만료 전 `pending_payment` 예약을 `confirmed`로 전이한다.
- [ ] 쿠폰 예약은 임시 점유를 확정 점유로 바꾸고 1회 결제 예약은 쿠폰 부수 효과 없이 확정한다.
- [ ] 중복 확정 요청은 상태·쿠폰·감사 이력을 두 번 반영하지 않으며 허용되지 않은 상태는 거부한다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- 입금 확인의 의미가 외부 결제 연동 없이는 결정되지 않아 `pending_payment` 확정을 정의할 수 없다.
- 쿠폰 점유 전환과 예약 상태 전이가 서로 다른 트랜잭션에서만 가능하다.
- 만료 시각과 확정 요청의 경쟁을 상태 조건이나 잠금으로 재현·검증할 수 없다.
- ADMIN 행위자 또는 확정 시각을 감사 가능하게 기록할 수 없다.
- 허용 범위 밖의 스키마·보안 설정 변경이 필요하다.
