## 완료 조건

- [ ] 예약 테이블이 도메인 모델의 회원, 클래스, 수업 날짜·시각, 결제 출처, 쿠폰, 입금 마감, 승인·반려·취소 감사 정보, 버전과 감사 시각을 저장한다.
- [ ] 상태는 `pending_admin_approval`, `pending_payment`, `payment_expired`, `confirmed`, `completed`, `rejected`, `cancelled`, `no_show`만 허용하고 결제 출처·쿠폰 nullable 조합과 필수 감사 필드를 검증한다.
- [ ] 회원·쿠폰 참조와 쿠폰 사용 로그의 선택적 예약 참조를 연결하고 `rejected`와 `cancelled`가 별도 값으로 저장됨을 Flyway·영속성 통합 테스트로 검증한다.
- [ ] 활성 점유 상태 집계를 위한 날짜·시각·상태·클래스 복합 인덱스가 존재한다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- `coupon_id` 외 별도 `planned_coupon_id`를 다시 도입해야 한다는 기존 계약이 발견된다.
- `rejected`와 `cancelled`를 하나의 상태로 저장하거나 기존 상태값을 변경해야 한다.
- 날짜·시각 기반 시간대 연결을 `timeslot_id` 외래 키로 바꾸어야만 무결성을 보장할 수 있어 도메인 모델 변경이 필요하다.
- 상태별 감사 필드와 결제 출처 nullable 조합이 입력 문서끼리 충돌한다.
- 기존 예약 데이터의 삭제·재작성 또는 다른 migration 수정이 필요하다.
