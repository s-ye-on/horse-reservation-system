# M1-19A: 회원 예약 조회 API

## 상태

`READY`

## 목표

인증된 회원이 자신의 예약 목록과 예약·결제·쿠폰 상태를 조회한다.

`backend`

- M1-11, M1-12, M1-13, M1-14, M1-15, M1-16, M1-17, M1-18, M1-19 완료

- [MVP 1](../../product/mvp-1.md)의 회원 예약 목록 범위와 완료 조건
- [운영 정책](../../product/policies.md)의 예약 승인·쿠폰·입금대기 표시 정보

## 제외 범위

- 다른 회원 예약과 관리자 예약 조회
- `GET /api/me/reservations/{reservationId}` 상세 조회
- 예약 신청·변경·취소 command와 회원 웹 화면
- 기존 아키텍처·컨벤션 변경과 관련 없는 리팩터링

## 완료 조건

- [ ] MEMBER는 JWT `sub`에 연결된 자신의 예약만 `GET /api/me/reservations`로 조회하고 다른 회원 예약은 노출되지 않는다.
- [ ] 승인대기, 입금대기, 만료, 반려, 확정, 완료, 취소, 노쇼를 구분해 수업·결제원·쿠폰 예정 사용·`payment_due_at` 정보를 제공한다.
- [ ] ADMIN 권한만으로 다른 회원 데이터를 우회 조회할 수 없고, 존재하지 않는 회원 응답과 조회 무부수효과를 검증한다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- JWT `sub`와 `Member.auth_subject`의 본인 식별 계약이 충돌한다.
- 목록 정렬·페이지 계약을 구현 전에 제품 결정해야 한다.
- 회원에게 노출할 관리자 메모·반려 사유 범위를 현재 정책으로 결정할 수 없다.
- 조회를 위해 예약 상태나 쿠폰 점유를 갱신해야 한다.
- 허용 범위 밖의 상세 API·프론트엔드 변경이 필요하다.
