## 제외 범위

- 예약 가능 클래스·정원 재판정과 다른 시간대 탐색
- 예약 변경·취소와 외부 결제
- 관리자 승인·입금 확인·만료 복구
- 생성형 API 클라이언트 직접 수정, 클라이언트 쿠폰 선택, 백엔드 상태 전이 구현

## 완료 조건

- [ ] 달력에서 전달된 시간대·클래스·날짜·시간을 확인한 뒤 예약 신청을 한 번만 제출한다.
- [ ] 쿠폰 응답은 `pending_admin_approval`, 선택 쿠폰, 만료일, 현재 잔여 횟수와 점유 후 사용 가능 횟수를 표시한다.
- [ ] 1회 결제 응답은 `pending_payment`, `payment_due_at`, 2시간 입금 안내를 표시하고 충돌·만석·권한 오류를 구분한다.
- [ ] 320px 이상 두 결제 분기·중복 제출·오류 컴포넌트 테스트와 검증 명령이 모두 종료 코드 0으로 성공한다.

```bash

```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | - | READY 단계, 구현 후 `verify:m1-26` 등록을 기록한다. |
| `mise run verify:m1-26` | - | READY 단계, 쿠폰·입금대기 신청 분기 테스트 결과를 기록한다. |
| `mise run verify:changed` | - | READY 단계, 변경 영역 품질 게이트 결과를 기록한다. |

## 중단 조건

- M1-11 응답이 선택 쿠폰, 만료일, 현재 잔여 횟수, 점유 후 사용 가능 횟수를 제공하지 않는다.
- M1-12 응답이 `pending_payment`와 `payment_due_at`을 `Asia/Seoul` 기준으로 표시할 수 있게 제공하지 않는다.
- 두 신청 API의 성공·정원 충돌·중복 요청·권한 오류를 구분할 수 없다.
- 요구사항 충족에 클라이언트 쿠폰 선택이나 정원 판정, 생성형 API 클라이언트 직접 수정이 필요하다.
