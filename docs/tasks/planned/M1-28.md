## 완료 조건

- [ ] 쿠폰별 종류, 상태, 총·잔여·점유·사용 가능 횟수를 서버 응답대로 함께 표시한다.
- [ ] 첫 사용 전 만료일 없음, 첫 기승일·만료일, 무료 변경권 사용 여부, `active`·`expired`·`depleted` 상태를 구분한다.
- [ ] `held`, `confirmed`, `used`, `released`, `deducted`, `expired`, `free_change_used` 이력을 발생 시각과 관련 예약 기준으로 표시하고 로딩·빈 목록·오류를 처리한다.
- [ ] 320px 이상 쿠폰 요약·사용 이력·상태 컴포넌트 테스트와 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m1-28
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | - | READY 단계, 구현 후 `verify:m1-28` 등록을 기록한다. |
| `mise run verify:m1-28` | - | READY 단계, 쿠폰 요약·사용 이력 테스트 결과를 기록한다. |
| `mise run verify:changed` | - | READY 단계, 변경 영역 품질 게이트 결과를 기록한다. |

## 중단 조건

- M1-09A가 인증 회원의 쿠폰 목록과 쿠폰 사용 로그 조회 계약을 제공하지 않는다.
- 응답에서 `remaining_count`, `held_count`, 사용 가능 횟수 또는 만료일 미확정 상태를 구분할 수 없다.
- 사용 로그 action 값이 도메인 모델과 다르거나 관련 예약·발생 시각을 제공하지 않는다.
- 화면 구현에 클라이언트 잔여·만료 판정 또는 생성형 API 클라이언트 직접 수정이 필요하다.
