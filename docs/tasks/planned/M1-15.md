# M1-15: 입금대기 자동 만료 job

## 상태

`READY`

## 목표

결제 마감이 지난 입금대기 예약을 멱등하게 만료하고 점유 정원을 반환한다.

## 담당

`backend`

## 선행 작업

- M1-12 완료

## 입력 문서

- [MVP 1 Backlog](../mvp-1.md)의 `M1-15`
- [운영 정책](../../product/policies.md)의 `입금대기`
- [API 초안](../../architecture/api.md)의 시스템 작업과 `expire-payment`
- [예약 상태 전이](../../architecture/reservation-state-machine.md)의 `1회 결제 예약`, `상태 전이 원칙`
- [시스템 개요](../../architecture/system-overview.md)의 `일관성 경계`, `백그라운드 작업`
- 트랜잭션 입력 원칙: 만료 command use case 하나가 대상 예약의 상태 전이와 정원 반환 트랜잭션을 소유하며 job 진입점과 Repository는 독립 트랜잭션을 열지 않는다.

## 제외 범위

- 만료 예약 복구와 관리자 입금 확인
- 쿠폰 예약 또는 승인대기 자동 만료
- 외부 scheduler·queue 도입과 알림 전송
- 기존 아키텍처·컨벤션 변경과 관련 없는 리팩터링

## 완료 조건

- [ ] `payment_due_at`이 현재 시각 이하인 `pending_payment`만 `payment_expired`로 전이하고 정원을 반환한다.
- [ ] `Asia/Seoul` 2시간 경계, 확정과 만료의 경쟁, 반복 실행을 자동 테스트하며 정원을 한 번만 반환한다.
- [ ] 내부 인증된 시스템 작업 진입점으로 실행되고 쿠폰 예약과 다른 상태는 변경하지 않는다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- 시스템 작업 인증 방식이 없어 일반 사용자 공개 없이 호출할 수 없다.
- 만료 처리와 정원 반환을 한 command 트랜잭션으로 묶을 수 없다.
- 여러 인스턴스의 동시 실행에서 같은 예약의 정원을 중복 반환할 가능성을 차단할 수 없다.
- 승인대기 쿠폰 예약도 시간 만료해야 한다는 요구가 발견된다.
- 고정 Clock으로 2시간 경계와 재실행을 자동 검증할 수 없다.
