# M1-11: 쿠폰 보유 예약 신청 API

## 상태

`READY`

## 목표

회원의 쿠폰 보유 예약 신청을 승인대기 예약, 정원 점유, 쿠폰 임시 점유로 원자적으로 생성한다.

## 담당

`backend`

## 제외 범위

- 쿠폰 없는 입금대기 신청과 관리자 승인·반려
- 예약 변경·취소, 완료·노쇼 처리
- 프론트엔드와 생성 API 클라이언트 직접 수정
- 기존 아키텍처·컨벤션 변경과 관련 없는 리팩터링

## 완료 조건

- [ ] 유효한 클래스 일치 쿠폰 중 만료일이 가장 가까운 쿠폰을 선택해 `pending_admin_approval` 예약을 만든다.
- [ ] 정원과 쿠폰 사용 가능 횟수를 원자적으로 검증해 정원 1명과 쿠폰 1회를 임시 점유하고, 경쟁 요청은 불변식을 넘지 않는다.
- [ ] 응답에 상태, `coupon` 결제원, 선택 쿠폰과 임시 점유 결과를 포함하고 TimeSlot 삭제 가드가 생성된 예약 이력을 조회하며 회원 권한·입력 오류를 검증한다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- 쿠폰 선택·정원 점유·예약 생성 중 하나라도 command use case 밖의 독립 트랜잭션을 요구한다.
- M1-05 또는 M1-09가 동시성 제어 가능한 API를 제공하지 않는다.
- 쿠폰이 여러 장이고 `expires_at`이 모두 비어 있을 때의 선택 순서를 추가로 결정해야 한다.
- 실패 시 예약, 정원, 쿠폰 임시 점유를 모두 롤백하는 통합 테스트를 만들 수 없다.
- 허용 범위 밖의 스키마·인증·프론트엔드 변경이 필요하다.
