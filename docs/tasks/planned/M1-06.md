## 완료 조건

- [ ] 쿠폰 테이블이 회원, 종류, 총·잔여·점유 횟수, 첫 사용·만료 시각, 무료 변경권, 상태와 감사 시각을 도메인 모델대로 저장한다.
- [ ] DB 또는 자동화된 영속성 검증이 `0 <= held_count <= remaining_count <= total_count`, 허용된 쿠폰 종류·상태, 첫 사용 전 nullable 날짜를 보장한다.
- [ ] 사용 로그가 쿠폰·회원·선택적 예약 식별자, 허용된 action, `count_delta`, 발생 시각, 행위자, 메모를 보존하고 잘못된 참조·열거값을 통합 테스트로 거부한다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 중단 조건

- `CouponUsageLog.reservation_id`를 M1-10 이전에 외래 키로 강제하기 위해 예약 스키마를 함께 만들어야 한다.
- 만료처럼 예약과 무관한 action에도 `reservation_id`를 필수로 요구하는 기존 convention 또는 문서가 발견된다.
- `held_count` 불변식을 DB·영속성 통합 테스트로 검증할 수 없다.
- 기존 회원 PK 타입과 쿠폰의 `member_id` 계약이 일치하지 않는다.
- 데이터 손실 가능성이 있는 기존 migration 수정이나 architecture 변경이 필요하다.
