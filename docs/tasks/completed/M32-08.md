# M32-08 Completion Evidence

## 목표

M32-06과 M32-07에서 확정한 회원 클래스 progression 정책을 관리자 Web에서 조회하고,
baseline·promotion hold·특수 승인 인정분·실제 일반 기승 횟수를 서버 preview 확인 후 변경하며
append-only 감사 이력을 확인한다.

## Architecture 결정

Frontend에서 threshold나 progression 계산을 복제하지 않고 Backend Domain이 현재 상태와 예상 상태를
모두 계산하는 preview API를 제공한다.

- `POST /api/admin/members/{memberId}/class-progression/preview`는 기존 Aggregate Command와 같은
  검증·계산 경계를 재사용하며 상태와 감사를 변경하지 않는다.
- preview 응답의 `stateToken`은 실제 Command의 `If-Match`로 전달한다. Application Service는 회원
  행을 잠근 뒤 현재 snapshot과 비교하여, preview 이후 상태가 달라졌으면 409로 거부한다.
- 기존 M32-06/07 API 호출과의 하위 호환을 위해 `If-Match`는 선택 계약으로 유지하지만 M32-08
  Web은 preview 없이는 적용 버튼을 활성화하지 않고 항상 token을 보낸다.
- `GET /api/admin/members/{memberId}/class-progression/audit-logs`는 최신순 Page와 전후 snapshot,
  관리자, 필수 사유를 제공한다.
- M32-09 전까지 generated client는 수정하지 않고 중앙 Bearer 설정을 사용하는 얇은 수동 adapter를
  둔다. OpenAPI와 generated client 동기화는 M32-09가 소유한다.

## 구현

- 현재 actual count, progression/effective class, baseline Anchor, 특수 승인 인정분, promotion hold와
  관리 시작 시각을 회원 상세에 표시한다.
- baseline 설정·변경·해제, hold 설정·변경·해제, 특수 승인 인정분 교정, ride-count delta 보정은
  서버 preview와 필수 사유를 거쳐 기존 Command API를 호출한다.
- 최초 baseline 대상의 미초기화 회원도 현재 상태와 초기화 후 예상 상태를 비교할 수 있다.
- Special Approval과 promotion hold의 상호 배타 및 명시적 해제 순서를 화면에서 안내하고 서버
  Domain이 최종 강제한다.
- 감사 상세는 actual/delta, progression/effective class, baseline threshold와 Anchor actual,
  특수 승인 인정분과 hold의 전후 값을 구조적으로 표시한다.
- Command 및 특수 승인 성공 후 회원 detail/list cache와 해당 회원 감사 Page를 갱신한다.
- 320px에서는 회원 선택, 상태, preview, 적용, 감사 이력이 수평 overflow 없이 한 열로 배치된다.
