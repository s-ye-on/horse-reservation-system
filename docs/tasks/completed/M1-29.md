## 완료 조건

- [x] 쿠폰 보유 회원이 웹에서 예약을 신청하고 관리자가 웹에서 확정한 뒤 회원 화면에서 `confirmed`를 확인하는 E2E가 성공한다.
- [x] 쿠폰 없는 회원이 웹에서 예약을 신청하고 관리자가 입금을 확인한 뒤 회원 화면에서 `pending_payment`에서 `confirmed`로 바뀐 결과를 확인하는 E2E가 성공한다.
- [x] 쿠폰 흐름의 수업 완료 후 회원 재조회에서 `completed`와 쿠폰 차감·탑승 이력 반영이 한 번만 나타나며 두 흐름은 격리된 결정적 fixture를 사용한다.
- [x] Chromium에서 role·label 중심 selector로 실행한 E2E와 검증 명령이 모두 종료 코드 0으로 성공하고 실패 시 trace·screenshot을 남긴다.

## Completion Evidence

- Playwright가 MySQL, Spring Boot, Vite를 결정적으로 기동하고 준비 완료 URL을 확인한다.
- 테스트 전용 JWT와 회원·쿠폰·시간대 fixture를 테스트 내부에서 생성하고 종료 시 관련 데이터만 정리한다.
- 쿠폰 예약의 `pending_admin_approval -> confirmed -> completed`, 쿠폰 1회 차감, 사용 로그 1건, 일반 기승 횟수 1회 증가를 실제 화면과 API 응답으로 확인했다.
- 1회 결제 예약의 `pending_payment -> confirmed` 전이를 회원·관리자 화면에서 확인했다.
- `backend/conventions/review.md`를 점검했으며 백엔드 계층·도메인·예외 코드는 변경하지 않았다.

## 중단 조건

- 테스트 전용 회원·관리자 JWT와 격리된 fixture를 공개된 하네스 또는 API로 준비·정리할 수 없다.
- React 웹과 Spring API를 함께 시작하고 준비 완료를 판정하는 결정적 명령이 없다.
- M1-23·M1-26·M1-27 화면에서 role·label 기반으로 핵심 작업을 선택할 수 없거나 브라우저에서 실제 API 대신 mock만 사용한다.
- 쿠폰 완료·차감·탑승 이력을 허용 범위 안에서 관찰할 수 없어 완료 조건을 자동 검증할 수 없다.
