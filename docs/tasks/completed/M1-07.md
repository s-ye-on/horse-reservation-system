## 완료 조건

- [x] `POST /api/admin/members/{memberId}/coupons`가 `general`, `dressage`, `jumping` 중 하나인 신규 10회권을 대상 회원에게 등록한다.
- [x] 신규 쿠폰은 총·잔여 10회, 점유 0회, 미사용 변경권, `active`, 첫 사용일·만료일 없음으로 생성된다.
- [x] 등록 관리자와 등록 시각을 감사 정보로 보존하고, 성공한 요청마다 쿠폰 한 장을 생성한다.
- [x] `ADMIN` 권한, 존재하지 않는 회원, 잘못된 종류·횟수를 API·통합 테스트로 검증한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 완료 증거

- 성공 요청 하나가 독립된 쿠폰 한 장을 생성하며 서버 멱등성은 도입하지 않았다.
- 신규 쿠폰의 횟수, 점유, 변경권, 상태와 사용일 불변식을 Entity 팩토리에서 보장한다.
- JWT `sub`와 DB 생성 시각을 각각 `created_by`, `created_at` 감사 정보로 저장한다.
- `COUPON_*` 예외 접두사를 기존 단일 `ExceptionCode` 규칙에 편입했다.
- `mise run backend:convention`을 별도로 실행해 종료 코드 0을 확인했다.
- `review.md` 기준으로 Controller DTO 경계, Service 트랜잭션, Entity setter 부재, 예외와 테스트 경계를 점검했다.

## 중단 조건

- 외부 구매나 입금 상태를 확인하지 않고는 등록할 수 없다는 새로운 제품 정책이 필요하다.
- 10회권 외 총 횟수 또는 초기 만료일을 관리자가 입력해야 한다는 기존 API 계약이 발견된다.
- 구현에 회원 수정, 쿠폰 보정 또는 전역 인증 설정 변경이 필요하다.
- 다른 회원에게 쿠폰을 등록하거나 `MEMBER` 권한으로 성공하는 보안 테스트 실패가 발생한다.
