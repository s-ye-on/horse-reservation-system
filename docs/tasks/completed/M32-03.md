# M32-03 Completion Evidence

## 목표

Coupon 물리 소유권을 유지하면서 활성 가족 구성원의 유효 Coupon을 신규 예약 후보에 포함하고,
결정적인 정렬·선택 행 잠금·사용 당시 가족 관계 snapshot을 보장한다.

## 구현

- V37 migration
  - Reservation의 예약 회원과 Coupon 원소유자를 분리하도록 복합 FK를 Coupon 단일 FK로 변경
  - Coupon 사용 이력에 `coupon_owner_member_id`, `family_group_id` snapshot 추가
  - 기존 self-owned 사용 이력의 원소유자 값을 기존 Coupon에서 backfill
  - 자기 Coupon 사용은 가족 snapshot이 없고, 가족 Coupon 사용은 가족 snapshot이 필수인 CHECK 적용
  - Coupon ID와 원소유자 쌍은 Coupon row의 실제 소유권과 FK로 일치시킴
- 가족 후보
  - 예약 회원 자신의 Coupon과 같은 ACTIVE FamilyGroup의 active 구성원 Coupon을 한 후보 집합으로 조회
  - 그룹 가입 전에 발급한 Coupon도 현재 유효 조건을 만족하면 포함
  - 종료된 membership과 DISSOLVED 그룹은 신규 가족 후보에서 제외
  - 클래스 종류, active 상태, `remainingCount > heldCount`, 수업일 만료 조건 유지
- 결정 정렬과 잠금
  - 만료일 존재, 빠른 만료일, 빠른 생성일, 작은 Coupon ID 순서 유지
  - `expiry_null_rank` generated column과 선택 인덱스로 NULL 만료를 마지막에 배치
  - `LIMIT 1 FOR UPDATE`가 선택하지 않은 Coupon을 막지 않고 결정된 한 행만 잠그는 실제 MySQL 검증
- 사용 이력
  - HELD 시 예약 회원, Coupon 원소유자, FamilyGroup, Reservation과 실제 Coupon을 snapshot
  - CONFIRMED, USED, DEDUCTED, RELEASED, FREE_CHANGE_USED는 최초 HELD snapshot을 복사
  - membership 종료 후에도 기존 hold는 원 Coupon으로 반환하며 원소유자와 가족 snapshot을 유지
  - Coupon 만료는 원소유자의 self-owned snapshot으로 기록
- 기존 self-owned Coupon fixture는 새 필수 원소유자 필드만 명시하도록 보정했다.

## 검증 시나리오

- V36→V37 기존 이력 backfill과 fresh schema FK·CHECK
- 가족 전체 후보의 클래스·상태·잔여·수업일 필터
- 만료 NULL 마지막, 만료일·생성일·ID tie-breaker
- 가입 전 발급 Coupon 포함, membership 종료·그룹 해제 이후 신규 후보 제외
- 선택 Coupon 잠금 중 미선택 Coupon 갱신 가능, 선택 Coupon 갱신 대기
- 가족 Coupon 예약·hold·membership 종료·release와 snapshot 보존
- 기존 self-owned 선택·hold·예약·관리자 예약·무료 변경 회귀
- snapshot fixture 영향 클래스 18개, 128개 테스트 회귀 확인

## 범위

- Coupon row의 `member_id`와 물리 소유권은 변경하지 않았다.
- 가족 Coupon을 합산 잔액으로 병합하지 않았다.
- 현재 membership 변경은 신규 후보에만 영향을 주며 기존 Reservation·hold·이력을 소급 변경하지 않는다.
- 교차 경쟁의 lock order와 예약·제거·반환·만료 동시성 증명은 M32-04 범위다.
- API/OpenAPI와 생성 Client 확장은 M32-09 범위다.
