# M32-02 Completion Evidence

## 목표

ADMIN만 FamilyGroup을 생성하고 구성원을 추가·제거하거나 그룹을 해제할 수 있게 하며, 모든
변경을 관리자·시각·전후 상태·필수 사유와 함께 append-only 감사 이력으로 남긴다.

## 선행 작업

- M32-01 FamilyGroup, membership, 감사 원장 스키마 반영
- ADR-018의 대표자 없음, 단일 활성 membership, 빈 ACTIVE 그룹, 전용 이관 미지원 계약

## 구현

- `POST /api/admin/family-groups`
  - 중복 가능한 필수 이름으로 빈 ACTIVE 그룹 생성
  - `GROUP_CREATED` 감사 이력 기록
- `POST /api/admin/family-groups/{groupId}/members`
  - 그룹과 회원을 비관적으로 잠근 뒤 단일 활성 membership 확인
  - `MEMBER_ADDED` 전후 상태와 사유 기록
- `DELETE /api/admin/family-groups/{groupId}/members/{memberId}`
  - membership 행을 삭제하지 않고 종료 시각 기록
  - `MEMBER_REMOVED` 전후 상태와 사유 기록
- `POST /api/admin/family-groups/{groupId}/dissolution`
  - 모든 활성 membership을 종료하고 그룹을 비가역적으로 `DISSOLVED` 처리
  - 해제 전 활성 회원 snapshot을 `GROUP_DISSOLVED` 감사 이력에 기록
- 모든 Command는 그룹 잠금, 필요한 회원·membership 잠금, 상태 변경, 감사 append를 하나의
  트랜잭션에서 수행한다.
- 가족 대표자, MEMBER 직접 관리, 전용 가족 이관 API는 추가하지 않았다.
- OpenAPI 저장 계약과 생성 Client 갱신은 M32-09 범위로 남겼다.

## 검증 시나리오

- 비인증 401, MEMBER 403, ADMIN 성공
- 중복 이름과 membership 없는 빈 ACTIVE 그룹 생성
- 그룹 이름·변경 사유 필수 검증
- 회원별 활성 membership 하나만 허용
- 제거 후 다른 그룹 추가와 과거 membership 이력 보존
- 그룹 해제 시 모든 활성 membership 종료와 재변경 거부
- 존재하지 않는 그룹·회원 공통 오류 계약
- 감사 actor, reason, action, 전후 JSON 상태

## 후속

M32-03은 현재 활성 membership을 Coupon 후보 범위에만 사용하고 Coupon 물리 소유권을 유지한다.
