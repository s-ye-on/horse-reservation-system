# M31-11: Page 기반 조회 계약과 회원 예약 상세 API

## 상태

`COMPLETED`

## 목표

정책에 지정된 기존 목록 API를 Spring Data `Page` 기반 6필드 응답으로 통일하고,
누락된 회원 예약 상세 조회를 소유권 검증과 함께 추가한다.

## 담당

`backend`

## 선행 작업

- M31-05 완료
- M31-10 완료

- [MVP 3.1 Backlog](../mvp-3.1.md)의 `M31-11`
- [제품 정책](../../product/policies.md)의 `목록 페이지네이션`, `회원 예약 조회`,
  `관리자 예약 조회`, `관리자 감사 이력 조회`
- [API 계약](../../architecture/api.md)

## 완료 조건

- [x] 대상 목록이 Spring Data `Pageable`과 `Page`를 사용한다.
- [x] 모든 목록 응답이 6필드 Page 의미와 안정적인 PK 보조 정렬을 지킨다.
- [x] 기존 필터, 검색, 상태 의미와 권한을 유지한다.
- [x] 회원 예약 상세가 명시적 DTO를 반환하고 본인 예약만 조회할 수 있다.
- [x] 목록 조회가 항목 수에 비례하는 추가 조회를 발생시키지 않는다.
- [x] 잘못된 page, size, sort와 401, 403, 404가 공통 오류 응답을 사용한다.
- [x] OpenAPI와 생성 TypeScript Client가 최신이며 타입 검사를 통과한다.
- [x] 기존 웹 API 어댑터가 Page의 `content`를 배열로 반환해 화면 계약을 유지한다.
- [x] Backend와 QA 독립 검토에 HIGH 또는 MEDIUM finding이 남지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 관리자 예약, 관리자 예약 감사, 관리자 회원, 회원 예약, 회원 쿠폰, 회원 쿠폰 사용
  이력이 `content`, `page`, `size`, `totalElements`, `totalPages`, `hasNext`를 반환한다.
- 기본 `page=0`, `size=20`, 최대 `size=100`을 적용한다. 첫·중간·마지막·빈
  페이지와 전체 건수 및 다음 페이지 여부를 API 테스트로 검증했다.
- 관리자 예약은 수업 시각 오름차순을 기본으로 하고 `createdAt,desc`만 명시적
  정렬로 허용한다. 모든 정렬은 ID 보조 정렬을 포함한다.
- 관리자 감사는 발생 시각·이력 ID 역순, 관리자 회원은 생성 시각·회원 ID 역순,
  쿠폰과 사용 이력은 각 발생 시각·ID 역순을 유지한다.
- 회원 예약은 예정 예약 오름차순을 먼저 제공하고 지난 예약 내림차순을 이어서
  제공하는 DB Page 쿼리를 사용한다.
- `GET /api/me/reservations/{reservationId}`는 인증 주체의 회원 ID로 함께 조회하여
  다른 회원의 예약과 존재하지 않는 예약을 동일한 404 소유권 오류로 처리한다.
- 관리자 예약 목록은 회원과 쿠폰을 각각 한 번에 일괄 조회하고, 회원 예약 목록은
  페이지 내 쿠폰을 한 번에 조회한다. 서로 다른 회원·쿠폰 데이터로 쿼리 수가
  4개로 고정되는 것을 Hibernate Statistics로 검증했다.
- 여섯 웹 API 어댑터는 생성 Client의 Page 응답에서 `content ?? []`만 반환하여
  기존 화면의 배열 계약을 유지한다. Page 메타데이터를 사용하는 UI는 추가하지 않았다.
- DB migration과 예약·쿠폰·일정 상태 전이 정책은 변경하지 않았다.
- OpenAPI에 Page 모델, page·size 제약, 관리자 예약 sort와 회원 예약 상세가
  반영되었고 생성 TypeScript Client 타입 검사를 통과했다.

## 남은 위험

- 관리자 회원, 회원 쿠폰과 감사 목록은 연관 Entity를 순회하지 않는 단순 Page 또는
  projection 조회다. 예약 목록 두 경로에는 고정 쿼리 수 회귀 테스트가 있지만,
  이 단순 목록에는 별도의 Hibernate Statistics 테스트를 두지 않았다.
- 기존 웹 화면은 첫 Page의 `content`만 소비한다. 전체 페이지 탐색과 Page
  메타데이터 사용은 M31-13에서 구현해야 한다.
