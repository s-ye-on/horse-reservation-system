## Completion Evidence

- V33은 `auth_subject + operation + idempotency_key` binary unique scope와
  `processing/completed` 결과 CHECK, Reservation FK, 정리용 `(created_at, id)`
  인덱스를 추가한다. V32 upgrade와 fresh DB에서 기존 Reservation 보존, collation,
  최대 scope index 1,848 bytes, CHECK/FK 위반과 인덱스를 실제 MySQL로 검증했다.
- `IdempotentReservationApplicationService`는 scope를 `INSERT IGNORE`로 선점한 뒤
  같은 행을 `FOR UPDATE`로 읽는다. 새 요청만 기존 예약 생성 흐름을 실행하고 완료 행은
  저장된 HTTP status와 JSON body를 그대로 replay한다.
- fingerprint는 JSON 문자열이 아니라 version, `timeSlotId`, `classType`을 길이 구분
  binary 형식으로 정규화한 SHA-256이다. 같은 key의 다른 fingerprint는
  `RESERVATION_IDEMPOTENCY_KEY_CONFLICT` 409로 차단한다.
- 원장 선점, Reservation, TimeSlot 점유, Coupon 임시 점유, CouponUsageLog와 성공
  응답 저장은 하나의 transaction이다. 직렬화 장애와 MySQL 1213은 전체 rollback되며
  M31-07 바깥 재시도가 새 transaction으로 전체 흐름을 다시 실행한다.
- 실제 MySQL에서 같은 scope의 두 번째 claim이 첫 transaction 종료 전 대기하고, 첫
  commit 뒤 기존 행을 재사용하며 첫 rollback 뒤 새 선점자가 되는 순서를 검증했다.
- 쿠폰 예약과 무쿠폰 `pending_payment`의 동시 동일 key 요청은 Reservation과 점유를
  한 번만 생성한다. 완료 직전 실제 deadlock 뒤에도 Reservation, Coupon 점유와 감사,
  원장은 각각 한 번만 남는다.
- OpenAPI는 필수 `Idempotency-Key` Header와 구조화된 201 응답을 제공한다. 생성
  TypeScript Client는 필수 `idempotencyKey`를 Header에 전달한다.
- 웹은 같은 `timeSlotId/classType` 요청의 응답 실패 재시도에 같은 key를 사용하고,
  예약 본문이 바뀌면 새 key를 생성한다.
- 독립 Architecture와 DB 검토는 최초 MEDIUM finding을 각각 보정한 뒤 모두 `GO`이며
  남은 HIGH와 MEDIUM finding은 0건이다.
- `backend/conventions/review.md` 기준으로 Controller DTO 경계, Application Port,
  Entity 상태 변경, 예외 prefix와 한글 테스트 이름을 확인했다.

## 남은 위험

- 제품 정책의 원장 기본 보관 기간은 24시간이지만 만료 판정과 정리 Job은 M31-08 제외
  범위다. 후속 Task 전까지 완료 행은 계속 보존되고 같은 key는 계속 replay된다.
- Reservation 점유 조회와 Coupon 후보 정렬의 실제 InnoDB 잠금 범위는 통계와
  실행계획에 따라 넓어질 수 있다. M31-07의 1213 제한 재시도와 lock matrix 검증을
  유지하며 SQL 변경 시 EXPLAIN 근거를 다시 확인해야 한다.
- 관리자 수동 예약은 별도 operation과 멱등성 scope가 필요한 M31-09 범위다.

## 중단 조건

- 원장과 Reservation 생성 효과를 하나의 DB commit으로 묶을 수 없다.
- 최초 성공 HTTP status와 response body를 변형 없이 replay할 수 없다.
- M31-07 재시도가 같은 요청의 효과를 중복 반영한다.
- 기존 쿠폰 자동 선택 또는 무쿠폰 `pending_payment` 정책을 변경해야 한다.
- 원장 보존 기간이나 실패 결과 저장 범위에 새로운 제품 정책 결정이 필요하다.
- 독립 Architecture·DB 검토에 HIGH 또는 MEDIUM blocker가 남는다.
