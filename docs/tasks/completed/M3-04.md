## 완료 조건

- [x] 관리자는 수업 날짜·시각과 최대 8개의 예약별 `complete`·`no_show` 처리를 요청할 수 있다.
- [x] 각 예약은 요청한 시간대 소속을 잠금 안에서 검증하고 독립 트랜잭션으로 처리되어 한 항목 실패가 다른 항목을 롤백하지 않는다.
- [x] 구조적으로 유효한 요청은 항목별 성공·실패와 오류 코드를 반환하며 반복 요청은 쿠폰·기승 횟수·노쇼 이력을 중복 반영하지 않는다.
- [x] 미인증·회원 권한·잘못된 요청 본문은 기존 보안·오류 응답 계약으로 거부한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 완료 증거

- `POST /api/admin/reservations/complete-bulk`가 같은 시간대의 출석 완료와 노쇼를 최대 8건까지 처리한다.
- 비트랜잭션 일괄 조정 Service가 항목별 `REQUIRES_NEW` 처리 Service를 호출하고, 항목 처리기는 예약 잠금과 일정 검증 뒤 기존 단건 완료·노쇼 Service를 재사용한다.
- MySQL API 테스트에서 혼합 처리, 부분 실패 커밋, 일정 불일치 격리, 반복 요청의 쿠폰·기승 횟수·노쇼 이력 멱등성을 확인했다.
- 업무 예외는 항목별 도메인 오류로, 예기치 않은 실행 예외는 내부 정보를 숨긴 공통 오류로 반환한다.
- ADR-010과 제품 정책, API 계약, 생성 TypeScript 클라이언트를 구현과 함께 갱신했다.

## 중단 조건

- 일괄 처리에 완료·노쇼 외 새로운 상태 전이가 필요하다.
- 기존 단건 완료·노쇼의 쿠폰 정책을 바꿔야 한다.
- 항목별 독립 트랜잭션을 위해 기존 컨벤션을 완화해야 한다.
- 기존 API 소비자의 계약을 깨야 한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
