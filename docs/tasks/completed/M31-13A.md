## Completion Evidence

- `GET /api/me/reservations`에 선택적 `displayGroup`과 `status` query parameter를
  추가했다. 두 필터를 생략하면 기존 혼합 정렬 쿼리를 그대로 사용한다.
- `UPCOMING`은 수업 시작 시각이 현재보다 뒤인 예약, `PAST`는 정확한 시작 시각을
  포함하여 현재 이하인 예약으로 분류한다. 기준 시각은 주입된 `Clock`의
  `Asia/Seoul` 시각이다.
- `displayGroup`, `status`와 두 필터의 조합은 DB 조회와 count query에 함께
  적용된다. Page의 `content`, `totalElements`, `totalPages`, `hasNext`는 필터된
  전체 결과를 기준으로 계산한다.
- 필터별 정렬은 예정 예약 `lessonDate/startTime/id ASC`, 지난 예약
  `lessonDate/startTime/id DESC`이며, 필터 생략 시 기존 혼합 정렬과 ID 보조
  정렬을 유지한다.
- 잘못된 `displayGroup`과 `status`는 공통 `ErrorResponse` 형식의 400 응답으로
  반환한다.
- 탭별 건수는 별도 count API나 Page 필드를 추가하지 않고, M31-13에서 각
  `displayGroup` Page의 `totalElements`를 사용한다.
- Repository 통합 테스트에서 상태와 무관한 시간 분류, 첫·중간·마지막·빈
  페이지, count 정확성, ID 결정 정렬을 검증했다.
- 조회 쿼리 수는 필터 없음, 그룹과 상태 조합, 상태 단독 경로 모두 4개로 고정해
  N+1 회귀를 검증했다.
- OpenAPI와 생성 TypeScript Client에 필터 enum과 공통 400 응답 계약을 반영했다.
