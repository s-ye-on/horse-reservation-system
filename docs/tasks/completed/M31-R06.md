## 전환 검토 결론

- PM, Architecture, DB 모두 `GO`, HIGH·MEDIUM blocker 없음으로 판정했다.
- R06은 SYNCING 중 R03 horizon no-op을 보완해 동기화 자체에서 누락 날짜를 보충한다.
- 상태·진행률·재시도는 내부 Application 계약으로 구현하고 공개 HTTP 계약은 R11에
  남긴다.
- V26과 R06은 같은 배포 단위여야 하며 R05/V26을 R06 없이 단독 배포하지 않는다.
- R04의 요일·시각 동시 변경 영향 미리보기 정확도는 LOW 후속 항목이며 R06 동기화
  안전성을 막지 않으므로 이번 범위에서 수정하지 않는다.

## Completion Evidence

### 구현

- pending version 동기화는 누락 ScheduleDate를 보충한 뒤 날짜별 `REQUIRES_NEW`
  트랜잭션으로 occurrence를 반영한다. 각 트랜잭션은 Config guard 공유 잠금,
  ScheduleDate 배타 잠금, TimeSlot ID 오름차순 배타 잠금 순서를 지킨다.
- `applied_config_version`을 날짜별 진행률 SSOT로 사용한다. 전체 horizon을 날짜
  고유 인덱스로 `FOR UPDATE` 재조회해 모든 날짜가 목표 version임을 확인한 경우에만
  guard를 ACTIVE로 전환한다.
- 시작 완료 이벤트와 5분 주기 복구가 동일 pending version을 멱등 재시도한다.
  ACTIVE 상태의 일일 동기화는 새 horizon 마지막 날짜와 occurrence를 보충한다.
- 준비 단계와 날짜 단계 실패 모두 guard를 SYNCING으로 유지하고 비식별 실패 코드,
  요약, 시각을 기록한다. stale worker는 version conflict로 중단한다.
- 정기 휴일과 Template 활성 상태는 TEMPLATE TimeSlot의 자동 마감 원인만 갱신한다.
  MANUAL TimeSlot, 관리자 마감, 기존 정원, 활성 예약은 수정하거나 삭제하지 않는다.

### Migration과 잠금

- V27은 `time_slot_capacities(lesson_date, id)` 인덱스를 추가한다. 동기화 잠금 쿼리는
  해당 인덱스를 명시해 같은 날짜의 TimeSlot을 ID 오름차순으로 잠근다.
- 26→27 별도 MySQL migration 테스트에서 기존 TimeSlot 두 행 보존, 인덱스 컬럼 순서,
  실행 계획을 검증했다.
- ScheduleDate 전체 재검증은 `uk_schedule_dates_date`를 명시하고 날짜순으로 잠근다.
  겹치는 범위 잠금이 직렬화되는 MySQL 테스트를 추가했다.

### 독립 검토

- PM: 구현 요구는 충족했으나 완료 문서와 검증 표가 비어 있어 문서상 BLOCKED로
  판정했다. 이 문서 이동, 완료 체크, 검증 증거와 리뷰 기록으로 지적을 해소했고 최종
  재검토에서 HIGH·MEDIUM blocker 없음으로 `GO` 판정했다.
- Architecture: 시작 복구, 준비 실패 기록, stale version 차단, 날짜별 트랜잭션,
  잠금 순서와 ACTIVE 완료 조건에 HIGH·MEDIUM blocker가 없다고 `GO` 판정했다.
- DB: 최초 리뷰에서 실제 인덱스 잠금 순서, ScheduleDate 범위 잠금, V27 업그레이드
  증거를 지적했다. V27 전용 인덱스와 FORCE INDEX, 범위 `FOR UPDATE`, 26→27 이관
  테스트와 범위 잠금 동시성 테스트를 추가해 해결했다. V27은 이 R06 커밋에 명시적으로
  포함하며 최종 staged diff 재검토에서 `GO` 판정했다.

### 자기 점검

- Controller, 공개 API, 웹과 Expo를 추가하거나 변경하지 않았다.
- Service는 동기화 orchestration과 트랜잭션 경계만 담당하고 Entity 상태는 의미 있는
  도메인 메서드로 변경한다.
- 새 업무 예외는 `ScheduleException`과 `SCHEDULE_*`, Template 참조 오류는 기존
  `TIMESLOT_*` prefix를 사용한다.
- public setter, `IllegalArgumentException`, 직접 `RuntimeException` 상속을 추가하지
  않았다.
- 실패, stale version, 부분 재시작, 동시 재시도, 시작 복구, ACTIVE 일일 보충,
  자동 마감 원인 보존, migration과 잠금 경계를 테스트했다.

## 남은 위험과 후속 소유

- 공개 상태·진행률·수동 재시도 API와 SYNCING 503 응답은 M31-R11이 소유한다.
- 예약 생성·변경·복구의 guard/ScheduleDate 잠금 적용은 M31-R07~R10이 소유한다.
- 날짜 CLOSING/CLOSED와 개별 TimeSlot 휴강의 예약 정리는 후속 Task가 소유한다.
- R04의 요일·시각 동시 변경 영향 미리보기 오차는 LOW 후속 항목으로 남는다.
- R05/V26은 R06과 같은 배포 단위로 적용해야 하며 V27도 R06 런타임 쿼리와 함께
  배포해야 한다.
