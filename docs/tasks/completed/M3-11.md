- MVP-1의 쿠폰·1회 결제 예약 2개 흐름과 MVP-2 변경·취소 정책 5개 흐름을 현재 관리자 운영 화면 계약으로 회귀 검증했다.
- MVP-3 전용 E2E 3건이 기간별 승인대기 집계, 시간대 일괄 완료의 예약·쿠폰·기승 반영, 감사 화면·CSV 일치를 검증한다.
- fixture는 현재 날짜로부터 20일 뒤의 전용 회원·시간대를 만들고 예약 이력, 쿠폰 이력, 예약, 쿠폰, 회원, 시간대 순으로 정리한다.
- 기존 MVP-1 E2E의 확정 후 카드 제거 가정을 현재 확정 예약 변경·취소 운영 계약에 맞게 갱신했다.
- 외부 APM, 부하 시험, 모바일 실기기 E2E는 제외 범위로 유지한다.

## 중단 조건

- 기존 MVP 정책 또는 API 계약을 바꾸지 않으면 회귀를 해결할 수 없다.
- 결정적 fixture를 운영 데이터나 보안 우회 없이 구성할 수 없다.
- 핵심 E2E가 실제 Spring API 대신 mock을 사용해야만 통과한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
