## 실행 환경 확인

- 최초 Gate는 로컬 시연 DB에 남아 있던 `source=TEMPLATE`이면서 Template metadata가 없는
  29개 행 때문에 M31-R02 preflight에서 중단됐다. preflight는 데이터를 변경하지 않았고,
  이는 M34 production 결함이 아닌 기존 로컬 fixture 상태로 판정했다.
- 시연 DB를 변경하지 않기 위해 기존 MySQL volume/container를 보존하고 별도 임시 volume의
  깨끗한 MySQL 8.4에 42개 migration을 적용해 공식 Gate를 재실행했다.
- 첫 격리 실행은 OpenAPI 생성 스크립트가 고정 컨테이너 이름 `horse-mysql`을 참조하여 중단됐다.
  임시 DB가 공식 컨테이너 이름을 사용하도록 격리 구성을 바로잡았다.
- 다음 실행에서 `AdminScheduleConfigurationApiTest`의 Mockito stubbing이 한 차례 비결정적으로
  실패했으나 해당 테스트 클래스 단독 재실행은 성공했다. production 변경 없이 동일한 깨끗한
  DB에서 공식 Gate를 다시 실행해 전체 PASS를 확인했다.
- 검증 후 임시 DB와 volume을 제거하고 기존 로컬 시연 DB를 원래 이름으로 복구했으며 health
  상태가 `healthy`임을 확인했다.
