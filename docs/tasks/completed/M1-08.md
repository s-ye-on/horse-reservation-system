## 완료 조건

- [x] 일반·마장마술·장애물 클래스는 각각 일치하는 쿠폰 종류만 후보로 선택한다.
- [x] `active`이고 `remaining_count - held_count > 0`이며 수업일이 만료일을 지나지 않은 쿠폰만 후보로 남긴다.
- [x] 만료일이 있는 쿠폰을 미사용 쿠폰보다 우선하고 `expires_at`, `created_at`, `id` 순으로 결정적으로 선택한다.
- [x] 만료·소진·종류 불일치·수업일 이후 쿠폰을 제외하며 조회 과정에서 쿠폰을 변경하지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

| `mise run verify:changed` | 0 | 백엔드 전체, 통합, OpenAPI 클라이언트, 문서 검증 통과 |

## 완료 증거

- SSOT에 동일 종류 복수 쿠폰과 사용 중 쿠폰 우선, FIFO 및 결정적 tie-breaker를 기록했다.
- MySQL에서 `(expires_at IS NULL)`, `expires_at`, `created_at`, `id` 순으로 NULL을 후순위 처리했다.
- 클래스 종류, 상태, 사용 가능 횟수, 수업일 만료 경계를 DB 조회에서 함께 제한했다.
- 선택 전후 쿠폰 스냅샷이 동일한 MySQL 테스트로 부수 효과가 없음을 확인했다.
- `mise run backend:convention`을 별도로 실행해 종료 코드 0을 확인했다.
- `review.md` 기준으로 읽기 전용 Service, Repository 조회 책임, setter·원시 예외·API 노출 부재를 점검했다.

## 중단 조건

- 쿠폰 유효기간 3개월 계산에서 말일·윤년 처리 convention이 입력 문서와 충돌한다.
- 선택과 동시에 쿠폰을 수정하거나 예약·정원 트랜잭션까지 구현해야 한다.
- 쿠폰 종류와 기존 `RidingClass` 매핑이 일치하지 않는다.
