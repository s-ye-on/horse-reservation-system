## 완료 조건

- [x] ADMIN만 `confirmed` 일반 기승 예약을 `completed`로 전이하고 정원 점유를 종료한다.
- [x] 쿠폰 예약은 점유 1회를 실제 차감하며 최초 완료이면 수업일을 `first_used_at`으로 하고 3개월 만료일을 계산하고, 1회 결제는 쿠폰을 변경하지 않는다.
- [x] 신규 쿠폰·1회 결제 예약은 `Asia/Seoul` 기준 신청일로부터 3개월 이내 수업만 허용하고, 기존 정상 쿠폰 점유 예약은 이후 계산된 만료일을 초과해도 완료·차감한다.
- [x] 회원의 일반 기승 완료 횟수와 감사 이력을 한 번만 반영하고 반복·경쟁 완료 요청은 멱등하다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- `GeneralRideCompletionService`가 예약과 회원을 비관적 잠금하고 예약 완료, 쿠폰 실제 사용, 일반 기승 횟수 증가를 한 트랜잭션에서 처리한다.
- `Coupon.useHeld(...)`가 최초 완료 수업일과 3개월 만료일을 설정하고 점유·잔여 횟수를 함께 감소시킨다.
- 기존 `held`와 `confirmed` 이력이 있는 예약은 이후 계산된 만료일을 넘더라도 fallback으로 완료하며, 신규 예약은 서울 날짜 기준 3개월 경계를 넘지 못한다.
- 반복·경쟁 완료 요청은 Reservation 잠금과 `completed` 상태 재검증으로 쿠폰 사용 로그와 회원 횟수를 한 번만 반영한다.
- OpenAPI 계약과 TypeScript 공유 API 클라이언트를 재생성했다.

## 중단 조건

- 완료 상태와 쿠폰 차감·회원 횟수 증가가 서로 다른 트랜잭션에서 커밋된다.
- 첫 기승일 기준 3개월 만료일 계산 규칙을 현재 날짜 타입으로 일관되게 표현할 수 없다.
- 이미 만료된 쿠폰 점유 예약의 완료 처리 정책을 추가 결정해야 한다.
- 반복·경쟁 요청에서 쿠폰 또는 일반 기승 횟수 중복 반영을 막을 수 없다.
- 일반 완료에 특수 클래스 이력을 함께 변경해야 한다는 요구가 추가된다.
