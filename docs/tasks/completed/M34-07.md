# M34-07 Completion Evidence

## 상태

`DONE`

## 관리자 Web 계약

- 정규 시간표의 기존 활성/비활성 조작을 사용자-facing `삭제`로 교체하고, generated client의
  `DELETE /api/admin/schedule-templates/{templateId}` 계약을 사용한다. 삭제 전에는 대상 시간표,
  남은 미래 점유 예약 수, 신규 예약 차단과 기존 예약 비자동 취소 의미를 확인한다.
- inactive Template은 일반 정규 시간표 목록과 주간 정규 시간표에서 숨긴다. 미래 점유 예약이
  남은 inactive Template만 `예약 정리 필요` 영역에 표시하고, 0건인 Template은 별도 운영 종료
  목록을 남기지 않는다.
- `예약 확인`은 기존 관리자 예약 화면의 `reservationId` query parameter로 이동한다. 선택한
  Reservation을 기존 generated query client로 조회하고 기존 시간 변경·취소 Command를 그대로
  사용하므로 별도 취소 subsystem을 만들지 않는다.
- 동일 요일·시각 생성은 기존 생성 UX를 유지하며 Backend의 inactive Template 재사용 사실을
  노출하지 않는다.
- `TIMESLOT_CAPACITY_BELOW_OCCUPANCY`의 generated discriminator/details를 파싱하여 문제 수업의
  날짜·시간, 전체·원형·RidingClass별 현재 점유와 요청 정원을 관리자에게 표시한다.

## 반응형·접근성

- 삭제는 명시적인 확인 dialog와 destructive style을 사용하며 Escape, focus trap, 실행 전 focus
  복원 계약을 유지한다.
- cleanup loading, 부분 조회 오류와 retry, 실제 0건을 서로 구분한다.
- 320px에서는 cleanup header/예약 행/버튼과 예약 정리 대상 header를 세로로 배치하고 수평
  overflow가 없음을 Playwright로 검증했다.
- 신규 색상 조합은 WCAG AA 대비를 충족하고, 링크·버튼·dialog·상태 메시지는 keyboard/semantic
  경계를 유지한다.
