# M32-04 Completion Evidence

## 목표

가족 Coupon 예약과 membership 제거, 기존 hold 반환, Coupon 만료가 실제 MySQL에서 겹쳐도
후보 권리 판정, Coupon 수치와 append-only 사용 이력이 한 가지 순서로 일치하게 한다.

## 선행 작업

- M32-02의 FamilyGroup 우선 잠금과 membership 종료 Command
- M32-03의 가족 Coupon 결정 선택, 선택 Coupon 행 잠금과 사용 당시 snapshot
- ADR-018의 현재 사용 권리와 과거 행위 snapshot 분리

## 구현

- 신규 가족 Coupon 선택은 기존 예약 잠금 문맥 뒤에 active FamilyGroup을 먼저 잠근다.
- FamilyGroup 잠금 뒤 requester의 active membership을 현재 읽기로 재검증한다.
- 검증된 Group ID만 후보 쿼리에 전달하고, 같은 그룹의 active Coupon 원소유자만 JOIN한다.
- 정렬된 후보 ID를 `LIMIT 1` derived 결과로 계산하고, 외부 PK locking read에서 현재 상태를
  재검증해 FamilyGroup 다음에 결정된 Coupon 한 행만 잠근다.
- M32-02의 추가·제거·해제도 FamilyGroup을 먼저 잠그므로 후보 판정과 관계 변경이 직렬화된다.
- 예약이 가족 없음 상태를 먼저 관찰한 뒤 가입과 겹치면 가입 전 권리로 완료하고, 새 membership은
  다음 예약부터 적용한다.
- 기존 hold의 반환과 Coupon 만료는 membership을 재판정하지 않고 원 Coupon 행에서 직렬화한다.
- 최초 테스트에서 제거 commit을 기다린 뒤에도 오래된 MVCC snapshot membership을 후보가
  재사용하는 문제가 확인됐다. 현재 읽기 재검증과 명시적 Group ID 후보 경계로 수정했다.
- DB schema, Flyway, 외부 API와 OpenAPI 계약은 변경하지 않았다.

## 잠금 순서

| 흐름 | 순서 |
|---|---|
| 신규 가족 Coupon 예약 | 기존 예약 문맥 → active FamilyGroup → requester membership 재검증 → 선택 Coupon → HELD append |
| 구성원 추가·제거·그룹 해제 | FamilyGroup → 필요한 Member·membership → 가족 감사 append |
| 기존 hold 반환 | 기존 예약 문맥 → 원 Coupon → RELEASED append |
| Coupon 만료 | 만료 대상 Coupon ID 순 → EXPIRED append |

가족 Command는 Reservation·Coupon 잠금을 뒤에서 요구하지 않고, 반환·만료는 FamilyGroup을
요구하지 않으므로 위 순서 사이에 역방향 순환 대기가 없다.

## 검증 시나리오

- 같은 가족 두 회원이 마지막 1회 Coupon을 동시에 예약해 한 건만 HELD
- 접근 불가능한 선행 Coupon과 선택 후순위 Coupon은 잠그지 않고 결정된 Coupon만 잠금
- 가족 Coupon 선택이 먼저면 membership 제거가 예약 commit까지 대기
- membership 제거가 먼저면 대기한 신규 예약이 가족 Coupon을 선택하지 않음
- 진행 중인 예약이 가족 없음 상태를 먼저 관찰하면 동시 가입을 소급 적용하지 않고 다음 예약부터 적용
- 그룹 해제가 먼저면 대기한 신규 예약이 가족 Coupon을 선택하지 않음
- 기존 hold 반환과 membership 제거가 겹쳐도 원 Coupon과 가족 snapshot 유지
- 기존 hold 반환과 만료가 겹쳐도 `remainingCount`·`heldCount`가 0 미만이 되지 않음
- RELEASED·EXPIRED 이력이 각각 한 번만 append
- 선택 Coupon 1행 잠금, 기존 self/family hold와 만료 동시성 회귀
