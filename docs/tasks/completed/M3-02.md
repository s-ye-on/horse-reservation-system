## 제외 범위

- 기존 검색 API 경로와 응답 필드 변경
- 관리자 대시보드와 검색 화면 변경
- 예약 집계 API 변경
- 과거 예약 전용 화면
- 쿠폰·회원 통합 검색 추가
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [x] 상태·날짜·클래스·회원 이름 또는 전화번호 필터가 함께 동작한다.
- [x] 기본 조회는 오늘 이후이며 날짜 경계를 지정하면 과거 예약을 조회할 수 있다.
- [x] 페이지 기본값과 최대 크기, 수업일·시각·예약 ID 고정 정렬을 유지한다.
- [x] 목록·상세는 관리자만 조회할 수 있고 조회 과정에서 데이터를 변경하지 않는다.
- [x] OpenAPI query parameter는 `status`, `lessonDateFrom`, `lessonDateTo`, `classType`, `keyword`, `page`, `size`로 평면 생성된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 완료 증거

- M1-16A의 목록·상세 API가 MVP-3 검색 요구사항 전체를 충족함을 회귀 테스트로 확인했다.
- query DTO의 필터·페이지·고정 정렬·권한·read-only 계약을 유지했다.
- `@ParameterObject` 기반 OpenAPI가 평면 query parameter를 생성함을 검증했다.
- 동일 기능을 다시 구현하거나 API 경로와 응답 계약을 변경하지 않았다.

## 중단 조건

- 제품 정책과 기존 M1-16A 계약이 충돌한다.
- 검색 요구를 충족하려면 관리자 외 개인정보 노출 범위를 넓혀야 한다.
- 기존 API 소비자의 query 또는 응답 계약을 깨야 한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
