## 완료 조건

- [x] 생성·마감·재개·정원 수정·삭제는 수업 시작 직전까지 허용되고 정각부터 거부된다.
- [x] 관리자 기본 조회는 미래 TimeSlot만, 과거 조회는 시작된 TimeSlot만 안정적인 순서로 반환한다.
- [x] 모든 시간 판정은 주입된 서버 `Clock`의 `Asia/Seoul` 시각을 사용한다.

## Completion Evidence

- TimeSlot 일반 관리 시각 정책은 수업 시작 직전 허용, 정확한 시작 시각부터 차단하는 순수 Domain Policy다.
- 생성은 저장 전에, 마감·재개·정원·삭제는 TimeSlot 행 비관적 잠금 이후 서버 `Clock`으로 정책을 검증한다.
- 기본 조회는 현재 시각보다 미래인 슬롯을 오름차순으로, 과거 조회는 시작된 슬롯을 내림차순으로 반환한다.
- 과거 조회 전용 `GET /api/admin/timeslots/history`를 OpenAPI와 생성 TypeScript Client에 반영했다.
- 기존 MySQL 경쟁 테스트에 고정 서울 `Clock`을 주입해 테스트 목적과 시간 정책을 분리했다.
- `review.md` 기준 Controller는 DTO 변환만 수행하고 정책은 Domain, 트랜잭션 조합은 Service에 유지했다.

## 중단 조건

- 일반 관리자 API에서 과거 TimeSlot을 수정해야 하는 정책이 발견된다.
- 과거 조회의 별도 권한 또는 보존 기간 결정이 필요하다.
- 기존 DB migration 변경이 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
