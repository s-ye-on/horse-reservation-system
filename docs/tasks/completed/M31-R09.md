## 완료 조건

- [x] 미래 `NORMAL/OPEN` 날짜만 CLOSING을 시작하고 직전 상태를 `resumeStatus`에 보존한다.
- [x] 활성 예약이 없으면 같은 날짜 잠금 안에서 즉시 CLOSED로 확정할 수 있다.
- [x] CLOSING 시작 이후 신규 예약과 대상 날짜로의 예약 변경·복구가 차단된다.
- [x] CLOSING 중 승인, 입금 확인과 회원 직접 취소가 차단된다.
- [x] CLOSING 중 반려, 자동 입금 만료, 자동 승인 만료와 전용 취소는 허용된다.
- [x] 영향 예약은 활성 상태만 Reservation ID 오름차순으로 반환한다.
- [x] 전용 취소는 ScheduleDate, member-day guard, Reservation, Coupon 순서를 지킨다.
- [x] 전용 취소는 쿠폰 예약에 `stable/RETURN`, 1회 결제에 `stable/NONE`을 강제한다.
- [x] 취소 실패는 Reservation, Coupon과 감사 이력을 rollback하고 날짜를 CLOSING으로 유지한다.
- [x] 활성 예약이 남으면 CLOSED 확정을 409로 거부하고 0건이면 확정한다.
- [x] CLOSING 취소는 `resumeStatus`로 복귀하며 이미 취소된 예약을 복원하지 않는다.
- [x] 날짜 상태 변경과 예약 정리 행위가 append-only 감사 이력으로 남는다.
- [x] 예약 생성과 CLOSING 시작의 MySQL 경쟁에서 잘못된 활성 예약이 남지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

### 구현

- `ScheduleDate`가 미래 `NORMAL/OPEN → CLOSING → CLOSED`와 CLOSING 취소를 소유하고,
  CLOSED 확정 직전에 활성 예약 0건을 같은 날짜 잠금 안에서 재검사한다.
- 신규 예약, 변경, 승인·입금 확인, 복구, 회원·일반 관리자 취소와 수동 TimeSlot 생성은
  CLOSING/CLOSED 날짜를 차단한다. 반려와 자동 입금·승인 만료는 날짜 및 member-day
  guard 순서를 지키며 안전한 종료를 계속 허용한다.
- 휴무 정리 전용 취소는 `ScheduleDate → member-day guard → Reservation → Coupon`
  순서로 잠그고 쿠폰 예약 `stable/RETURN`, 1회 결제 `stable/NONE`을 강제한다.
  반복 호출은 추가 반환·감사를 만들지 않으며 반환 실패는 전체 트랜잭션을 rollback한다.
- 영향 목록은 활성 예약 ID 오름차순과 현재 건수를 반환한다. 공개 진행률 API와 화면은
  R11과 R13이 이 Read Model을 기반으로 완성한다.

### 검증과 보정

- 날짜 CLOSING과 회원 예약 생성, 수동 TimeSlot 생성의 실제 MySQL 경쟁에서 같은
  ScheduleDate 잠금으로 실행 순서가 결정되고 CLOSED 이후 신규 유입이 남지 않음을 검증했다.
- 첫 R09 전용 검증에서 기존 회원 시간대 조회 fixture에 ScheduleDate가 없어 3건이
  실패했다. 운영 날짜 fixture와 CLOSING/CLOSED 숨김 회귀 테스트를 추가한 뒤 통과했다.
- PM 1차 검토가 수동 TimeSlot 생성의 날짜 상태 우회를 HIGH로 지적했다.
  `ScheduleDateInflowLockService`와 API·경쟁 테스트를 추가했고 재검토에서 GO를 받았다.

### 독립 검토

- PM: 수동 TimeSlot 생성 차단 보정 후 `GO`. 진행률 공개 계약은 R11/R13 후속 범위로 판정했다.
- Architecture: canonical lock order, CLOSING matrix, 전용 취소 원자성과 멱등성에 `GO`.
- DB: ScheduleDate와 member-day guard 직렬화, 0건 재검사, 자동 만료 경쟁에 `GO`.

### 자기 점검

- Controller, DTO, OpenAPI, 생성 Client와 웹·Expo 계약을 변경하지 않았다.
- 개별 TimeSlot 휴강·재개, 알림, 일괄 취소와 Idempotency를 조기 구현하지 않았다.
- V1~V29 migration과 관련 없는 dirty 파일을 수정하지 않았다.

## 남은 위험과 후속 소유

- R10은 개별 TimeSlot 휴강의 신규 유입 차단, 전용 취소, 0건 확정과 재개를 구현한다.
- R11/R13은 날짜 휴무 영향 대상의 공개 API, 초기·잔여 건수 기반 진행률과 관리자 UX를
  구현한다.
