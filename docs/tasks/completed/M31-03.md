# M31-03: 승인·반려와 입금 만료 시각 정합성

## 상태

`COMPLETED`

먼저 도래한 시각으로 일치시킨다.

## 완료 조건

- [x] 수업 시작 직전 승인·반려는 허용되고 정각부터 모두 거부된다.
- [x] 입금 마감은 `min(신청 시각 + 2시간, 수업 시작 시각)`으로 응답과 DB에 저장된다.
- [x] 입금 마감 또는 수업 시작 정각의 만료와 재실행이 기존 멱등성을 유지한다.
- [x] 모든 검증 명령이 종료 코드 0으로 성공한다.

## Completion Evidence

- 승인과 반려는 수업 시작 직전까지 허용되고 정확한 시작 시각부터 동일한 Domain Policy로 거부된다.
- 입금대기 마감은 신청 후 2시간과 수업 시작 중 먼저 도래하는 시각으로 한 번 계산해 응답과 DB에 저장한다.
- 당일 수업 직전 신청의 `paymentDueAt`이 수업 시작 시각을 넘지 않는 API 회귀 테스트를 추가했다.
- 입금 마감 및 수업 시작 정각의 만료, Scheduler 재실행과 승인 경쟁의 기존 멱등성 테스트를 함께 통과했다.
- `review.md` 기준 Controller/DTO/Repository 경계를 유지하고 상태 검증은 Entity, 마감 계산은 순수 Domain Policy에 배치했다.

## 중단 조건

- 수업 종료 시각 또는 입금 grace period가 필요하다.
- 승인과 반려에 서로 다른 수업 시작 경계가 필요하다.
- 기존 입금대기 데이터의 비가역 이관이 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
