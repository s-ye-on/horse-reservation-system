## 완료 조건

- [x] 쿠폰 만료와 입금대기 만료 scheduler는 성공과 실패에 작업 이름, `SCHEDULED`, `SYSTEM`을 기록한다.
- [x] 관리자 수동 입금대기 만료는 JWT `sub`를 `ADMIN` 행위자로 기록한다.
- [x] 실패 로그는 예외 종류와 stack trace를 남기고 예외를 삼키지 않는다.
- [x] 일괄 출석의 예상 밖 항목 실패 로그는 예약 ID, 행위, 관리자 JWT `sub`를 포함한다.
- [x] 로그에는 회원 이름·전화번호나 요청 본문 전체를 포함하지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 공통 `OperationalJobLogger`가 작업 이름, 실행 방식, 행위자와 결과 또는 예외를 일관된 로그 필드로 기록한다.
- 자동 만료 scheduler는 `SYSTEM`, 관리자 수동 만료 API는 JWT `sub` 기반 `ADMIN` 컨텍스트를 전달한다.
- 실패 로그에 예외 종류와 stack trace를 남긴 뒤 같은 예외를 다시 전파함을 검증했다.
- 일괄 출석 예상 밖 실패는 기존 항목 격리를 유지하면서 예약 ID, 행위와 관리자 `sub`를 기록한다.
- 외부 APM, 알림, 영속 실행 원장과 자동 재시도는 제외 범위로 유지한다.

## 중단 조건

- 외부 APM이나 로그 수집 인프라가 없으면 완료 조건을 충족할 수 없다.
- 관리자 식별을 위해 JWT `sub` 외 개인정보를 기록해야 한다.
- 관측성 추가가 기존 job의 트랜잭션·실패 전파 의미를 변경한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
