# M34-04 Completion Evidence

## 상태

`DONE`

## 구현 계약

- 아직 시작하지 않은 `source=TEMPLATE`, `capacityOverridden=false` 슬롯의 전체·원형·
  RidingClass별 정원을 현재 Template에 맞춰 동기화한다. 비활성 Template의 기존 슬롯도
  같은 정원 규칙을 따르되, 비활성 마감과 새 occurrence 생성 중단은 유지한다.
- Template 변경을 커밋하기 전에 설정 guard, 날짜, 슬롯, 점유 Reservation 순으로 잠그고
  모든 대상의 점유 하한을 기존 `TimeSlotCapacity` 불변식으로 검증한다. 하나라도 충돌하면
  Template 변경·감사·SYNCING 진입을 함께 롤백한다. 기존 오류 코드와 상세 정보에 충돌
  날짜·시각, 점유, 요청 정원을 담는다.
- 통과한 변경은 기존 config version의 `SYNCING` 상태에서 날짜별 짧은 트랜잭션으로
  반영하고, 모든 날짜가 적용되기 전에는 `ACTIVE`로 전환하지 않는다. 재시도 시작 때
  현재 horizon도 재검증한다.
- M34-03 이전에 생성된 비 override 미래 슬롯의 오래된 정원은 시작/일일 복구 경로에서
  mismatch를 발견할 때 동일한 versioned `SYNCING` 경로로 reconciliation한다.
- 개별 override·MANUAL·이미 시작된 슬롯의 정원과 독립적인 관리자/휴일 마감 원인,
  과거 운영 기록은 보존한다. 새 migration, API 계약, generated client 변경은 없다.

`verify:changed`는 실행하지 않았다. 작업 시작 전부터 존재한 관련 없는 frontend·
`scripts/` 변경과 이번 `mise.toml` 변경을 포함하면 harness가 `verify:all`로 확대되므로,
이번 변경 범위에는 위 Backend Gate와 docs 검사를 사용했다. M34-02의 신규 API와
OpenAPI/generated client 사이의 기존 차이는 M34-06 책임이며, M34-04는 API 계약을
변경하지 않았다. 이 known deferred 항목은 이번 Gate의 PASS로 표기하거나 다른 실패를
허용하는 일반 예외로 확대하지 않는다.

## 독립 검토

읽기 전용 reviewer가 비활성 Template의 기존 미래 슬롯을 사전 검증·동기화에서 빠뜨리는
HIGH 결함을 발견했다. 비활성 Template의 동일 ID 슬롯을 포함하도록 수정하고,
점유 충돌 전체 거부와 닫힘 보존 통합 테스트 두 건을 추가했다. 같은 reviewer의
재검토 결과는 `RESOLVED`이며, 남은 CRITICAL/HIGH/MEDIUM finding은 없다.
