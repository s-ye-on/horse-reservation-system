## 완료 조건

- [x] 하나의 application query surface가 JWT `sub`로 현재 회원을 식별하고 두 GET endpoint에 본인 데이터만 제공한다.
- [x] 쿠폰 목록은 종류, 총·잔여·점유·사용 가능 횟수, 첫 사용일, 만료일, 무료 변경권, 상태를 조회할 수 있게 한다.
- [x] 사용 내역은 쿠폰·선택적 예약 식별자, action, 횟수 변화, 발생 시각, 행위자를 조회할 수 있고 타 회원 데이터와 내부 전용 메모를 노출하지 않으며 모든 조회가 상태를 변경하지 않음을 API 테스트로 검증한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- `MemberCouponQueryService`가 JWT `sub`로 회원을 확정하고 두 조회 API에 본인 쿠폰과 사용 내역만 제공한다.
- 응답 DTO는 쿠폰 운영 정보와 사용 이력의 공개 필드만 포함하며 내부 메모는 포함하지 않는다.
- query service는 읽기 전용 트랜잭션으로 실행되고 API 테스트에서 조회 전후 상태가 변경되지 않음을 확인했다.
- `backend:convention`을 포함한 `verify:changed`가 종료 코드 0으로 통과했다.
- `backend/conventions/review.md` 기준으로 Controller의 DTO 경계, feature package, 예외·Entity 규칙, 테스트 유무를 점검했다.

## 중단 조건

- 두 GET endpoint를 하나의 query surface로 제공하려면 기존 모듈 또는 API 경계를 바꿔야 한다.
- JWT `sub` 외 회원 식별자를 요청으로 받아야만 조회할 수 있다.
- 쿠폰 목록이나 사용 내역 조회가 lazy loading 또는 도메인 메서드를 통해 상태를 변경한다.
- 제품 문서에 없는 구매·수정 command를 같은 task에 포함해야 한다.
- 내부 메모와 회원 공개 필드의 구분이 기존 응답 계약에서 명확하지 않아 개인정보를 안전하게 제한할 수 없다.
