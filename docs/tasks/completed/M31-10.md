## Completion Evidence

- `ErrorResponseWriter`가 이미 commit된 응답에는 아무 것도 추가하지 않으며, 그렇지 않은
  경우 상태와 `application/json` Content-Type을 설정한 뒤 기존 `ErrorResponse`만
  직렬화한다.
- `GlobalExceptionHandler`, `JwtAuthenticationEntryPoint`, `JwtAccessDeniedHandler`는
  모두 같은 writer와 `ErrorResponse` 생성 경로를 사용한다. Controller가 오류 응답을
  직접 만들지 않는다.
- JSON 본문 오류, Bean Validation, path variable·query parameter 변환 또는 누락은
  `COMMON_INVALID_REQUEST`(400)로 반환한다. validation field error는 기존
  `fieldErrors` 구조를 유지하며 거부된 입력값은 응답에 포함하지 않는다.
- 누락 API는 현재 Spring Boot 4.1의 정적 리소스 처리에서 발생하는
  `NoResourceFoundException`을 거쳐 `COMMON_NOT_FOUND`(404)로 반환한다. 존재하는
  URI의 지원하지 않는 method는 `COMMON_METHOD_NOT_ALLOWED`(405)로 반환한다.
- 인증 누락·형식 오류·만료·위조 JWT는 `COMMON_UNAUTHORIZED`(401), 인증된 USER의
  ADMIN 경로 요청은 `COMMON_FORBIDDEN`(403)으로 반환한다.
- 기존 `BusinessException`의 status·code·message·details는 보존한다. 처리되지 않은
  예외는 `COMMON_INTERNAL_ERROR`(500)만 반환하여 내부 예외 메시지와 stack trace를
  노출하지 않는다.

## 남은 위험

- 인증되지 않은 `/api/**` 미존재 URI는 MVC에 도달하기 전에 Security 정책상 401을
  반환한다. 인증된 요청에서만 404 공통 응답 경로가 적용되며, 이는 기존 인증 우선순위를
  변경하지 않는 의도된 동작이다.
- 비 API 정적 리소스와 framework-level 오류 중 response가 이미 commit된 경우에는
  공통 응답으로 교체하지 않고 기존 응답을 보존한다.

## 중단 조건

- ErrorResponse 필드 또는 `details` 계약 변경이 필요하다.
- 기존 Security 인증·인가 정책을 광범위하게 재설계해야 한다.
- 같은 원인의 필수 검증 실패가 세 번 반복된다.
