## Completion Evidence

- 설정 변경은 ScheduleConfigGuard를 ACTIVE에서 SYNCING으로 전환하고 모든 horizon 날짜가
  같은 pending version을 적용한 뒤에만 ACTIVE로 복귀한다.
- 프로세스 중단 후 같은 pending version을 멱등 재개하며 경과 시간만으로 강제 ACTIVE
  전환하지 않는다.
- SYNCING은 예약 가능 조회와 신규 일정 진입만 503으로 차단하고 기존 예약·쿠폰·휴무
  정리와 안전한 종료 Command는 계속 허용한다.
- 정기 휴일·Template 비활성화는 TEMPLATE TimeSlot에만 적용하고 기존 활성 예약은 별도
  휴무 정리 Read Model에서 추적한다.
- 독립 마감 원인, CLOSING 허용·차단 전이와 휴무 전용 stable 쿠폰 처리를 문서화했다.
- 활성 예약 overlap은 member-day guard, `active_slot_guard`와 MySQL 계약 테스트로
  보장하도록 계획했다.
- R04·R05는 외부 운영 진입점을 제외하고 R06 엔진 완료 후 R11에서 API를 공개한다.

## 남은 위험

- `is_closed` generated column과 mutable+CHECK 중 실제 JPA에 더 안전한 방식은 M31-R01에서
  코드와 migration 실험 후 확정한다.
- 전역 SYNCING은 설정 동기화 장애가 길어지면 신규 예약 가용성을 낮춘다. R06에서 재시작
  복구, 수동 재시도, 진행률과 장기 지속 구조화 로그를 검증해야 한다.
- 기존 TEMPLATE 예약의 휴무 정리는 자동 취소하지 않으므로 운영자가 영향 목록을 끝까지
  처리해야 한다.

## 중단 조건
