# M34-00 Completion Evidence

## 상태

`DONE`

## 목표

정규 시간표의 사용자-facing 삭제, 같은 시간대 재운영과 미래 TEMPLATE TimeSlot 정원 동기화
정책을 기존 schedule version·마감 원인·Reservation 불변식과 일치하는 SSOT/ADR로 확정한다.

## 확정 계약

- 관리자 `삭제`는 내부적으로 Template `active=false`인 운영 종료이며 Template, TimeSlot,
  Reservation과 감사 행을 물리 삭제하지 않는다.
- 삭제는 미래 TEMPLATE TimeSlot을 닫고 새 occurrence 생성을 중단하지만 기존 Reservation, 쿠폰
  hold와 결제 상태를 자동 변경하지 않는다.
- 미래 `ReservationStatus.occupyingStatuses()` Reservation은 `예약 정리 필요` 건수·목록으로 파생하고
  기존 관리자 Reservation 취소 흐름에서 처리한다.
- 같은 요일·시각 재생성은 inactive Template ID를 현재 설정으로 갱신해 재사용하고 Reservation 상태를
  복구하지 않는다.
- 미래 TEMPLATE TimeSlot은 현재 Template 정원을 따르되 slot-level `capacityOverridden=true`인 개별
  정원 보정을 제외한다.
- 점유 하한 충돌은 Template 변경 전체를 거부하고, 성공한 설정은 기존 날짜별 짧은 트랜잭션과
  `ScheduleDate.appliedConfigVersion`으로 완결한다.
- Template 동기화는 `templateInactiveClosed`와 비 override 정원만 소유하며 다른 마감 원인,
  MANUAL TimeSlot과 과거 운영 사실을 보존한다.
- 2026-09-19 배포 데이터 확인으로 rollout 결정을 수정했다. 기존 TEMPLATE TimeSlot은
  `capacityOverridden=false`로 이관하되 M34-03 migration 자체는 기존 정원 값을 변경하지 않는다.
  상세 근거와 MANUAL 경계는 ADR-024의 기존 데이터 rollout을 따른다.

## 선행 구현 결함과 작업 순서

- M34-01: `MemberAvailableTimeSlotsService`의 SYNCING 조회 guard 누락을 기존 503 계약으로 보완한다.
- M34-02: 날짜 범위를 우회할 수 있는 impact query를 Template별 미래 점유 Reservation read model로
  교체한다.
- M34-03~04: 정원 provenance를 먼저 도입한 뒤 정확한 미래 점유 read model을 사용해 수정·재운영
  동기화를 구현한다.
- M34-05~08: 삭제·동일 key 재운영 API, OpenAPI/generated client, 관리자 Web과 최종 Gate 순서로
  진행한다.

## 독립 검토

- Backend/Capacity 사전 검토: 관리자 개별 정원 Command가 전체·원형·클래스 정원을 한 번에 교체하므로
  현재 요구는 slot-level boolean provenance 하나로 표현 가능하다고 판단했다.
- Lifecycle/UX 사전 검토: inactive Template과 미래 점유 Reservation 파생값으로 운영 종료와 정리 필요
  상태를 표현할 수 있으며 별도 삭제 상태가 필요하지 않다고 판단했다.
- 최종 read-only 아키텍처 리뷰는 ADR-015의 오래된 Template 정리 표현, M34-04의 read model 의존성,
  occurrence-level version으로 오해될 표현을 각각 HIGH 1건, MEDIUM 2건으로 지적했다. 모두 수정했고
  unresolved CRITICAL/HIGH/MEDIUM finding은 없다.
