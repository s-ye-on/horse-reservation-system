- 관리자 대시보드 화면
- 기존 예약 목록·상세 검색 계약 변경
- 예약 상태 변경, 정원·쿠폰 처리
- 통계 영속화, 캐시, 별도 집계 테이블

## 완료 조건

- [x] `ROLE_ADMIN`은 날짜 범위의 전체 예약 수와 상태별·일자별 집계를 조회할 수 있다.
- [x] 날짜를 생략하면 `Asia/Seoul`의 오늘 하루를 조회하고 시작일이 종료일보다 늦으면 400을 반환한다.
- [x] 상태별 집계는 0건인 상태를 포함한 모든 `ReservationStatus`를 고정 순서로 반환한다.
- [x] 집계 조회는 데이터를 변경하지 않으며 일자, 상태 순으로 결정적인 결과를 반환한다.
- [x] `(lesson_date, status)` 집계 인덱스가 Flyway migration으로 생성된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 완료 증거

- `GET /api/admin/reservations/summary`가 날짜 범위의 전체·상태별·일자별 집계를 반환한다.
- 상태별 결과는 예약 상태 전체를 도메인 순서로 제공하고 0건 상태도 유지한다.
- V12 migration과 MySQL 통합 테스트가 `(lesson_date, status)` 인덱스 순서를 검증한다.
- OpenAPI와 공유 TypeScript API Client가 평면 날짜 query parameter로 재생성되었다.

## 중단 조건

- 집계 결과를 위해 Reservation 이외의 점유 원장이 필요하다.
- 날짜 범위의 제품 기준이 기존 `Asia/Seoul` 정책과 충돌한다.
- 기존 예약 검색 API의 응답 계약을 깨야 한다.
- 집계 과정에서 예약, 정원, 쿠폰 또는 감사 이력이 변경된다.
- 같은 원인의 검증 실패가 세 번 반복된다.
