## Completion Evidence

### 운영 Secret과 fail-fast

- 운영 프로필은 `prod`로 확정하고 `application-prod.yml`은 `JWT_SECRET`을 fallback 없이
  `security.jwt.secret`에 연결한다.
- `prod` 전용 설정 검증은 외부 `JWT_SECRET`과 실제 Decoder 설정값이 동일한지 확인한다.
- 누락·빈 문자열·공백·32바이트 미만·개발 기본값·알려진 placeholder는 Secret 값을
  포함하지 않는 고정 메시지로 시작을 중단한다.

### 개발·테스트·OpenAPI·데모 경계

- 기본 `application.yml`의 개발 fallback은 변경하지 않아 기존 로컬·테스트 실행을 유지한다.
- `openapi` 프로필에는 운영 검증을 적용하지 않는다.
- 로컬 데모는 기존처럼 실행 시 생성한 Secret을 백엔드와 JWT 프록시에 함께 외부 주입한다.
- 현재 Compose는 로컬 MySQL만 소유하므로 백엔드 Secret이나 임의 배포 구성을 추가하지 않았다.

### 보안과 인증 회귀

- 유효·만료·위조 JWT와 401·403 공통 `ErrorResponse` 회귀 테스트를 유지한다.
- 운영 시작 실패 원인에는 필요한 환경 변수 이름만 포함하며 입력 Secret은 예외와 로그에
  노출하지 않는다.
- 저장소에는 운영 Secret을 추가하지 않았고 문서의 실행 예시는 고정 Secret 형태가 아니라
  외부 Secret 저장소 변수 참조만 기록했다.

## 독립 검토

  남은 HIGH·MEDIUM finding이 없다.
- Security: `GO`. Secret fallback·placeholder·길이·로그 노출 방어를 확인했으며 남은

## 남은 위험

- 기본 프로필의 개발 fallback은 호환성을 위해 유지된다. 운영 배포에서 `prod` 프로필을
  활성화하지 않으면 개발 fallback으로 시작할 수 있으므로 배포 파이프라인의 프로필 Gate가
  필요하다. 실제 배포 파이프라인 검증은 현재 존재하지 않으며 후속 배포 작업에서 다룬다.
- 실제 로그인과 토큰 발급, Secret 키 회전 및 이전 키와의 전환 정책은 후속 범위다.
