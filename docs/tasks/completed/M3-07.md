## 완료 조건

- [x] ADMIN만 예약 감사 이력을 최신 발생순과 이력 ID 역순으로 페이지 조회한다.
- [x] 회원 이름·전화번호 키워드, 예약 ID, 발생 기간, 행위자 유형, 변경 유형 필터를 지원한다.
- [x] 응답은 회원·예약 식별 정보, 행위자, 사유, 전후 상태·일정, 쿠폰 처리, 발생 시각을 제공한다.
- [x] 조회는 감사 이력과 예약·회원·쿠폰 상태를 변경하지 않으며 잘못된 필터·날짜·페이지를 일관된 오류 응답으로 거부한다.
- [x] `@ModelAttribute` Query DTO가 OpenAPI에서 평면 query parameter로 생성되고 전체 기간 정렬 인덱스가 존재한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- `GET /api/admin/audit-logs`가 예약 변경 이력을 `occurredAt DESC`, `auditLogId DESC`로 페이지 조회한다.
- 회원 이름·전화번호, 예약 ID, 발생 기간, 행위자, 변경 유형 필터와 기본 20·최대 100 페이지 계약을 검증했다.
- 응답의 행위자 인증 주체, 사유, 전후 상태·일정, 쿠폰 처리와 발생 시각을 MySQL API 테스트로 검증했다.
- 미인증 401, 회원 403, 잘못된 조건 400, 조회 전후 DB 불변성을 검증했다.
- ADR-011에 `ReservationChangeLog`와 `CouponUsageLog`의 별도 SSOT, 추론·backfill 금지, M3-09 분리 다운로드 결정을 기록했다.
- V13에 전체 최신순 조회 인덱스를 추가하고 컬럼 순서를 `information_schema`에서 검증했다.

## 중단 조건

- 조회를 위해 기존 감사 행을 수정하거나 과거 상태를 추론해 저장해야 한다.
- 예약 변경 이력과 쿠폰 사용 이력을 하나의 쓰기 원장으로 합쳐야 한다.
- 회원·예약·기간 필터를 안정적으로 페이지 조회할 수 없는 스키마 변경이 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
