## Completion Evidence

- [M31 Command Lock Matrix](../../architecture/m31-command-lock-matrix.md)에 현재
  Command별 Repository 메서드, 실제 SQL 조건, 잠금 순서, 인덱스와 교차 대기를 기록했다.
- MySQL 8.4 V32 격리 DB에서 날짜·TimeSlot·overlap·점유·Coupon 선택 SQL의
  `EXPLAIN FORMAT=JSON`과 overlap의 `EXPLAIN ANALYZE`를 검증했다.
- 겹침 조회 결과가 없어도 같은 회원·날짜의 range 안 삽입이 `REPEATABLE READ`
  next-key/gap lock에 의해 대기하고, 단건 `FOR UPDATE`가 동일 Member 갱신을
  차단하는 것을 실제 error code 1205로 재현했다.
- 점유 조회는 `idx_reservations_occupancy`를 후보로 보유하지만 카디널리티와
  `ORDER BY id` 비용에 따라 `PRIMARY` index scan 또는 occupancy range scan을
  선택할 수 있어 잠금 범위가 통계 의존적임을 기록했다.
- 현재 수업 완료가 `Reservation -> Member -> Coupon`, TimeSlot 정원 변경·삭제가
  ScheduleDate 잠금 없이 TimeSlot에서 시작하는 두 canonical 차이를 발견해
  M31-07의 필수 회귀 기준으로 고정했다.
- `review.md` 자기 점검 결과 프로덕션 Controller·DTO·Domain·Exception은 변경하지
  않았고, 새 MySQL 테스트 메서드는 한글 이름·Given/When/Then에 해당하는 준비·실행·검증
  구분과 예외 경로 단언을 사용한다. `backend:convention`도 통과했다.

## 중단 조건

- 현재 SQL과 Repository 계약을 문서화하려면 프로덕션 잠금 구현을 먼저 변경해야 한다.
- MySQL V32에서 필수 실행 계획이나 잠금 범위를 재현할 수 없다.
- 입력 문서의 canonical 순서 또는 활성 예약 정의가 서로 충돌한다.
- 기존 V1~V32 migration 수정이나 데이터 보정이 필요하다.
- 검증이 반복 실행에서 불안정하다.
