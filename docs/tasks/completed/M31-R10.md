## Completion Evidence

### 구현

- `V30`은 Closure와 고정 Impact membership을 추가하고 generated active guard와 UNIQUE로
  TimeSlot별 `IN_PROGRESS` 작업을 하나로 제한한다. 기존 `admin_closed` 행은 활성 예약이
  있으면 IN_PROGRESS와 Impact로, 없으면 COMPLETED 이력으로 additive 이관한다.
- `V31`은 Impact의 시작 상태를 기존 활성 상태의 소문자 DB 계약으로 제한한다.
- 휴강 시작은 ScheduleDate와 TimeSlot을 잠근 뒤 `adminClosed`, Closure, Impact와
  ScheduleAuditLog를 한 트랜잭션에 저장한다. 영향 membership은 갱신하지 않고 현재
  Reservation 상태와 원래 TimeSlot 유지 여부로 해결 상태를 계산한다.
- 완료는 고정 Impact 전부 해결과 현재 활성 예약 0건을 재검사한다. 철회는 해결 건수
  0건일 때만 허용하고 재개는 `adminClosed`만 해제해 다른 마감 원인과 기존 예약을
  변경하지 않는다.
- 기존 PATCH는 휴강 workflow에만 위임한다. 이미 열린 상태의 재개 요청과 반복 요청은
  감사 중복 없이 멱등 no-op이다.
- 휴강 전용 관리자 취소와 회원 직접 취소는 마장 책임을 적용하며 Coupon 예약
  `stable/RETURN`, 1회 결제 `stable/NONE`을 강제한다.

### 잠금과 동시성

- 휴강과 예약 정리는 `ScheduleDate → member-day guard → TimeSlot → TimeSlotClosure →
  Reservation → Coupon → append-only audit` 순서를 지킨다.
- PATCH 재개 분기 전에 Closure를 먼저 잠그던 경로를 제거하고 한 트랜잭션의
  `withdrawOrReopen`으로 합쳤다.
- 일괄 출석이 Reservation을 선행 잠그던 경로를 projection 검증으로 바꾸고 단건
  완료·노쇼 서비스가 날짜와 TimeSlot을 먼저 잠그도록 보정했다.
- 실제 MySQL 동시 휴강 시작, generated guard NULL 동작, V29 upgrade와 rollback을
  검증했다.

### 독립 검토

### 배포 제약과 후속

- R10은 기존 PATCH로 휴강을 시작할 수 있지만 고정 영향 조회·예약별 전용 취소·완료·
  철회·재개 공개 API는 R11 소유다. 운영에는 R10과 R11을 함께 배포하거나 기존 관리자
  마감 진입점을 제한해야 한다.
- R13은 영향 대상·남은 대상·진행률, 예약별 조작, 일부 처리 후 철회 불가와 재개 시
  기존 예약 미복구 경고를 구현한다.
- 연락 상태·메모·담당자는 별도 후속 요구사항이며 R10/R11/R13에 포함하지 않는다.
