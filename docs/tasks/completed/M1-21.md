## 완료 조건

- [x] 회원 식별 정보와 일반·마장마술·장애물 중 한 쿠폰 종류를 확인한 뒤 10회권 등록을 제출할 수 있다.
- [x] 제출 중 버튼과 입력을 잠가 중복 요청을 막고 성공 시 서버가 반환한 쿠폰 종류·총 횟수·상태를 표시한다.
- [x] 필수 입력 오류, 권한 거부, 회원 없음, 서버 유효성 오류를 서로 구분해 폼 가까이에 표시한다.
- [x] 320px 이상 반응형 폼·오류·중복 제출 컴포넌트 테스트와 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 회원 선택 결과에 이름, 전화번호, 회원 ID와 일반 기승 횟수를 표시하고 세 쿠폰 종류 중 하나를 선택하게 했다.
- API 요청은 고정된 10회를 전송하며 성공 응답의 종류, 총 횟수, 상태를 화면에 표시한다.
- 요청 중 fieldset과 제출 버튼을 잠그고 자동 재시도를 사용하지 않아 빠른 중복 제출을 방지한다.
- 로컬 필수 입력과 HTTP 400, 403, 404 오류를 폼 가까이에서 구분해 안내한다.
- `mise run backend:convention`, `mise run web:typecheck`, `mise run web:lint`도 종료 코드 0으로 통과했다.

## 중단 조건

- M1-02A API로 등록 대상 회원을 식별할 수 없거나 M1-07 API가 회원 ID와 쿠폰 종류를 받아 정확히 10회를 등록하는 계약을 제공하지 않는다.
- 등록 성공 응답만으로 생성된 쿠폰의 종류·총 횟수·상태를 확인할 수 없다.
- 재시도 또는 빠른 연속 클릭에서 중복 등록 여부를 판별할 API 오류 계약이 없다.
- 화면 구현에 쿠폰 스키마 변경이나 생성형 API 클라이언트 직접 수정이 필요하다.
