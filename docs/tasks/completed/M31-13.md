## 완료 조건

- [x] 대상 목록이 Page metadata로 이전·다음과 현재 페이지를 제공한다.
- [x] 회원 예약이 `displayGroup`과 `status`를 서버에 전달하고 탭 건수에 `totalElements`를 사용한다.
- [x] 필터·탭 변경은 page 0으로 초기화하며 오래된 응답이 최신 화면을 덮지 않는다.
- [x] 최초 loading, 이동 중, 빈 목록, 오류·재시도와 범위 초과 복귀를 처리한다.
- [x] 페이지 조작은 접근 가능하며 320px에서 겹치거나 잘리지 않는다.
- [x] 기존 관리자 감사 Page와 RFC3339 표시가 회귀하지 않는다.
- [x] Frontend와 QA 독립 검토에 HIGH 또는 MEDIUM finding이 남지 않는다.

## 중단 조건

- 요구사항을 충족하려면 Backend 또는 OpenAPI 계약 변경이 필요하다.
- 기존 배열 소비자를 호환 가능하게 유지할 수 없다.
- Page metadata로 정확한 탭 건수나 범위 초과 복귀를 구현할 수 없다.
- 기존 사용자 변경과 M31-13 변경을 안전하게 분리할 수 없다.
- 독립 검토에서 HIGH 또는 MEDIUM finding이 남는다.

## Completion Evidence

- 관리자 회원, 관리자 예약, 회원 쿠폰, 회원 예약 목록이 Page 전체 응답을
  소비하고 서버의 `page`, `totalElements`, `totalPages`, `hasNext`로 이전·다음
  이동과 1-based 현재 페이지를 표시한다.
- 관리자 감사 목록의 기존 Page UI에는 이동 중 중복 요청 차단, 오류 재시도,
  범위 초과 페이지 복귀를 보강했다.
- 관리자 예약의 네 운영 상태와 회원 쿠폰·사용 이력은 서로 독립된 Page 상태를
  유지한다.
- 회원 예약은 예정 탭에 `displayGroup=UPCOMING`, 지난 탭에
  `displayGroup=PAST`를 전달한다. 예정 상태 필터는 `status`로 전달하며 탭 또는
  필터 변경 시 page 0으로 복귀한다.
- 회원 예약 탭 건수는 group-only Page의 `totalElements`를 사용한다. 보조 건수
  조회 실패는 활성 목록을 차단하지 않고 `—`와 별도 재시도 상태로 격리한다.
- TanStack Query key에 탭, 상태와 페이지를 포함하여 늦게 도착한 이전 응답이
  최신 화면을 덮지 않도록 했다.
- 회원 목록 페이지 전환 시 현재 Page에 존재하는 회원 ID를 렌더 단계에서
  선택하여 이전 페이지 상세가 남지 않도록 했다.
- 버튼은 실제 `button`과 `disabled` 상태를 사용하고 현재 페이지 정보는
  `aria-live`로 제공한다.
- 실제 로컬 데모를 320x800 뷰포트에서 확인했다. 회원 예약, 회원 쿠폰, 관리자
  회원, 관리자 감사 화면의 문서 폭은 320px이며 페이지 조작 버튼이 뷰포트
  밖으로 벗어나지 않았다.

## 독립 검토

- Frontend 최초 검토에서 보조 탭 건수 조회 실패가 전체 화면을 차단하는 문제와
  회원 Page 전환 시 이전 상세가 남는 문제를 MEDIUM으로 발견했다.
- 두 문제와 회귀 테스트를 보정한 뒤 Frontend 재검토에서 HIGH/MEDIUM finding
  없음으로 확인했다.
- QA 검토는 HIGH/MEDIUM finding 없음으로 확인했다. 감사 화면 재시도와 범위
  초과 복귀의 LOW 테스트 공백은 관련 테스트를 추가해 보정했다.

Gate만 재실행하여 통과했다.
