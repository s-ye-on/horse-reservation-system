# M33-05 Completion Evidence

## 상태

`DONE`

## 목표

M33-02의 주간 운영 캘린더 Query API와 M33-03 generated TypeScript client를 사용해 관리자가
현재 주와 탐색한 주의 실제 materialized TimeSlot, 예약 회원, 기승 클래스와 예약 상태를 한눈에
확인하는 반응형 Web 화면을 제공한다.

## 구현 계약

- 관리자 메뉴에 `주간 운영 캘린더` 진입점을 추가하고
  `/admin/weekly-operations-calendar`를 기존 ADMIN route guard 아래에 배치했다.
- 기본 기준일은 브라우저 시각을 `Asia/Seoul`로 해석한 현재 날짜이며, 이전 주·다음 주 이동과
  `오늘` 버튼으로 현재 날짜가 포함된 월요일~일요일 주간 View에 복귀한다.
- Backend가 반환한 실제 TimeSlot만 날짜와 시작 시간 기준의 주간 시간표에 배치한다. DB에 없는
  시간대나 슬롯을 Frontend에서 생성하지 않는다.
- 같은 날짜·시간에 여러 TimeSlot이 있으면 같은 시간대 안에 각각의 슬롯을 표시하고, 같은
  TimeSlot의 여러 Reservation은 하나의 슬롯 블록 안에 함께 표시한다.
- 실제 TimeSlot에 표시 Reservation이 없으면 `예약 없음`을 표시한다. 조회 주에 TimeSlot 자체가
  없을 때는 별도의 주간 empty state를 표시한다.
- 회원 이름, RidingClass와 ReservationStatus는 API 응답을 그대로 사용하고 화면에서 자연스러운
  한글 라벨로 표현한다. Frontend는 점유·완료 상태 필터나 정원 정책을 다시 구현하지 않는다.
- loading, API error와 TimeSlot 0건을 서로 다른 상태로 표시하고 오류에는 재시도 동작을 제공한다.
- 데스크톱은 월~일과 시간 흐름을 읽는 CSS grid 시간표를 사용한다. 760px 이하에서는 실제 슬롯
  카드를 날짜·시간 순으로 쌓고, 320px에서도 주 이동·재시도와 슬롯 내용을 가로 넘침 없이 유지한다.
- 시간표는 이름 있는 region, 날짜·시간 heading, 실제 시간대 group과 슬롯 article의 접근성 의미를
  유지하며 모바일에서도 이 구조를 접근성 트리에서 제거하지 않는다.

## API와 Web 경계

- feature adapter는 `AdminReservationQueryControllerApi.getWeeklyOperationsCalendar()`와 기존
  `bearerApiConfiguration`을 사용한다.
- 기준일은 generated request의 `referenceDate` 문자열로 전달하며 Frontend에서 시간대 timestamp로
  변환하지 않는다.
- Frontend는 API의 `timeSlots`와 각 슬롯의 `reservations`를 표시만 한다. 표시 Reservation 상태,
  가짜 슬롯 생성, RidingClass 정책과 capacity 계산을 별도로 소유하지 않는다.
- generated 파일, Backend/OpenAPI 계약과 M33-02 조회 정책을 변경하지 않았다.

## 독립 검토

- 최초 검토에서 모바일 CSS가 날짜·시간 heading을 접근성 트리에서 제거하는 MEDIUM finding과
  320px E2E의 시간표 의미 검증이 부족한 LOW finding을 확인했다.
- 모바일 heading은 시각적으로만 감추고 접근성 트리에는 유지하도록 보완했으며, unit/E2E에 이름 있는
  시간표 region, 날짜·시간 heading, 실제 시간대 group과 슬롯 article 검증을 추가했다.
- 재검토와 `verify:m33-05` 재실행에서 기존 MEDIUM/LOW finding이 해소됐고 새
  CRITICAL/HIGH/MEDIUM/LOW finding은 없다.
- 최종 read-only refactor review는 파일 책임, route 영향 범위, generated client 경계,
  Frontend 상태 필터·가짜 슬롯 부재를 확인했다. 추가 분해는 실제 결함 수정이 아닌 cosmetic
  refactor로 판단해 수행하지 않았다.
