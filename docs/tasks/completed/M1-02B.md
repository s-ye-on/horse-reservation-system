# M1-02B: 관리자 특수 클래스 승인 API

## 상태

`DONE`

## 목표

관리자가 회원의 마장마술·장애물 승인 상태를 변경한다.

## 담당

`backend`

## 선행 작업

- M1-02A 완료

## 입력 문서

- `docs/product/requirements.md`의 클래스와 관리자 기능
- `docs/architecture/api.md`의 회원과 쿠폰
- `docs/architecture/domain-model.md`의 `Member`
- `backend/conventions/README.md`

## 허용 범위

- `backend/src/main/java/com/horse/members/**`
- `backend/src/test/java/com/horse/members/**`
- `backend/openapi/horse-api.json`
- `frontend/packages/api-client/src/**` (API 생성 결과만)
- `docs/tasks/active/M1-02B.md`
- `docs/tasks/completed/M1-02B.md`

## 제외 범위

- 일반 기승 횟수 보정
- 독립 대마장 허용 플래그
- 회원 개인정보 수정과 쿠폰 등록
- 관련 없는 리팩터링과 컨벤션 변경

## 완료 조건

- [x] ADMIN이 마장마술·장애물 승인을 각각 변경할 수 있다.
- [x] Entity의 의미 있는 상태 변경 메서드가 승인 상태를 변경한다.
- [x] 승인 변경 후 파생 대마장 이용 가능 여부가 즉시 일관된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m1-02b
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m1-02b` 등록 확인 |
| `mise run verify:m1-02b` | 0 | ADMIN 승인·철회, MEMBER 거부, 회원 없음 API 테스트 4건 성공 |
| `mise run verify:changed` | 0 | backend convention·check·integration·OpenAPI·문서 검증 성공 |

## 중단 조건

- 승인 변경에 상담 이력이나 별도 승인 워크플로가 필요하다는 정책이 발견된다.
- 승인 철회가 기존 미래 예약에 미치는 정책이 구현 범위에 영향을 준다.
- ADMIN 외 권한 주체가 필요하다.

## Completion Evidence

- `PATCH /api/admin/members/{memberId}/riding-permissions`가 마장마술·장애물 승인 상태를 변경한다.
- `Member.changeDressageApproval()`과 `Member.changeJumpingApproval()`이 승인 상태를 소유한다.
- 승인·철회 직후 응답의 `canUseLargeArena`가 파생 정책과 일치한다.
