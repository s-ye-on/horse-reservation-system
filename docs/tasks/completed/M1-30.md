# M1-30: 활성 점유 기반 시간대 정원 축소 검증

## 제외 범위

- 예약 생성·상태 전이 정책 변경
- 정원 자동 조정과 예약 변경·취소
- DB 스키마와 기존 migration 수정
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [x] 전체 정원을 활성 예약 수보다 작게 줄이면 `409 Conflict`다.
- [x] 원형 또는 클래스 정원을 해당 활성 예약 수보다 작게 줄이면 `409 Conflict`다.
- [x] 유효한 정원 변경은 기존과 같이 성공한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m1-30
mise run backend:convention
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m1-30` 등록을 확인했다. |
| `mise run verify:m1-30` | 0 | API 및 MySQL 정원 통합 테스트가 성공했다. |
| `mise run backend:convention` | 0 | Checkstyle과 convention test가 성공했다. |
| `mise run verify:changed` | 0 | 백엔드·OpenAPI·웹·모바일 전체 게이트가 성공했다. |

## Completion Evidence

- 정원 변경과 예약 생성이 동일하게 TimeSlot 행을 먼저 비관적 잠금한다.
- 활성 상태 세 종류의 전체·원형·클래스 점유를 Entity가 새 정원과 비교한다.
- 점유 하한 위반은 `TIMESLOT_CAPACITY_BELOW_OCCUPANCY`와 `409 Conflict`로 반환된다.

## 중단 조건

- 활성 점유 상태가 제품 정책과 충돌한다.
- 정원 변경과 예약 생성에 동일한 TimeSlot 잠금 순서를 적용할 수 없다.
- 기존 migration 변경이 필요하다.
