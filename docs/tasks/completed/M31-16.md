## Completion Evidence

### 포트·프로세스·출력 격리

- OpenAPI는 OS 할당 backend 포트와 실행별 임시 DB·build·project cache를 사용한다.
- E2E 공식 진입점은 실행마다 backend·Vite 포트, DB, runtime을 만들고 Playwright child
  process group만 종료한다. 기존 `8080` 서버는 재사용하거나 종료하지 않는다.
- Playwright와 Vite 출력·cache는 실행 runtime 아래에 두고 종료 시 함께 삭제한다.
- 백엔드 검증은 `run-isolated-gradle.sh`를 통해 실행별 build·project cache와
  `--no-daemon` 계약을 사용한다.

### 경쟁·실패·정리 검증

- 데모 proxy가 `8080`을 점유한 상태의 `api:check`, OpenAPI와 E2E 병렬 실행,
  동일 E2E 두 실행, 백엔드 검증 두 실행, web build와 E2E를 검증했다.
- 실패 E2E와 정상 `api:check`가 서로 영향을 주지 않고, 자동 timeout은 `124`,
  SIGTERM은 `143`을 반환한 뒤 포트·DB·runtime을 정리한다.
- 호출자가 만든 runtime 디렉터리는 거부하고 sentinel을 보존한다.
- 검증 전후 임시 DB 집합과 Git working tree가 동일하며 child process와 고정 포트
  listener가 남지 않음을 확인한다.

### OpenAPI·E2E 회귀

- 실제 OpenAPI 서버는 동적 포트에서 시작하지만 외부 계약의 canonical server URL은
  `http://localhost:8080`으로 유지해 직접 Gradle 생성과 공식 생성 결과가 같다.
- fresh E2E DB에서 기존 fixture가 기본 DB 잔존 데이터에 기대지 않도록 ScheduleDate와
  member-day guard 정리 계약을 보정했다.
- `quality:m31-critical`에 MVP1 예약, MVP2 정책, MVP3 관리자 운영·생명주기와
  M31 Checkpoint E2E를 포함했다.

## 남은 위험

- OS 할당 포트를 확인한 뒤 Spring·Vite가 실제 bind하기 전까지 매우 짧은 TOCTOU가
  남는다. `strictPort`와 bind 실패로 다른 서버를 잘못 재사용하지는 않는다.
- `horse-mysql` 컨테이너, 사용자 Gradle dependency cache와 pnpm cache는 도구의
  동시성 계약을 신뢰해 공유한다.
- 직접 `playwright test`는 기존 로컬 호환 경로이며 병렬 격리 계약은 공식
  `pnpm --dir frontend/apps/web test:e2e -- <spec>` 진입점에만 적용한다.
- 실패 시 trace와 screenshot도 소유 runtime과 함께 삭제하므로 자동 Gate의 정리는
  보장되지만 실패 후 장기 분석을 위한 artifact 보존은 후속 CI 작업에서 다룬다.
