## 완료 조건

- [x] SSOT와 ADR이 Scheduler와 Command 검증 책임을 구분한다.
- [x] Aggregate, Application, Controller와 Read Model 책임 경계를 명시한다.
- [x] M3-13부터 M3-18까지 독립 Task와 검증 명령이 등록된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m3-12
mise run harness:loop-ready
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m3-12`부터 `verify:m3-18`까지 등록 확인 |
| `mise run verify:m3-12` | 0 | 문서 링크와 상태 용어 검사 통과 |
| `mise run harness:loop-ready` | 0 | M3-12 단일 active Task와 전용 검증 확인 |
| `mise run verify:changed` | 0 | backend, MySQL, OpenAPI, web 127건, mobile 전체 검증 통과 |

## Completion Evidence

- 승인·변경·취소와 완료·노쇼의 수업 시작 시각 경계를 제품 SSOT에 추가했다.
- ADR-013이 Aggregate 내부 불변식, Application 조정, Scheduler 상태 정리와 Read Model의
  책임을 구분한다.
- 구현을 M3-13부터 M3-18까지 Command, Job, API, 회원 UX, 관리자 UX, 회귀 Task로
  분해했다.
- 첫 `verify:changed` 실패는 실행 중인 로컬 데모 프록시의 8080 포트 점유가 원인이었고,
  데모 종료 후 같은 검증이 성공했다.

## 중단 조건

- 시간 경계 또는 자동 만료 상태가 입력 정책과 충돌한다.
- 후속 Task를 주요 동작 하나 단위로 자동 검증할 수 없다.
- 기존 하네스를 완화해야 문서 검증이 통과한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
