# M3-17: 관리자 출석 처리 가능 UX

## 상태

`COMPLETED`

## 목표

관리자 출석 화면을 오늘 처리 가능과 지난 미처리 예약 중심으로 구성하고 미래 수업의
완료·노쇼 실행을 노출하지 않는다.

## 담당

`frontend`, `qa`

## 선행 작업

- M3-15 완료

## 입력 문서

- [운영 정책](../../product/policies.md)
- M3-15 OpenAPI 계약

## 허용 범위

- `frontend/apps/web/src/features/admin-attendance/**`
- 관련 web 테스트와 스타일
- `docs/tasks/active/M3-17.md`, `docs/tasks/completed/M3-17.md`

## 제외 범위

- Backend 정책과 API 계약 변경
- 예약 운영 대시보드 전체 재설계
- 회원 화면과 모바일 앱
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [x] 오늘 처리 가능과 지난 미처리 예약을 구분한다.
- [x] 미래 수업에는 완료·노쇼 CTA를 노출하지 않고 서버 차단 이유를 표시한다.
- [x] 단건·일괄 처리 대상이 동일한 서버 행동 판정을 따른다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m3-17
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m3-17` 등록 확인 |
| `mise run verify:m3-17` | 0 | 출석 화면 테스트 22개, lint와 typecheck 통과 |
| `mise run verify:changed` | 0 | web 테스트 128개와 production build 통과 |

## Completion Evidence

- 확정 예약을 오늘 처리 가능, 지난 미처리, 시작 전 수업으로 구분한다.
- 시작 전 수업은 완료·노쇼 버튼 없이 서버 차단 사유를 표시한다.
- 단건 카드와 일괄 패널이 공통 `actions.complete`, `actions.noShow` 판정만 사용한다.
- 일괄 패널은 서버가 두 행동을 모두 허용한 예약만 선택 대상으로 구성한다.

## 중단 조건

- 출석 조회에 행동별 서버 판정이 없다.
- 단건과 일괄 처리 정책을 일관되게 표현할 수 없다.
- 같은 원인의 검증 실패가 세 번 반복된다.
