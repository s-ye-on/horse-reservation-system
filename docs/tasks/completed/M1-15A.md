## Completion Evidence

- `V7__create_reservation_change_logs.sql`이 FK, 행위별 CHECK, `(reservation_id, created_at, id)` 인덱스를 생성한다.
- `ReservationChangeLog.paymentRestored(...)`가 관리자 복구 행위의 전이·쿠폰·메모 값을 한 번에 고정한다.
- `@Immutable`, `updatable = false`, 제한된 Spring Data `Repository`로 기존 이력 수정·삭제 경로를 노출하지 않는다.
- 이름은 현재 도메인 문서 및 후속 task와 일치하는 `ReservationChangeLog`를 유지하고 JWT `sub`는 `actorAuthSubject`로 명시한다.

## 중단 조건

- 로그를 현재 예약 상태의 SSOT로 사용해야 한다는 요구가 추가된다.
- 기존 로그를 수정·삭제하는 API가 필요하다.
- JWT `sub` 외 개인정보나 토큰 원문을 저장해야 한다.
- 기존 migration 수정 또는 비가역 데이터 변환이 필요하다.
- 허용 범위 밖의 API·보안 변경이 필요하다.
