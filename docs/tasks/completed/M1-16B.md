# M1-16B: 관리자 입금대기 조회 API

## 상태

`DONE`

## 목표

관리자가 입금 확인과 만료 복구 대상을 마감 정보와 함께 조회한다.

`backend`

## 선행 작업

- M1-12, M1-15, M1-16 완료

## 입력 문서

- [제품 요구사항](../../product/requirements.md)의 관리자 `입금대기 확인과 만료 예약 복구`

- 입금 확인·만료·복구 command 변경

- 외부 결제·입금 연동, 알림, 관리자 화면
- 기존 아키텍처·컨벤션 변경과 관련 없는 리팩터링

## 완료 조건

- [x] ADMIN만 `GET /api/admin/pending-payments`로 `pending_payment`와 복구 대상인 `payment_expired` 예약을 조회한다.
- [x] 각 항목에 회원·수업·상태·신청 시각·`payment_due_at`과 현재 시각 기준 마감 여부를 제공한다.
- [x] 경계 시각과 상태별 결과를 고정 Clock으로 검증하며 조회가 만료·복구나 정원 변경을 일으키지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- `pending_payment`, `payment_expired`만 `paymentDueAt ASC`, 예약 ID ASC로 조회한다.
- 관리자에게 회원 이름·전화번호, 수업, 신청·마감 시각과 `deadlineExceeded`를 제공한다.
- 마감 시각과 현재 시각이 같으면 마감된 것으로 계산한다.
- 조회 전후 예약 상태·버전·수정 시각이 동일함을 MySQL에서 검증한다.
- OpenAPI 계약과 TypeScript 공유 API 클라이언트를 재생성했다.

## 중단 조건

- `payment_expired`를 이 endpoint에 포함할지 별도 조회로 분리할지 SSOT와 구현 계약이 충돌한다.
- 복구 가능 여부를 조회 시 정원 선점으로 표현해야 한다.
- 입금대기 목록의 회원 개인정보 노출 범위를 관리자 권한 정책으로 결정할 수 없다.
- 조회 중 자동 만료를 실행해야 한다는 요구가 추가된다.
- 허용 범위 밖의 스키마·프론트엔드 변경이 필요하다.
