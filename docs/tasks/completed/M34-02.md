# M34-02 Completion Evidence

## 상태

`DONE`

## 목표

Template별로 아직 시작하지 않은 점유 Reservation의 건수와 목록을 동일한 조회 계약으로 제공한다.

## 구현 계약

- 정리 대상은 `ReservationStatus.occupyingStatuses()`에서 파생한
  `PENDING_ADMIN_APPROVAL`, `PENDING_PAYMENT`, `CONFIRMED` Reservation이다.
- `Asia/Seoul` 현재 시각을 기준으로 아직 시작하지 않은 TimeSlot만 조회하며 과거와
  현재 시각에 이미 시작한 수업은 제외한다.
- `time_slot_capacities.template_id`를 기준으로 Template 소속을 결정하므로 다른 Template의
  Reservation은 포함하지 않는다.
- `GET /api/admin/schedule-templates/{templateId}/future-occupying-reservations`는 관리자에게
  정리 대상 건수와 예약 목록을 함께 반환한다.
- 응답에는 예약 ID, 수업 일자와 시작·종료 시각, 회원 ID·이름·전화번호,
  `RidingClass`, 원래 `ReservationStatus`를 포함한다.
- `reservationCount`는 반환 목록의 크기에서 파생하므로 건수와 목록이 다른 필터 의미를
  가질 수 없다. 존재하지 않는 Template은 기존 `SCHEDULE_TEMPLATE_NOT_FOUND` 계약을 따른다.
- 기존 impact preview SQL의 날짜 조건은 template 연결 분기에도 적용되도록 괄호를 바로잡아
  과거 template-linked 행이 기간 밖에서 집계되는 회귀를 차단했다.

## Query와 인덱스

- read model은 `time_slot_capacities`를 root로 Template과 미래 범위를 먼저 제한하고,
  Reservation 및 Member를 한 번에 projection한다.
- Template 존재 확인 1회와 projection 1회, 총 2회의 bounded query를 사용하며 예약 수가
  1건에서 21건으로 증가해도 query 수는 2회로 유지된다.
- `V41__index_template_future_time_slots.sql`에서
  `(template_id, lesson_date, start_time)` 인덱스를 추가했다.
- 1,200개 TimeSlot/Reservation fixture의 `EXPLAIN` 검증에서 TimeSlot은
  `idx_time_slot_template_lesson_start`, Reservation은 기존 occupancy/active-slot 인덱스를 사용했다.
