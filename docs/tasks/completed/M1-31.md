# M1-31: 시간대 삭제와 예약 생성 직렬화

## 상태

`COMPLETED`

## 목표

시간대 삭제와 예약 생성이 경쟁해도 예약 이력이 생긴 시간대는 삭제되지 않는다.

## 담당

`backend`

## 선행 작업

- M1-30 완료

## 입력 문서

- [운영 정책](../../product/policies.md)의 시간대 운영과 삭제
- [예약 점유 ADR](../../architecture/adr-005-reservation-occupancy-ssot.md)

## 허용 범위

- `backend/src/main/java/com/horse/timeslots/**`
- `backend/src/test/java/com/horse/timeslots/**`
- `mise.toml`
- `docs/tasks/**`

## 제외 범위

- TimeSlot FK 추가와 예약 스키마 변경
- 논리 삭제와 삭제 이력
- 예약 생성 정책 변경
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [x] 삭제가 TimeSlot을 비관적 잠금한 뒤 예약 이력을 검사한다.
- [x] 삭제와 예약 생성 경쟁에서 둘 중 하나만 정책에 맞게 성공한다.
- [x] 예약 이력이 존재하면 `409 Conflict`이며 TimeSlot이 유지된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m1-31
mise run backend:convention
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m1-31` 등록을 확인했다. |
| `mise run verify:m1-31` | 0 | 삭제·예약 MySQL 경쟁 테스트와 API 테스트가 성공했다. |
| `mise run backend:convention` | 0 | Checkstyle과 convention test가 성공했다. |
| `mise run verify:changed` | 0 | 백엔드·OpenAPI·웹·모바일 전체 게이트가 성공했다. |

## Completion Evidence

- 삭제가 `findByIdForUpdate`로 TimeSlot을 잠근 뒤 예약 이력을 검사한다.
- 동시 삭제·예약 중 하나만 성공하고 TimeSlot 없는 예약은 남지 않는다.
- 기존 예약 이력이 먼저 생성되면 삭제는 `TIMESLOT_RESERVATION_HISTORY_EXISTS`로 거부된다.

## 중단 조건

- 예약 생성 또는 복구 경로가 TimeSlot 잠금을 공유하지 않는다.
- 기존 migration 변경이 필요하다.
- 경쟁 테스트를 결정적으로 구성할 수 없다.
