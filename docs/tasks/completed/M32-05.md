# M32-05 Completion Evidence

## 목표

M32-02에서 구현한 ADMIN 전용 FamilyGroup Command를 관리자 Web에 연결하고, 그룹 검색,
구성원 추가·제거, 변경 감사와 명시적 그룹 해제를 320px 화면에서도 사용할 수 있게 한다.

## 선행 작업

- M32-01 FamilyGroup, membership와 감사 원장 스키마
- M32-02 ADMIN 전용 생성·추가·제거·해제 Command와 필수 사유 감사
- ADR-018의 대표자 없음, 빈 ACTIVE 그룹, 비가역 해제와 전용 이관 미지원 계약

## 구현

- 관리자 가족 그룹 조회
  - 그룹 이름과 ACTIVE/DISSOLVED 상태 검색
  - 6필드 Page 계약과 활성 구성원 수 일괄 조회
  - 현재 구성원, 추가 가능한 미배정 회원과 최신순 감사 이력 Page 조회
  - 구성원과 감사의 연관 데이터를 일괄 조회해 항목 수에 따른 N+1을 방지
- 관리자 Web
  - `/admin/family-groups` ADMIN 보호 Route와 관리자 메뉴 연결
  - 그룹 검색·상태 필터·Page 탐색과 loading·empty·error·retry 상태
  - 필수 사유를 포함한 그룹 생성, 구성원 추가·제거와 비가역적 그룹 해제
  - 변경 성공 후 그룹·구성원·후보·감사 Query를 다시 읽어 최신 상태 반영
  - 처리자, 사유, 시각과 전후 상태를 포함한 감사 이력 표시
  - 실제 320px viewport에서 핵심 조작과 가로 overflow 부재 검증
- API adapter
  - 중앙 Bearer configuration과 기존 401 refresh 경계를 재사용
  - M32-09의 Phase B OpenAPI·생성 Client 동기화 전까지 가족 타입을 단일 adapter에 격리
- 테스트 fixture
  - 검색 폼을 semantic scope로 식별해 생성 폼의 동명 필드와 구분
  - 실제 fetch처럼 호출마다 새로운 Response body를 반환
  - assertion 삭제·skip·완화 없이 검색 초기화, Command payload와 Query 경로를 검증

## 검증 시나리오

- 비인증 401, MEMBER 403, ADMIN 조회 성공
- 그룹 이름·상태 검색, Page metadata와 활성 구성원 수
- 현재 구성원과 추가 가능 회원 분리
- 최신순 감사 이력과 RFC3339 시각
- 생성·추가·제거·해제의 필수 사유와 중복 요청 방지
- 변경 성공 후 그룹·구성원·후보·감사 재조회
- 빈 결과, 조회 오류와 재시도
- 관리자 메뉴·보호 Route
- 320px에서 검색·구성원 변경·감사 조작과 가로 overflow 부재

## 독립 검토

- Architecture reviewer가 Query API·Command 경계, N+1, ADMIN 권한, mutation 후 재조회,
  M32-09 전 임시 adapter와 320px E2E를 읽기 전용으로 검토했다.
- 최종 CRITICAL, HIGH, MEDIUM, LOW finding은 없다.

## 범위

- 가족 대표자, MEMBER 직접 관리와 전용 이관 기능은 추가하지 않았다.
- Coupon 소유권·후보·잠금·snapshot 정책은 변경하지 않았다.
- DB schema와 Flyway migration을 변경하지 않았다.
- Phase B OpenAPI 저장 계약과 생성 Client 동기화는 M32-09 범위로 유지했다.
- 일반 클래스 progression 기능인 M32-06에는 진입하지 않았다.
