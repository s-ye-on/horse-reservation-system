# M33-03 Completion Evidence

## 상태

`DONE`

## 목표

M33-01 월간 완료 기승 통계와 M33-02 주간 운영 캘린더의 Backend runtime 계약을 OpenAPI에
정확히 표현하고, repository의 정식 생성 절차로 TypeScript client와 모델을 동기화한다.

## 동기화 계약

- `GET /api/admin/reservations/monthly-ride-statistics`를
  `getMonthlyRideStatistics` operation으로 고정했다.
- 선택 `month` parameter는 `YYYY-MM` 형식이고, 선택 `rideType`은
  `ALL`, `GENERAL`, `DRESSAGE`, `JUMPING` enum이며 기본값은 `ALL`이다.
- 월간 응답은 조회 월·종류, 총 완료 횟수, 최고 완료 횟수와 공동 최고 회원 전체를 required
  field로 제공한다. 0건 응답의 기존 runtime 의미는 변경하지 않았다.
- `GET /api/admin/reservations/weekly-operations-calendar`를
  `getWeeklyOperationsCalendar` operation으로 고정했다.
- 선택 `referenceDate` parameter는 `YYYY-MM-DD` pattern의 string이며, generated client도
  `referenceDate?: string`으로 시간대 변환 없이 전달한다. 주간 응답은 기준일·주 시작일·주 종료일과
  실제 TimeSlot 목록을 required field로 제공한다.
- 주간 TimeSlot과 Reservation에는 기존 global `TimeSlotResponse`와 충돌하지 않는
  `AdminWeeklyOperationsTimeSlotResponse`, `AdminWeeklyOperationsReservationResponse` schema 이름을
  부여했다. 이로써 `endTime`, 정원, 마감 여부와 nested Reservation이 생성 모델에서 보존된다.
- RidingClass는 현재 전체 9개 catalog를 enum으로 고정했다.
- ReservationStatus는 runtime이 `databaseValue()`로 직렬화하는
  `pending_admin_approval`, `pending_payment`, `confirmed`, `completed`와 OpenAPI/generated client를
  일치시켰다. Java enum 이름이나 일반 `string`으로 계약을 약화하지 않았다.
- 두 endpoint 모두 기존 `/api/admin/**` bearer security 계약을 유지한다.

  노출한다.
- 월간 응답·공동 최고 회원, 주간 응답·TimeSlot·Reservation의 전용 TypeScript 모델 5개가
  생성됐다.
- generated output을 수동 편집하지 않았으며, `api:check` 재생성 diff 검증으로 결정성을 확인했다.

## 독립 검토

- Architecture 검토는 runtime JSON을 변경하지 않고 OpenAPI metadata와 고유 schema 이름으로
  계약을 표현하는 방식이 M32-09 생성 관례와 M33 제품 정책을 보존한다고 판단했다.
- ReservationStatus의 lowercase 외부 표현은 M33-02 API test와 실제 runtime serialization에 이미
  고정되어 있으므로 새로운 제품 결정이 필요하지 않았다.
- 최종 anti-fake-green review에서 runtime/OpenAPI/client 불일치, required/nullable 완화,
  generated output 수동 조작, M33-04 이후 범위 침범과 unrelated 변경 혼입을 확인했다. 날짜-only
  query의 UTC 변환 위험과 문서 표현을 보완한 뒤 CRITICAL/HIGH/MEDIUM/LOW finding은 모두 없다.
