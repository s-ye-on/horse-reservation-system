# M3-06: 쿠폰 만료 job

## 상태

`COMPLETED`

## 목표

M1-32에서 구현한 쿠폰 만료 자동 작업을 MVP-3의 운영 자동화 계약으로 채택하고 만료, 잔여 소멸, 점유 보존, 재실행 안전성을 회귀 검증한다.

## 담당

`backend`, `qa`, `docs`

## 선행 작업

- MVP-2 완료
- M1-32 완료

## 입력 문서

- [MVP-3 운영 효율화](../../product/mvp-3.md)
- [운영 정책](../../product/policies.md)
- [도메인 모델](../../architecture/domain-model.md)의 Coupon과 CouponUsageLog
- [M1-32 완료 Task](../completed/M1-32.md)

## 허용 범위

- `docs/tasks/active/M3-06.md`, `docs/tasks/completed/M3-06.md`
- `mise.toml`의 `verify:m3-06`
- 기존 쿠폰 만료 구현과 테스트의 결함이 발견된 경우 `backend/src/main/java/com/horse/coupons/**`, `backend/src/test/java/com/horse/coupons/**`

## 제외 범위

- 관리자 쿠폰 수동 만료·보정 API와 화면
- 쿠폰 선택 순서, 유효기간, 점유 정책 변경
- 예약 취소·변경과 회원 알림
- 외부 Scheduler와 별도 배치 서버
- 관련 없는 리팩터링과 라이브러리 교체

## 구현 판단

- M1-32가 M3-06의 완료 신호를 이미 충족하므로 별도 만료 모델이나 중복 job을 추가하지 않는다.
- `CouponExpiryScheduler`와 `CouponExpiryService`를 그대로 MVP-3 운영 자동화 구현으로 사용한다.
- M3-06 전용 검증은 도메인 경계, MySQL job 동시성·멱등성, 회원 쿠폰 조회에서 만료 상태 노출을 함께 고정한다.

## 완료 조건

- [x] `Asia/Seoul` 기준 만료일 다음 날에만 미점유 잔여 횟수가 소멸하고 상태가 `expired`가 된다.
- [x] 만료 전에 점유된 횟수는 만료 후에도 완료·차감할 수 있으며 반환해도 사용 가능 잔여분으로 복구되지 않는다.
- [x] job 재실행과 동시 실행은 상태 및 `expired` 이력을 중복 생성하지 않는다.
- [x] 회원 쿠폰 조회는 만료 상태와 소멸 후 잔여·점유 횟수를 일관되게 반환한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- `Coupon.expire(...)`가 만료일 당일은 보존하고 다음 날 미점유 잔여분만 소멸시키는 경계를 검증했다.
- 만료 전 점유분은 `remaining_count = held_count`로 보존되며 반환·사용 후 사용 가능분으로 되살아나지 않음을 검증했다.
- `FOR UPDATE` 대상 조회로 동시 실행을 직렬화하고 반복 실행 시 상태와 `expired` 로그가 한 번만 생성됨을 MySQL에서 검증했다.
- 기존 M1-32 구현이 M3-06 계약을 모두 충족하므로 중복 Scheduler나 별도 만료 모델을 추가하지 않았다.

## 중단 조건

- M1-32의 만료 정책과 현재 제품 SSOT가 충돌한다.
- 기존 점유 예약을 보존하면서 잔여분만 소멸할 수 없다.
- 멱등성을 위해 기존 쿠폰·이력 데이터를 손상하는 migration이 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
