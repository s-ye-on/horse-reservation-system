## 완료 증거

- TimeSlot PATCH의 `closed` 요청은 영속 필드를 직접 쓰지 않고
  `TimeSlotClosureService.start` 또는 `withdrawOrReopen` workflow를 선택한다는 계약으로
  단일화했다.
- OpenAPI, Request DTO, Controller와 Application Service의 실제 계약을 전용
  verifier에서 함께 검사해 문서만 통과하는 회귀를 막았다.
- PM·Architecture 독립 검토에서 발견한 `is_closed` 요청 명칭 드리프트와 검증 누락을
  보정한 뒤 HIGH 또는 MEDIUM finding 없이 `GO`를 받았다.

## 중단 조건

- 현재 Controller 또는 Application workflow가 문서화한 PATCH 위임 계약과 다르다.
- 문서 일관성을 위해 제품 정책이나 API 동작 변경이 필요하다.
- 관련 없는 dirty 파일 수정이 필요하다.
- HIGH 또는 MEDIUM 독립 검토 finding을 G01 범위에서 해결할 수 없다.
- 같은 원인의 검증 실패가 세 번 반복된다.
