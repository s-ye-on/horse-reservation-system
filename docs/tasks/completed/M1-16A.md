## 완료 조건

- [x] ADMIN만 예약 목록과 상세를 조회하고 MEMBER 요청 및 존재하지 않는 예약을 구분해 거부한다.
- [x] 목록과 상세에 회원·수업·상태·결제원·쿠폰·주요 상태 시각과 승인대기 경고 등 운영 판단 정보를 제공한다.
- [x] 경고는 `approval_requested_at`, 현재 시각, 수업 시작 시각으로 계산하며 조회가 상태·정원·쿠폰·감사 이력을 변경하지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 날짜 조건이 모두 없을 때만 `lessonDateFrom=오늘`을 적용하고, 날짜 경계가 하나라도 있으면 지정된 경계만 사용한다.
- `status`, 날짜 범위, `classType`, 회원 이름·전화번호 `keyword` 검색과 0 기반 페이지, 기본 20·최대 100 크기를 제공한다.
- 목록은 `lessonDate ASC`, `startTime ASC`, `reservationId ASC` 고정 순서로 조회한다.
- 목록과 상세에 관리자용 회원 전화번호, 수업·상태·결제원·쿠폰·주요 상태 시각·승인대기 경고를 반환한다.
- `@Transactional(readOnly = true)` 조회 전후 예약 버전, 쿠폰 수량, 쿠폰·예약 이력 건수가 동일함을 MySQL에서 검증한다.
- OpenAPI 계약과 TypeScript 공유 API 클라이언트를 재생성했다.

## 중단 조건

- 관리자 목록에 필요한 필터·정렬·페이지 계약을 구현 전에 제품 결정해야 한다.
- 승인대기 경고를 저장 상태로 만들거나 조회 중 예약 상태를 변경해야 한다.
- 회원 개인정보 노출 범위를 기존 관리자 권한 정책으로 결정할 수 없다.
- 목록 조회를 위해 command use case나 상태 전이 코드를 수정해야 한다.
- 허용 범위 밖의 스키마·프론트엔드 변경이 필요하다.
