- 예약 승인·반려·복구·변경·취소 실행
- 일괄 수업 완료
- 기존 관리자 예약 운영 화면 변경
- 차트 라이브러리와 전역 디자인 시스템 도입
- 백엔드 API와 생성 클라이언트 변경
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [x] 오늘을 기본으로 승인대기·입금대기·입금만료와 전체 예약 수를 구분해 표시한다.
- [x] 관리자는 시작일·종료일을 적용하고 세 운영 상태 중 하나를 선택해 동일 날짜 범위의 예약을 조회할 수 있다.
- [x] 승인대기 예약에는 정상·확인 필요·긴급 경고가 표시된다.
- [x] 집계와 목록의 로딩·오류·빈 상태를 구분해 제공한다.
- [x] `/admin/dashboard` 경로와 관리자 메뉴에서 접근할 수 있고 320px 화면에서 주요 기능을 사용할 수 있다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m3-03
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m3-03` 등록 확인 |
| `mise run verify:m3-03` | 0 | 대시보드 컴포넌트 테스트 6건, API 클라이언트 타입 빌드, 린트, 타입 검사 통과 |
| `mise run verify:changed` | 0 | 문서, 백엔드, OpenAPI, 웹 109건, 빌드, 모바일 전체 변경 검증 통과 |

## 완료 증거

- 집계 API가 반환한 실제 날짜 경계를 검색 API에 그대로 전달해 두 화면의 기간 불일치를 방지했다.
- 상태 카드에 명시적 접근성 이름과 선택 상태를 제공하고 승인대기 경고를 정상·확인 필요·긴급으로 표시했다.
- 집계와 목록 각각의 로딩·오류·빈 상태를 구분하고 320px에서도 기간과 상태 선택 기능을 유지했다.
- 생성 API 클라이언트 타입을 먼저 빌드하도록 Task 검증을 구성해 OpenAPI 변경 이후에도 타입 검사가 재현된다.

## 중단 조건

- 집계와 검색 API가 같은 날짜 범위를 표현할 수 없다.
- 화면 구현을 위해 예약 상태 또는 경고 정책을 새로 결정해야 한다.
- 기존 관리자 라우팅을 깨야 한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
