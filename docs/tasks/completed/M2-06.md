## 완료 조건

- [x] 취소 preview와 실행은 같은 정책 판정기를 사용하며 쿠폰 예약은 마감 전 `return`, 마감 후 회원 책임 `deduct`, 1회 결제는 `none`을 반환한다.
- [x] 회원은 본인의 활성 예약만 필수 사유와 함께 취소하고 Reservation을 `cancelled`로 전이한다.
- [x] 쿠폰 점유 반환·차감, 예약 상태, 취소 책임, 추가 전용 감사 이력이 하나의 트랜잭션으로 반영된다.
- [x] 승인대기 쿠폰 예약의 마감 후 차감과 동일 취소 재시도의 멱등성을 검증한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 회원 취소 preview와 실행이 `ReservationCancellationPolicy`를 공유한다.
- 회원 소유권, 활성 상태, 필수 사유와 500자 제한을 API 테스트로 검증했다.
- 쿠폰 반환·차감과 예약 취소·감사 로그를 하나의 트랜잭션에서 처리한다.
- 생성된 OpenAPI/TypeScript 계약에서 취소 사유가 필수 필드임을 확인했다.
- `backend/conventions/review.md` 체크리스트를 기준으로 Controller DTO 경계, Entity 상태 변경, 도메인 예외, 테스트 구성을 점검했다.

## 중단 조건

- 회원 취소가 즉시 `cancelled`가 아닌 관리자 승인대기 상태를 요구한다.
- 회원 취소 후 관리자가 이미 차감한 쿠폰을 복원해야 한다.
- 외부 결제 환불 연동이 취소 트랜잭션의 필수 조건이 된다.
- 기존 쿠폰 또는 예약 감사 이력을 수정·삭제해야 한다.
- 완료 조건을 자동 검증할 수 없다.
