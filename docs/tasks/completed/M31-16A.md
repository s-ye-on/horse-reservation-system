## 구현 증거

### 계정과 회원 경계

- `AuthAccount`가 정규화 이메일, Password hash, 역할, 상태와 안정적인 JWT subject를 소유한다.
- MEMBER 회원가입은 같은 트랜잭션에서 `Member`와 1:1 계정을 생성하고 두 레코드가 같은
  `authSubject`를 사용한다. ADMIN은 가짜 Member를 만들지 않는다.
- 기존 Member에는 자격 증명을 backfill하지 않았다. `/api/auth/me`는 연결된 로컬 계정만 조회한다.
- 비밀번호는 Spring Security `DelegatingPasswordEncoder`로 hash하고 원문을 저장·응답·로그하지 않는다.

### Token 수명주기

- Access Token은 기존 HS256, `roles` claim과 subject 변환을 유지하며 기본 수명은 15분이다.
- Refresh Token은 256-bit 난수로 발급하고 DB에는 SHA-256 hash만 저장한다. 기본 수명은 30일이다.
- refresh는 hash 행을 비관적 잠금으로 획득해 기존 세션을 `ROTATED`로 바꾸고 후속 세션을 만든다.
  동일 Token의 동시 회전은 한 건만 성공하고 이전 Token 재사용은 401로 거부한다.
- logout은 활성 세션을 `REVOKED`로 바꾸며 이미 회전·폐기된 알려진 Token의 반복 요청은 멱등 성공한다.

### API 계약

- `POST /api/auth/signup`: MEMBER 계정과 Member 생성
- `POST /api/auth/login`: Access/Refresh Token 발급
- `POST /api/auth/refresh`: Refresh Token 회전과 새 Token 발급
- `POST /api/auth/logout`: Refresh Session 폐기
- `GET /api/auth/me`: Bearer 인증 계정 조회
- OpenAPI와 생성 TypeScript Client에 요청·응답, 공통 오류와 `/me` bearer 인증 계약을 반영했다.

### Migration과 Bootstrap

- V35가 `auth_accounts`와 `refresh_token_sessions`를 생성한다. 이메일, subject, Member 1:1,
  최초 관리자 guard, Refresh hash 및 parent 관계를 UNIQUE/FK/CHECK로 보호한다.
- Refresh 조회 인덱스는 계정·상태·만료, family, 만료 순서로 명시했다.
- `bootstrap-admin` 프로필에서만 외부 `BOOTSTRAP_ADMIN_EMAIL`과
  `BOOTSTRAP_ADMIN_PASSWORD`를 읽는다. 동시 실행은 고정 DB guard로 한 관리자만 생성한다.
- 최초 관리자 확인 후 해당 프로필과 두 환경 변수를 제거하는 운영 절차를 README에 기록했다.
  실제 이메일, 비밀번호 또는 JWT Secret은 저장소에 추가하지 않았다.

## 독립 검토

- Architecture: 계정·Member 경계, 안정 subject와 기존 Member 연결 경계 보정 후 HIGH·MEDIUM 없음.
- Backend/Security: `/me` bearer OpenAPI, Refresh 회전·로그아웃, Secret·자격 증명 비노출 보정 후
  HIGH·MEDIUM 없음.
- DB: V35 CHECK·UNIQUE·FK와 모든 인덱스 순서 및 parent 관계 계약 테스트 보강 후 HIGH·MEDIUM 없음.
- QA: malformed Bootstrap startup과 신규 테스트 종료 후 데이터 격리를 보강했으며 HIGH·MEDIUM 없음.

## 남은 위험

- 로그인 rate limit과 자동 계정 잠금, 비밀번호 재설정은 후속 보안 작업이다.
- 회전된 Refresh Token 재사용은 거부하지만 token family 전체 자동 폐기는 아직 구현하지 않았다.
- 웹 Token 저장과 Cookie 채택 여부, Cookie 사용 시 CSRF 정책은 후속 UI·보안 결정이다.
- 기존 Member의 계정 연결·초대는 구현하지 않았다. 연결 전 Member는 기존 subject 기반 API만 사용한다.
- 추가 관리자 생성·복구·역할 변경은 후속 운영 기능이다.
- 기본 profile의 개발 JWT fallback은 M31-15 계약대로 비운영 용도로 남아 있으므로 운영은 반드시
  `prod` profile과 외부 `JWT_SECRET`을 사용해야 한다.
- 비밀번호는 문자 수 DTO 검증 후 UTF-8 72-byte 도메인 제한을 추가 적용하므로 다중 바이트 입력은
  DTO 최대 문자 수보다 먼저 도메인 오류가 발생할 수 있다.
