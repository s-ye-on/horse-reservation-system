## 완료 조건

- [x] ADMIN만 `pending_admin_approval` 또는 만료 전 `pending_payment` 예약을 `confirmed`로 전이한다.
- [x] 쿠폰 예약은 임시 점유를 확정 점유로 바꾸고 1회 결제 예약은 쿠폰 부수 효과 없이 확정한다.
- [x] 중복 확정 요청은 상태·쿠폰·감사 이력을 두 번 반영하지 않으며 허용되지 않은 상태는 거부한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 예약 행을 `PESSIMISTIC_WRITE`로 잠근 뒤 Entity의 상태 전이 메서드로 확정해 동시 요청을 직렬화했다.
- 입금대기 예약은 결제 기한보다 이른 시각에만 확정되며, 기한과 같은 시각부터 `409 Conflict`로 거부한다.
- 쿠폰 예약 확정 시 기존 임시 점유 수는 유지하고 ADMIN 행위자의 `CONFIRMED` 감사 로그를 한 번만 기록한다.
- 동시 중복 확정 요청이 모두 멱등 응답을 반환하면서 상태 버전과 쿠폰 감사 로그를 중복 반영하지 않음을 MySQL 통합 테스트로 확인했다.
- `backend/conventions/review.md` 기준 Controller/DTO 경계, Entity 상태 변경, 예외 계층, 테스트 범위를 자기 점검했다.

## 중단 조건

- 입금 확인의 의미가 외부 결제 연동 없이는 결정되지 않아 `pending_payment` 확정을 정의할 수 없다.
- 쿠폰 점유 전환과 예약 상태 전이가 서로 다른 트랜잭션에서만 가능하다.
- 만료 시각과 확정 요청의 경쟁을 상태 조건이나 잠금으로 재현·검증할 수 없다.
- ADMIN 행위자 또는 확정 시각을 감사 가능하게 기록할 수 없다.
- 허용 범위 밖의 스키마·보안 설정 변경이 필요하다.
