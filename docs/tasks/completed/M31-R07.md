## Completion Evidence

### 구현

- `ReservationBookingTimePolicy`가 서울 시각의 `lessonStartAt - 3시간`을 공용 마감으로
  계산한다. 정확한 마감 시각까지 허용하고 이후에는
  `RESERVATION_BOOKING_DEADLINE_PASSED`, 정확한 수업 시작 시각부터는
  `RESERVATION_LESSON_ALREADY_STARTED`를 반환한다.
- 회원 시간대 조회와 예약 Command가 같은 정책을 사용한다. Command는 Coupon 조회,
  Reservation 생성과 Coupon 점유 전에 경계를 검증한다.
- 순수 도메인 테스트는 1나노초 경계를, API 테스트는 MySQL `DATETIME(6)` 정밀도에
  맞춘 1마이크로초 경계를 검증한다.
- 정확한 경계에서 쿠폰 예약과 1회 결제 예약이 모두 성공하고, 경계 이후 실패에서는
  Reservation과 Coupon heldCount가 변경되지 않는다.

### 독립 검토

- PM: 제품 정책과 구현의 불일치는 없었다. 검토 중 별도 Gradle 실행이 공유
  `backend/build`와 경합해 `verify:changed` 실패를 보고했으나, 모든 검토 작업 종료 후
  네 Gate를 직렬 재실행하여 종료 코드 0을 확인했다.
- Architecture: 공용 경계 SSOT, 주입 Clock, 예외 매핑, R08·R09 제외 범위를
  충족해 `GO`로 판정했다. 쿠폰 경계 성공 증거가 간접적이라는 LOW 의견은 고정 Clock의
  직접 API 테스트를 추가해 해소했다.
- DB: 경계 검증이 모든 쓰기보다 앞서고 실패 경로에 점유가 남지 않으며 migration이
  필요하지 않음을 확인해 `GO`로 판정했다.

### 자기 점검

- Controller, DTO, OpenAPI, 웹과 Expo를 변경하지 않았다.
- R08의 member-day guard와 interval overlap을 조기 구현하지 않았다.
- 신규 업무 예외는 `ReservationException`과 `RESERVATION_*` 체계를 유지한다.
- 기존 V1~V27 migration과 관련 없는 dirty 파일을 수정하지 않았다.

## 남은 위험과 후속 소유

- 현재 예약 생성의 기존 잠금 순서 부채는 R07에서 확대하지 않았으며, member-day guard,
  canonical lock order와 interval overlap은 M31-R08이 소유한다.
- 데모 프록시는 OpenAPI 생성 포트 8080과 충돌하므로 전체 검증 동안 중지했다. M31-R10
  완료 후 로컬 데모를 복구한다.

## 중단 조건

- 신규 예약과 예약 변경 마감 정책을 분리할 수 없다.
- 조회와 Command가 하나의 경계 정책을 공유할 수 없다.
- R08 소유의 guard·overlap 또는 migration이 필요하다.
- 관리자 수동 예약이나 공개 API 계약을 조기 변경해야 한다.
- 관련 없는 dirty 파일 또는 기존 V1~V27 migration 수정이 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
