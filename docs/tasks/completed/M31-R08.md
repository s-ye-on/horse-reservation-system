## Completion Evidence

### 구현

- 회원 예약은 `ScheduleConfigGuard` 공유 잠금, `ScheduleDate`, member-day guard,
  `TimeSlot`, 겹치는 `Reservation`, 정원 점유 `Reservation`, `Coupon` 순서로 잠근다.
  member-day guard upsert와 `FOR UPDATE`는 예약 생성과 같은 트랜잭션 안에서 실행된다.
- `ReservationRepository`가 같은 회원·날짜의 활성 예약을 반개방 구간 조건으로 조회하고
  시작 시각과 ID 순으로 잠근다. 겹침이 확인되면 정원 행이나 Coupon을 잠그기 전에
  `RESERVATION_OVERLAPPING_ACTIVE_RESERVATION` 409로 중단한다.
- V15 exact-start UNIQUE 위반은 확인된 제약 이름에 한해서만 같은 도메인 오류로
  변환한다. 원인을 확정할 수 없는 DB 예외는 일반 겹침 오류로 오인하지 않는다.
- V28은 overlap 조회용 복합 인덱스를 추가하고, V29는 기존 데이터에 활성 overlap이
  있으면 배포 migration을 중단한다. V27에서 V29까지의 정상·충돌 업그레이드를 실제
  MySQL로 검증했다.

### 검증과 보정

- MySQL `EXPLAIN ANALYZE`와 JSON 계획에서
  `idx_reservations_member_date_active_interval`의 선택 및 range access를 확인했다.
- 같은 회원의 겹치는 서로 다른 TimeSlot 동시 요청은 하나만 성공하며, 실패 요청에는
  Reservation, Coupon heldCount와 정원 점유가 남지 않는다. 다른 날짜의 요청은
  member-day guard에서 불필요하게 직렬화되지 않는다.
- 첫 `verify:changed` 재실행에서 로컬 DB에 이미 적용된 V28을 수정해 발생한 Flyway
  checksum 오류를 확인했다. Flyway repair 없이 V28을 적용 당시 내용으로 복원하고
  사전 검증을 V29로 분리한 뒤 모든 Gate를 다시 통과했다.

### 독립 검토

- PM: V15 exact-start 경쟁 경로의 도메인 오류 통합 누락을 지적했다. 제약 이름을
  한정한 translator와 실제 DB 통합 테스트를 추가한 뒤 `GO`로 재판정했다.
- Architecture: overlap 행보다 정원 행을 먼저 잠그던 순서와 ADR의 fallback 설명
  불일치를 지적했다. overlap 우선 잠금·즉시 중단 순서와 문서·테스트를 보정한 뒤
  `GO`로 재판정했다.
- DB: 기존 V27 데이터의 활성 overlap preflight 누락을 지적했다. V29 검증 migration과
  실패 업그레이드 테스트를 추가한 뒤 `GO`로 재판정했다.

### 자기 점검

- Controller, DTO, OpenAPI, 웹과 Expo 계약을 변경하지 않았다.
- 관리자 수동 예약, 예약 변경·복구·취소·만료와 R09·R10 상태 전이를 조기 변경하지
  않았다.
- V1~V27 migration과 관련 없는 dirty 파일을 수정하지 않았다.

## 남은 위험과 후속 소유

- 관리자 수동 예약과 활성 집합 재진입 Command의 member-day guard 및 overlap 연결은
  후속 Task가 소유한다.
- R09 날짜 CLOSING/CLOSED와 R10 개별 TimeSlot 휴강은 신규 유입 차단 및 안정적인
  예약 이탈 경로를 별도로 완성해야 한다.

## 중단 조건

- 현재 V15 데이터에 이관 불가능한 활성 overlap이 발견된다.
- 회원 신규 예약 외 Command를 함께 변경해야만 불변식을 보장할 수 있다.
- canonical lock order와 기존 Coupon·정원 정책을 함께 만족할 수 없다.
- V1~V27 migration 수정이나 데이터 삭제·병합이 필요하다.
- Controller·OpenAPI·웹 계약을 조기 변경해야 한다.
- 관련 없는 dirty 파일 수정 또는 기존 검증 완화가 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
