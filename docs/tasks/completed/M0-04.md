## 제외 범위

- 회원 가입, 로그인, 로그아웃, 비밀번호 저장
- JWT 발급, 갱신, 폐기와 클라이언트 저장 방식
- OAuth 및 서버 세션 인증
- 회원 또는 관리자 UI와 실제 도메인 API
- DB 스키마와 기존 Flyway migration
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [x] `MEMBER`, `ADMIN` 역할이 코드에 명시적으로 정의된다.
- [x] JWT의 `roles` claim이 Spring Security 역할 권한으로 변환된다.
- [x] `/actuator/health`는 공개하고 `/api/admin/**`는 `ADMIN`, 그 외 `/api/**`는 인증 사용자에게만 허용한다.
- [x] 접근 허용과 거부를 자동 테스트로 검증하고 모든 검증 명령이 성공한다.

## 검증 명령

명령은 위에서 아래 순서로 실행한다.

```bash
mise tasks --all
mise run verify:m0-04
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise tasks --all` | 0 | `verify:m0-04` 존재 확인 |
| `mise run verify:m0-04` | 0 | 보안 경계 테스트 5개 통과 |
| `mise run verify:changed` | 0 | 백엔드 check·통합 테스트와 문서 검사 통과 |

## 중단 조건

다음 중 하나라도 해당하면 구현을 멈추고 상태를 `BLOCKED`로 변경한다.

- 입력 문서끼리 회원과 관리자 권한 정책이 충돌한다.
- JWT 서명 알고리즘이나 역할 claim 계약이 입력 문서와 충돌한다.
- 허용 범위 밖의 운영 코드 또는 설정을 수정해야 한다.
- 테스트용 endpoint가 운영 코드에 노출되어야만 검증할 수 있다.
- 필수 검증 명령이 없거나 반복 실행 결과가 불안정하다.
- 완료 조건을 자동 검증할 방법을 정의할 수 없다.
