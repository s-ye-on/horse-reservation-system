# M31-12: RFC3339 시간 계약과 OpenAPI 필수 필드

## 상태

`COMPLETED`

## 목표

외부 API의 시간 의미를 RFC3339, 날짜, 지역 시각으로 구분하고 OpenAPI의
required·nullable 계약과 생성 TypeScript Client를 실제 Java DTO에 맞춘다.

## 담당

`backend`, `frontend`

## 선행 작업

- M31-09 완료
- M31-11 완료

## 입력 문서

- [MVP 3.1 Backlog](../mvp-3.1.md)의 `M31-12`
- 현재 OpenAPI와 생성 TypeScript Client
- M31-10 공통 오류 계약
- M31-11 Page 계약

## 완료 조건

- [x] 절대 시점은 offset을 포함한 RFC3339 `date-time`으로 반환한다.
- [x] 날짜 전용 값과 한국 운영 시각은 기존 `date`와 지역 `time` 의미를 유지한다.
- [x] offset 없는 timestamp 입력은 공통 400 오류 응답으로 거부한다.
- [x] Response, Page, ErrorResponse 필수 필드가 OpenAPI required와 일치한다.
- [x] nullable 응답 필드는 생략 가능 필드가 아니라 명시적인 nullable로 생성된다.
- [x] 생성 TypeScript Client가 required와 `T | null` 계약을 반영한다.
- [x] 웹과 모바일 소비자가 변경된 생성 타입으로 컴파일된다.
- [x] Backend와 Frontend 독립 검토에 HIGH 또는 MEDIUM finding이 남지 않는다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- DB와 Application의 `LocalDateTime` 절대 시점은 `Asia/Seoul` 기준
  `OffsetDateTime`으로 변환하여 `+09:00`이 포함된 RFC3339 문자열로 노출한다.
- `Z`, 양수 offset, 음수 offset 입력은 같은 절대 시점으로 역직렬화되며 offset 없는
  timestamp 입력은 허용하지 않는다.
- 수업일과 휴일·만료일은 `YYYY-MM-DD` 날짜 의미를 유지하고, 수업 및 Template의
  시작·종료 시각은 한국 현지 벽시계 `time` 의미를 유지한다.
- OpenAPI 생성 단계에서 모든 `*Response`와 `FieldError`의 실제 프로퍼티를
  required로 선언한다. nullable 참조는 OpenAPI 3.1 `oneOf(ref, null)`로 표현한다.
- Page 응답 6필드와 ErrorResponse 7필드의 required 계약을 회귀 테스트로 고정했다.
- 생성 TypeScript 모델은 필수 응답 필드의 불필요한 `?`를 제거하고 nullable 필드를
  `T | null`로 생성한다. 생성 결과를 수동 편집하지 않았다.
- 웹 테스트 fixture는 실제 required·nullable 계약에 맞게 최소 보정했다. API
  어댑터와 화면 내부 타입은 null 호환에 필요한 경계만 수정했다.
- 관리자 쿠폰 검색 UI와 CSS의 기존 사용자 변경은 수정하거나 커밋하지 않았다.
  해당 테스트 파일에서는 M31-12 fixture 필드만 별도 stage한다.
- 기존 Backend API 회귀 테스트의 timestamp 기대값도 `+09:00` 계약으로 보정했고,
  전체 Backend 575개 테스트가 통과했다.

## 독립 검토

- Backend: HIGH/MEDIUM finding 없음, `GO`.
- Frontend: 기존 관리자 쿠폰 UI 변경을 M31-12 범위에서 제외한 재검토 결과
  HIGH/MEDIUM finding 없음, `GO`.
- LOW: nullable 응답 키 포함 여부를 실제 엔드포인트 JSON에서 전수 검증하지 않는다.
- LOW: 실제 Controller 입력에서 `Z`, 양수·음수 offset 수용을 모두 반복 검증하지 않는다.
- LOW: 생성 Client의 날짜 전용 outbound 직렬화 경계는 별도 회귀 테스트가 없다.

## 남은 위험

- 전역 Jackson null 제외 정책이 나중에 도입되면 required nullable 필드와 실제 JSON이
  어긋날 수 있으므로 엔드포인트 응답 회귀 테스트를 함께 보강해야 한다.
- OffsetDateTime의 세 offset 입력은 ObjectMapper 계약으로 검증했으며 실제 API별
  입력 허용 테스트는 대표적인 offset 없는 400 경로에 집중되어 있다.
- 날짜 전용 generated Client 직렬화는 UTC 기반 `Date` 구현을 사용한다. 웹 표시 계약은
  Asia/Seoul로 검증했지만 다른 방식으로 생성한 `Date`의 outbound 경계는 후속 보강 대상이다.
