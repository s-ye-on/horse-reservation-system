## 완료 조건

- [x] 모든 일정 관리 API는 `ROLE_ADMIN`만 호출할 수 있고 Controller는 DTO와 Application
  Service만 사용한다.
- [x] Template·정기 휴일 mutation은 expected config version과 영향 미리보기를 제공한다.
- [x] 동기화 상태는 active/pending version, 전체·적용·남은 날짜, 진행률과 비식별 실패
  정보를 반환하고 stale retry를 차단한다.
- [x] SYNCING 중 차단 진입점은 같은 `SCHEDULE_CONFIG_SYNC_IN_PROGRESS` 503 계약을
  사용하고 허용 조회·종료 Command는 정상 동작한다.
- [x] 날짜 휴무와 TimeSlot 휴강 API가 기존 고정 영향 목록, 전용 취소, 완료·철회·재개
  불변식을 우회하지 않는다.
- [x] 날짜 휴무 응답은 CLOSING 시작 감사 이력의 최초 건수와 현재 잔여 건수로
  resolved·progress를 안정적으로 복원한다.
- [x] `ErrorResponse.details`가 기존 필드와 함께 직렬화되고 구조화된 409 후속 정보를
  제공한다.
- [x] 외부 실제 시각은 `+09:00` offset을 포함하며 enum, nullable, optional 계약이
  실제 JSON과 일치한다.
- [x] OpenAPI와 생성 Client에 drift가 없고 웹·Expo가 생성 Client와 함께 typecheck된다.
- [x] 필수 검증과 독립 검토가 통과하고 Completion Evidence가 기록된다.

## Completion Evidence

### 구현

- 정규 Template과 정기 휴일의 조회·미리보기·생성·변경·활성 상태 API를 공개하고
  설정 version, 영향 건수와 동기화 상태를 응답한다.
- 동기화 상태·진행률과 현재 pending version 수동 재시도 API를 공개한다. 완료됐거나
  오래된 version 재시도는 `SCHEDULE_SYNC_RETRY_NOT_ALLOWED` 409로 거부한다.
- 날짜 CLOSING/CLOSED와 개별 TimeSlot 휴강의 영향 조회, 전용 취소, 완료·철회·재개
  API를 기존 R09/R10 Application workflow에 연결했다.
- 날짜 CLOSING 시작 당시 활성 예약 수를 append-only 일정 감사 metadata에 저장하고
  현재 잔여 예약과 조합해 해결 건수와 진행률을 복원한다.
- 날짜와 TimeSlot mutation은 상위 Application Service 트랜잭션 안에서 command 결과와
  후속 read model을 조립해 경쟁 중 혼합 스냅샷을 반환하지 않는다.
- `ErrorResponse.details`는 항상 존재하는 free-form JSON map이며, request/response의
  required·nullable·offset 계약을 OpenAPI와 생성 Client에 반영했다.

### 검증과 보정

- 최초 전체 게이트에서 기존 R06 동시 재시도 테스트가 MySQL lock acquisition으로 한 번
  실패했으나 단건 재실행과 R11 전체 재실행에서 성공했다.
- 수동 동기화 성공 API 테스트가 테스트 외부 트랜잭션으로 guard 행을 잠근 채 내부
  동기화를 실행해 전체 테스트에서 lock timeout을 만들었다. 해당 테스트만
  `NOT_SUPPORTED`로 분리하고 fixture를 명시적으로 초기화해 운영 트랜잭션과 동일한
  경계를 검증했다.
- API 테스트는 current pending version 성공, stale retry, config/date/closure version
  충돌, SYNCING 중 허용되는 휴강 정리, 쿠폰 `RETURN`과 1회 결제 `NONE`, 날짜·TimeSlot
  진행률과 `+09:00` 시각을 검증한다.
- OpenAPI 계약 테스트는 `ErrorResponse.details` free-form, 필수 optimistic version,
  필수 응답 필드, 문자열 최소 길이와 오류 응답 schema reference를 검증한다.

### 독립 검토

- PM: 날짜 휴무 진행률의 재진입 계약과 R11 범위 표현을 지적했다. 최초 건수를 감사
  metadata에 보존하고 `OPEN/normalize`를 후속 상태 전이로 명시한 뒤 `GO`.
- Architecture: optimistic version, free-form error details와 문서 optional drift를
  지적했다. 요청·Client·문서를 일치시키고 legacy PATCH를 best-effort 호환 경로로
  한정한 뒤 `GO`.
- Backend: mutation 후 별도 조회의 혼합 스냅샷과 required 계약 누락을 지적했다.
  상위 트랜잭션 facade, start/action DTO 분리와 stale-version 테스트 보정 후 `GO`.
- Frontend: 생성 Client의 optional 남용과 진행률 계약을 지적했다. OpenAPI required,
  free-form details, 날짜 진행률과 Client 재생성 후 `GO`.

### 범위와 후속

- 독립적인 날짜 `NORMAL → OPEN`과 날짜 예외 해제는 내부 workflow가 없으므로 R11에서
  임의 구현하지 않았다. R12/R13 화면 범위에서도 제외하고 제품 전이 규칙 확정 후
  별도 Task로 처리한다.
- 기존 `PATCH /api/admin/timeslots/{id}`는 요청 version이 없는 호환용 best-effort
  workflow다. R12/R13과 Expo는 필수 `expectedVersion`을 받는 신규 closure API를
  사용한다.
- 연락 상태·메모·담당자, 알림, 자동 일괄 취소와 신규 migration은 추가하지 않았다.
