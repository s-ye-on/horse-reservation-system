## 완료 조건

- [x] MEMBER는 본인 예약만, ADMIN은 필수 메모와 함께 `pending_admin_approval`, `pending_payment`, `confirmed` 예약을 마감 전에 변경한다.
- [x] 원본·대상 시간대를 결정적 순서로 잠그고 대상 정원을 검증한 뒤 같은 Reservation의 날짜·시간만 변경하며 상태·쿠폰·신청 시각·입금 마감은 유지한다.
- [x] 변경은 3개월 예약 범위와 쿠폰 만료일을 준수하고 동일 대상 재시도는 정원·감사 이력을 중복 처리하지 않는다.
- [x] 변경 전후 시간대, 행위자, 사유를 추가 전용 감사 이력으로 저장하고 동시성·권한·경계 테스트가 성공한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- MEMBER 소유권과 ADMIN 필수 메모를 검증하는 변경 API를 추가했다.
- 원본·대상 TimeSlot을 ID 오름차순으로 비관적 잠금하고 대상 활성 점유를 계산한 뒤 동일 Reservation의 일정만 변경한다.
- 상태, 쿠폰, 신청 시각, 입금 마감은 유지하며 변경 전후 일정과 행위자를 `SCHEDULE_CHANGED` 감사 로그에 추가한다.
- 동일 대상 재시도, 정원 충돌, 쿠폰 만료, 동시 변경 경쟁을 회귀 테스트로 고정했다.
- `backend/conventions/review.md` 체크리스트를 확인했으며 Controller DTO 경계, Entity 상태 변경, BusinessException 계층, 테스트 명명 규칙을 충족한다.

## 중단 조건

- 변경을 새 Reservation 생성으로 표현해야 한다는 요구가 추가된다.
- 변경 시 기존 신청 시각·입금 마감을 다시 시작해야 한다.
- 대상 정원 확보와 예약 시간 변경을 같은 트랜잭션에서 처리할 수 없다.
- 기존 Flyway migration 수정이나 예약·감사 이력 삭제가 필요하다.
- 완료 조건을 자동 검증할 수 없다.
