## 완료 증거

- 날짜 휴무와 개별 TimeSlot 휴강 tab을 각각 고유 panel과 연결하고 선택 tab만
  순차 focus 대상이 되는 roving tabindex를 적용했다.
- ArrowLeft·ArrowRight 순환과 Home·End 이동은 선택 상태, 실제 focus와 조건부
  렌더링 panel을 한 동작으로 갱신한다.
- panel 내부에 이미 focus 가능한 입력이 있으므로 panel 자체를 추가 탭 정지점으로
  만들지 않았다.
- 단위 테스트는 모든 키 경로의 focus, `aria-selected`, `tabIndex`와 panel 연결을
  검증한다. Chromium E2E는 320px에서 End·Home·양방향 화살표, dialog Escape 후 trigger
  focus 복귀와 가로 overflow 부재를 검증한다.
- Frontend·QA 독립 검토의 panel 추가 탭 정지점과 역방향·끝점 assertion finding을
  보정한 뒤 HIGH 또는 MEDIUM finding 없이 `GO`를 받았다.

## 중단 조건

- 접근성 보정을 위해 API 또는 제품 동작 변경이 필요하다.
- 기존 dialog focus trap 또는 반응형 동작을 깨뜨려야 한다.
- 320px 실제 Chromium 검증을 자동화할 수 없다.
- 관련 없는 dirty 파일 수정이 필요하다.
- HIGH 또는 MEDIUM 독립 검토 finding을 G03 범위에서 해결할 수 없다.
- 같은 원인의 검증 실패가 세 번 반복된다.
