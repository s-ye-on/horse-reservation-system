# M3-00: Spring MVC 오류 응답 통합

## 상태

`COMPLETED`

## 목표

업무 예외와 Spring MVC Validation·바인딩 예외를 하나의 `ErrorResponse` 계약으로 반환한다.

`backend`, `docs`

## 제외 범위

- Spring Security 필터의 인증·인가 실패 응답 변경
- 예상하지 못한 서버 예외의 공개 메시지·로깅 정책 변경
- Controller나 업무 예외 계층의 패키지 이동
- 구보초보·구보 클래스 및 회원별 예약 가능 클래스 승인 모델
- 관련 없는 리팩터링, 라이브러리 교체, API 성공 응답 변경

## 완료 조건

- [x] 업무 예외가 `code`, `message`, `status`, `timestamp`, `path`, 빈 `fieldErrors`를 반환한다.
- [x] `MethodArgumentNotValidException`과 `BindException`이 동일한 구조와 `COMMON_INVALID_REQUEST` 코드를 반환한다.
- [x] 필드 오류에는 필드명과 검증 메시지만 포함하고 거부된 값은 노출하지 않는다.
- [x] 기존 `code`와 `message` 계약 테스트가 유지된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise tasks --all
mise run verify:m3-00
mise run backend:convention
mise run verify:changed
```

## 완료 증거

- 업무 예외의 기존 `code`, `message`를 유지하면서 공통 메타데이터와 빈 필드 오류 목록을 추가했다.
- `@Valid` 요청 본문과 `BindException`을 동일한 `COMMON_INVALID_REQUEST` 응답으로 변환했다.
- 필드 오류 응답에서 거부된 입력값을 제외하는 회귀 테스트를 추가했다.
- 향후 클래스·회원별 승인 모델은 ADR-009로 기록하고 MVP-3 이후로 분리했다.

## 중단 조건

- 기존 소비자가 오류 응답의 추가 필드를 거부하는 계약이 발견된다.
- 요구사항을 만족하려면 Spring Security 인증·인가 경계를 함께 변경해야 한다.
- Validation 오류 메시지나 필드 공개 범위에 개인정보 노출 가능성이 발견된다.
- 기존 업무 예외의 `code` 또는 `message`를 변경해야 한다.
- 같은 원인의 검증 실패가 세 번 반복된다.
