## 중단 조건

- M1-10 예약 스키마가 완료되지 않았거나 Reservation 영속성 모델로 활성 상태를 구분할 수 없다.
- 원형 클래스 집합이 기존 `RidingClass` 정의에서 식별되지 않거나 제품 문서와 충돌한다.
- 모든 점유 진입 경로에서 TimeSlot 우선 잠금 순서를 유지하려면 기존 모듈 의존 방향 또는 transaction convention을 바꿔야 한다.
- 동시성 검증을 실제 MySQL이 아닌 단위 테스트로만 대체해야 한다.
- 별도 점유 원장·카운터를 도입해야만 완료 조건을 만족할 수 있다.

## Completion Evidence

- `ReservationCapacityService`가 TimeSlot 행을 먼저 비관적 잠금하고 활성 Reservation 행을 잠금 조회한 뒤 같은 트랜잭션에서 예약을 생성한다.
- Reservation 상태 enum은 `pending_admin_approval`, `pending_payment`, `confirmed`만 점유 상태로 제공한다.
- `TimeSlotCapacity`가 마감, 전체, 원형, 클래스별 정원 불변식을 검증하며 별도 점유 원장이나 점유 카운터는 만들지 않았다.
- 네 개 병렬 요청에서 정원 2개만 성공하고 비점유 상태 전환 후 다시 예약 가능한 것을 실제 MySQL로 검증했다.
