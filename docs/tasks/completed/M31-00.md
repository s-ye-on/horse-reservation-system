## 제외 범위

- 백엔드, DB migration, OpenAPI와 프론트엔드 구현
- ADR-014 이후의 상세 구현 결정 문서
- 가족, 클래스, 모바일 기능 구현
- 관련 없는 기존 변경과 하네스 검증 완화

## 완료 조건

- [x] 신규 예약은 당일 수업 시작 전까지 허용하고 변경 마감은 전날 21:00으로 구분한다.
- [x] 잠금 matrix, deadlock 재시도, 원자적 멱등성, 가족 NULL 정렬과 서울 표시 계약이 계획에 있다.
- [x] Phase A/B Task가 세 Checkpoint, 완료 신호, 제외 범위와 verify 명령으로 분해된다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

```bash
mise run harness:loop-ready
mise run verify:m31-00
mise run verify:changed
```

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `mise run harness:loop-ready` | 0 | active Task와 `verify:m31-00` 연결 확인 |
| `mise run verify:m31-00` | 0 | 문서 링크·용어, M31 18개와 M32 11개 Task 및 핵심 정책 계약 통과 |
| `mise run verify:changed` | 0 | `verify:all`로 backend, MySQL, OpenAPI, web 128개 테스트·빌드, mobile 검증 통과 |

## Completion Evidence

- 회원 신규 예약은 당일 수업 시작 전까지, 기존 예약 변경은 전날 21:00 기준으로 분리했다.
- 관리자 수동 예약, 활성 중복, 원자적 멱등성, canonical lock order와 제한적 1213 재시도 계약을 고정했다.
- Page, RFC3339, 과거 TimeSlot, 이관 preflight와 후속 ADR 경계를 문서화했다.
- Phase A를 세 Checkpoint 18개 Task, Phase B를 11개 Task로 분해하고 모바일 선행 Gate를 갱신했다.
- `review.md` 기준 백엔드 구현 항목은 적용 대상이 아니며 하네스 완화와 실패 테스트 삭제가 없음을 확인했다.

## 중단 조건

- 신규 예약과 예약 변경의 시간 정책이 다시 충돌한다.
- Checkpoint 의존성상 완료되지 않은 API를 다음 구간이 사용해야 한다.
- 검증 명령이 확정 정책의 필수 문장을 자동 확인할 수 없다.
- 문서 범위를 넘어 구현 코드 변경이 필요하다.
