## 제외 범위

- 예약 변경 이력과 쿠폰 사용 이력을 하나의 쓰기 원장이나 하나의 CSV로 통합
- 감사 행 수정·삭제와 누락 이력 추론·backfill
- 전화번호, JWT 인증 주체, 쿠폰 등록 관리자 등 불필요한 개인정보·내부 식별자 출력
- XLSX, PDF, 매출 통계와 관리자 다운로드 화면
- 비동기 export job, 외부 파일 저장소와 대용량 스트리밍 고도화
- 관련 없는 상태 전이·쿠폰 정책·인덱스 변경

## 완료 조건

- [x] `GET /api/admin/audit-logs/export`가 화면과 같은 필터·정렬의 예약 감사 CSV를 반환한다.
- [x] `GET /api/admin/coupon-usage-logs/export`가 회원·쿠폰·예약·기간으로 필터한 쿠폰 사용 CSV를 반환한다.
- [x] 두 파일은 UTF-8 BOM, CRLF, 안전한 CSV quoting과 수식 주입 방어를 적용한다.
- [x] 다운로드 응답은 `text/csv`, attachment 파일명, `Cache-Control: no-store`를 제공한다.
- [x] CSV에는 회원 이름과 운영 이력은 포함하지만 전화번호와 `actorAuthSubject`는 포함하지 않는다.
- [x] 관리자만 다운로드할 수 있고 조회 전후 예약·쿠폰·감사 데이터는 변경되지 않는다.
- [x] 빈 결과도 헤더만 포함한 정상 CSV로 반환한다.
- [x] 검증 명령이 모두 종료 코드 0으로 성공한다.

## Completion Evidence

- 예약 변경 감사 이력과 쿠폰 사용 이력을 서로 다른 CSV로 내보내 각 원장을 SSOT로 유지했다.
- UTF-8 BOM, CRLF, 전체 필드 quoting 및 스프레드시트 수식 주입 방어를 공통 인코더로 고정했다.
- 전화번호는 검색 조건으로만 사용하고 파일에서는 제외했으며 JWT 인증 주체도 출력하지 않는다.
- 쿠폰 사용 이력 엔티티와 저장소를 append-only 계약으로 강화했다.
- 동기 전체 다운로드의 대용량 스트리밍 고도화는 제외 범위로 유지한다.

## 중단 조건

- 다운로드를 위해 두 원장을 통합하거나 기존 이력을 수정해야 한다.
- 파일에 전화번호나 내부 인증 주체를 포함해야만 요구사항을 충족할 수 있다.
- 동기 CSV 범위를 넘어 비동기 job 또는 외부 저장소 정책이 필요하다.
- 같은 원인의 검증 실패가 세 번 반복된다.
