# M33-02 Completion Evidence

## 상태

`DONE`

## 목표

선택 기준일이 속한 월요일부터 일요일까지의 실제 materialized TimeSlot을 root로 사용해, 예약이
없는 슬롯과 정원을 점유하거나 완료된 예약의 회원·RidingClass·원래 상태를 관리자 주간 운영
캘린더 read model로 제공한다.

## 구현 계약

- `GET /api/admin/reservations/weekly-operations-calendar`는 선택 `referenceDate`가 속한 월요일부터
  일요일까지의 7일 범위를 조회한다.
- `referenceDate`를 생략하면 공용 `Clock`의 `Asia/Seoul` 현재 날짜를 사용한다.
- 응답은 기준일, 주 시작·종료일과 실제 `TimeSlotCapacity` 목록을 날짜·시각·ID 순으로 반환한다.
- 각 TimeSlot은 식별자, 수업일·시작·종료 시각, 전체·원형마장·클래스별 정원, 마감 상태와
  캘린더 표시 대상 Reservation 목록을 제공한다. TimeSlot에 단일 RidingClass를 만들지 않는다.
- 표시 대상은 `ReservationStatus.occupyingStatuses()`에서 파생한
  `PENDING_ADMIN_APPROVAL`, `PENDING_PAYMENT`, `CONFIRMED`와 `COMPLETED`의 합이다.
- Reservation에는 예약·회원 식별자, 현재 회원 표시 이름, RidingClass와 기존 API 형식의 원래
  ReservationStatus를 제공한다. 제외 상태를 다른 상태로 변환하지 않는다.
- `PAYMENT_EXPIRED`, `APPROVAL_EXPIRED`, `REJECTED`, `CANCELLED`, `NO_SHOW`만 존재하는 슬롯은
  빈 Reservation 목록으로 유지한다. 실제 TimeSlot이 없는 Reservation으로 가짜 슬롯을 만들지 않는다.
- 관리자 bearer 권한은 기존 `/api/admin/**` 보안 경계를 그대로 사용한다.

## Query와 DB

- `time_slot_capacities`를 주간 날짜 범위로 한 번 조회하고, 표시 대상 Reservation과 Member를
  projection join으로 한 번 조회한 뒤 `(lessonDate, startTime)`으로 조립한다.
- 슬롯별·날짜별·회원별 추가 조회가 없으며 단일 슬롯·예약 1건과 21개 슬롯·회원·예약 fixture가
  모두 prepared statement 2회를 사용했다.
- TimeSlot의 `(lesson_date, start_time)` 유일 인덱스와 `lesson_date` 선두 인덱스, Reservation의
  기존 `idx_reservations_occupancy`, `idx_reservations_lesson_status`,
  `idx_reservations_status_lesson_start`를 재사용한다.
- bounded 2-query 조회와 기존 범위·상태 인덱스로 완료 조건을 충족하므로 새 index나 migration을
  추가할 객관적 근거가 없었다.
