# M34-01 Completion Evidence

## 상태

`DONE`

## 목표

회원 예약 가능 TimeSlot 조회도 일정 설정 동기화 중 기존 503 계약으로 차단한다.

## 구현 계약

- `MemberAvailableTimeSlotsService`는 조회 작업 전에 기존
  `ScheduleConfigGuardRepository.findSingletonForShare()`로 설정 guard를 공유 잠금한다.
- 기존 `ScheduleConfigGuard.ensureActive()`를 재사용하므로 `SYNCING`이면
  `503/SCHEDULE_CONFIG_SYNC_IN_PROGRESS`를 반환한다.
- `ACTIVE`에서는 날짜·회원·정원 조회와 기존 응답 의미를 변경하지 않는다.
- Reservation Command의 기존 guard와 오류 계약은 변경하지 않는다.

## 검증 증거

| 명령 | 종료 코드 | 핵심 결과 |
|---|---:|---|
| `./gradlew test --tests '*MemberAvailableTimeSlotsApiTest'` | 0 | 7건 성공, ACTIVE 조회와 SYNCING 503 검증 |
| `mise run verify:m34-01` | 0 | 19건 성공, 회원 조회 7건과 Reservation Command 회귀 12건 |
| `mise run backend:convention` | 0 | Checkstyle 및 컨벤션 테스트 성공 |

## 독립 검토

- 기존 guard Repository와 Domain 예외를 직접 재사용하며 조회의 read-only 트랜잭션 안에서
  `FOR SHARE` 잠금이 유지됨을 확인했다.
- 새 API 테스트는 SYNCING fixture에서 503 코드까지 검증하고 기존 ACTIVE 시나리오를 함께 실행한다.
- 최종 read-only 리뷰에서 CRITICAL/HIGH/MEDIUM finding은 없었다. active 문서 경로와 완료 문서
  허용 범위가 어긋난다는 LOW 1건은 이 Completion Evidence 이동으로 해소했다.

## 제외 범위

- Template lifecycle, 관리자 Web과 M34-02 이후 구현
- 새 guard, 새 오류 코드 또는 API 계약 추가
- Reservation 상태·정원·동기화 정책 변경
