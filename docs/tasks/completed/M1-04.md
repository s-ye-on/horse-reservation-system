## 중단 조건

- `DELETE`를 물리 삭제, 마감 처리, 이력 보존 중 무엇으로 해석할지 기존 코드나 입력 문서가 서로 다르다.
- 정원 축소 시 이미 점유된 예약을 어떻게 처리할지 결정해야 하지만 점유 데이터가 존재한다.
- API 구현에 예약·쿠폰 모듈 또는 전역 보안 설정 변경이 필요하다.
- OpenAPI 또는 오류 응답 convention을 따르려면 기존 convention 자체를 바꿔야 한다.
- 관리자 권한과 비인증 응답을 자동 검증할 수 없다.

## Blocked Evidence

- `docs/architecture/api.md`는 `DELETE /api/admin/timeslots/{timeslotId}`를 정의하지만 삭제 의미를 규정하지 않는다.
- `TMP.md`는 같은 API를 "타임 삭제 또는 비활성화"로 설명하고, `TimeSlotCapacity.is_closed`는 별도 마감 상태를 제공한다.
- 위 삭제 정책 충돌은 사용자가 운영 마감 PATCH와 이력 없는 TimeSlot 물리 DELETE로 분리해 해결했다.
- 현재 `ExceptionCodeTest`는 `TIMESLOT_*` 접두사를 허용하지 않는다. M1-04 오류를 도메인 소유권에 맞게 추가하려면 exception convention과 해당 하네스의 허용 접두사 확장이 필요하다.
- `COMMON_*` 오류로 우회하지 않고 컨벤션 변경 승인 전까지 구현과 커밋을 중단했다.

## Blocked Resolution

- 사용자가 TimeSlot을 독립 도메인으로 확정하고 `TIMESLOT_*` 접두사의 컨벤션·하네스 확장을 승인했다.
- 기존 접두사·중복 검증은 유지하고 TimeSlot 도메인만 동일 규칙에 추가한다.

## Completion Evidence

- 관리자 TimeSlot 조회·생성·정원 변경·마감/재개·물리 삭제 API와 OpenAPI client를 동기화했다.
- PATCH는 `is_closed`만 변경하고 DELETE는 예약 이력 조회 port가 이력을 발견하면 `409 Conflict`로 거부한다.
- `TIMESLOT_*`를 단일 `ExceptionCode`와 접두사 하네스에 추가하고 수명주기 결정을 ADR 004로 기록했다.
- 최초 예약 생성 Task M1-11이 날짜·시각 기반 예약 이력 adapter를 연결하도록 후속 계약을 추가했다.
