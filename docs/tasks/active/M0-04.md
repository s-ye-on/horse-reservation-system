# M0-04: Spring Security 역할 골격

## 상태

`READY`

## 목표

회원용 API와 관리자용 API의 접근 경계를 Spring Security 설정과 자동 테스트로 고정한다.

## 담당

`backend`

## 선행 작업

- M0-01 완료

## 입력 문서

- [MVP 0 Backlog](../mvp-0.md)의 `M0-04`
- [시스템 개요](../../architecture/system-overview.md)의 백엔드 모듈과 책임
- [제품 요구사항](../../product/requirements.md)의 사용자 역할

## 허용 범위

- `backend/src/main/java/com/horse/auth/**`
- `backend/src/test/java/com/horse/auth/**`

## 제외 범위

- 회원 가입, 로그인, 로그아웃, 비밀번호 저장
- JWT, 세션, OAuth 등 인증 방식 결정과 구현
- 회원 또는 관리자 UI와 실제 도메인 API
- DB 스키마와 기존 Flyway migration
- 관련 없는 리팩터링, 라이브러리 교체, 포맷 전체 변경

## 완료 조건

- [ ] `MEMBER`, `ADMIN` 역할이 코드에 명시적으로 정의된다.
- [ ] `/actuator/health`는 공개하고 `/api/admin/**`는 `ADMIN`, 그 외 `/api/**`는 인증 사용자에게만 허용한다.
- [ ] 인증되지 않은 사용자와 역할이 부족한 사용자의 접근 거부를 자동 테스트로 검증한다.
- [ ] 검증 명령이 모두 종료 코드 0으로 성공한다.

## 검증 명령

명령은 위에서 아래 순서로 실행한다.

```bash
mise tasks --all
mise run verify:m0-04
mise run verify:changed
```

## 검증 증거

구현 완료 후 실행한 명령, 종료 코드, 테스트 결과를 기록한다.

## 중단 조건

다음 중 하나라도 해당하면 구현을 멈추고 상태를 `BLOCKED`로 변경한다.

- 입력 문서끼리 회원과 관리자 권한 정책이 충돌한다.
- 인증 방식까지 결정하지 않으면 역할 접근 경계를 구현할 수 없다.
- 허용 범위 밖의 운영 코드 또는 설정을 수정해야 한다.
- 테스트용 endpoint가 운영 코드에 노출되어야만 검증할 수 있다.
- 필수 검증 명령이 없거나 반복 실행 결과가 불안정하다.
- 완료 조건을 자동 검증할 방법을 정의할 수 없다.

## 중단 보고 형식

```text
BLOCKED
충돌/문제:
근거 문서 또는 실패 명령:
현재까지 변경한 파일:
필요한 결정:
안전하게 재개할 조건:
```
