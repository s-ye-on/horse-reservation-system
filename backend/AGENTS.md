# Backend Instructions

이 디렉터리는 Java 21 + Spring Boot 기반 마장 예약 시스템의 백엔드이다.  
기존 코드 구조와 문서에 확정된 제품 정책을 우선하며, 현재 task의 허용 범위 안에서만 작업한다.

## 작업 전 확인

1. 현재 `docs/tasks/`의 task 문서를 확인한다.
2. task가 지정한 제품 정책과 아키텍처 문서만 추가로 읽는다.
3. task 상태가 `READY` 또는 `IN_PROGRESS`가 아니면 구현하지 않는다.

## Required Rules

- Controller는 요청 검증, 변환, 응답 반환과 Application Service 호출만 담당한다.
- 트랜잭션 경계와 여러 객체 간 유스케이스 조정은 Application Service에 둔다.
- Entity의 상태는 외부 setter가 아니라 의미 있는 상태 전이 메서드로 변경한다.
- Repository는 Application Service 또는 명시된 도메인 서비스에서만 접근한다.
- Entity를 API 요청·응답 DTO로 직접 사용하지 않는다.
- `@ManyToOne` 연관관계는 특별한 이유가 없으면 `FetchType.LAZY`를 사용한다.
- 도메인 규칙 위반은 프로젝트의 공통 예외 및 오류 코드 체계로 표현한다.
- 관련 없는 리팩터링, 패키지 이동, 의존성 교체를 하지 않는다.

## Domain Rules

- 예약 상태 전이, 정원 점유 변경, 쿠폰 점유·해제는 문서에 정의된 정책을 따른다.
- 하나의 유스케이스에서 함께 성공하거나 실패해야 하는 변경은 같은 트랜잭션에서 처리한다.
- 중복 요청으로 예약, 정원, 쿠폰 사용 이력이 두 번 반영되지 않게 한다.
- 동시 요청에서도 정원과 쿠폰 잔여량이 음수이거나 한도를 초과하지 않게 한다.
- 테스트를 통과시키기 위해 상태 전이 조건이나 제품 정책을 임의로 완화하지 않는다.

## Implementation

- 한 메서드는 하나의 명확한 책임에 집중한다.
- 축약어보다 도메인 의도가 드러나는 이름을 사용한다.
- 생성 규칙이 있는 객체는 생성자 또는 정적 팩토리 메서드로 유효한 상태를 보장한다.
- 긴 `if-else`나 `switch`를 피하되, 불필요한 추상화보다 명확한 코드를 우선한다.
- 새 동작이나 수정된 동작에는 관련 테스트를 추가한다.

## Verification

task 문서의 검증 명령을 먼저 실행한다. 별도 명령이 없다면 다음을 실행한다.

```bash
./gradlew test
./gradlew check
```

검증을 통과시키기 위해 테스트를 삭제하거나 assertion을 약화하지 않는다.

## Stop Conditions

다음 상황에서는 임의로 결정하지 말고 작업을 중단하여 보고한다.

- 제품 정책과 아키텍처 문서가 충돌한다.
- task의 허용 범위를 벗어난 수정이 필요하다.
- 인증, 운영 설정 또는 기존 DB migration 변경이 필요하다.
- 확정되지 않은 정책이 구현 결과에 영향을 준다.
- 같은 원인의 검증 실패가 반복되어 문서나 설계 변경이 필요하다.

## Completion Report

완료 후 다음을 보고한다.

- 변경한 파일
- 충족한 Acceptance Criteria
- 실행한 검증 명령과 결과
- 직접 검증하지 못한 부분
- 남아 있는 위험 또는 필요한 후속 결정
